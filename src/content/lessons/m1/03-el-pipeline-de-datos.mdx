## Qué vas a construir

Nueve pasos de datos, cada uno con su configuración, sus rutas y su manifiesto. Con un YAML por
paso tendrías nueve ficheros que repiten `data/uci` y nueve sitios donde cambiar el límite de memoria
de <Term id="duckdb">DuckDB</Term>. Esta lección es el pegamento: **un solo `pipeline.yaml`**, un
modelo pydantic que lo valida entero y ocho subcomandos de la CLI con la misma forma. Cualquier sistema
con muchas piezas configurables, de un ETL a un agente con diez herramientas, gana lo mismo con una
sola fuente de configuración validada al cargar.

Con el pegamento vienen dos pasos completos: `elite`, que descarga la base Elite de Lichess y la
convierte con el código de la lección anterior, y `elo-bins`, que muestrea hasta 50 000 partidas por
tramo de 100 puntos de <Term id="elo">Elo</Term> para que M4 pueda entrenar los tokens de cabecera.

```python title="src/rukh/data/pipeline.py"
DUCKDB_STEPS = ("positions", "evals", "puzzles", "elo_bins")


class PipelineConfig(BaseConfig):
    """All step configs; each step reads only its own section.

    ``duckdb:`` is shared: the top-level settings are copied into every step that opens a
    DuckDB connection unless that step declares its own.
    """

    duckdb: DuckDbConfig = Field(default_factory=DuckDbConfig)
    uci: UciConfig = Field(default_factory=UciConfig)
    tokenize: TokenizeConfig = Field(default_factory=TokenizeConfig)
    positions: PositionsConfig = Field(default_factory=PositionsConfig)
    evals: EvalsConfig = Field(default_factory=EvalsConfig)
    puzzles: PuzzlesConfig = Field(default_factory=PuzzlesConfig)
    pairs: PairsConfig = Field(default_factory=PairsConfig)
    elite: EliteConfig = Field(default_factory=EliteConfig)
    elo_bins: EloBinsConfig = Field(default_factory=EloBinsConfig)
    publish: PublishConfig = Field(default_factory=PublishConfig)

    @model_validator(mode="after")
    def _share_duckdb(self) -> PipelineConfig:
        default = DuckDbConfig()
        for name in DUCKDB_STEPS:
            step = getattr(self, name)
            if step.duckdb == default:
                setattr(self, name, step.model_copy(update={"duckdb": self.duckdb}))
        return self
```

<Src file="src/rukh/data/pipeline.py" tag="p1" lines="39-67" />

Esta es la única pieza con lógica del fichero. Cuatro pasos abren una conexión de DuckDB y cada uno
tiene su campo `duckdb`. Sin el validador, subir el límite de memoria obligaría a escribirlo cuatro
veces, y olvidar una dejaría un paso con el valor viejo sin que nada lo dijera.

El `model_validator(mode="after")` corre cuando pydantic ya validó todos los campos. Si el `duckdb`
de un paso es igual al valor por defecto, ese paso no lo declaró y hereda el global; si difiere, se
respeta. El límite (escribir a mano el valor por defecto en un paso cuenta como no escribirlo) no
importa en la práctica, y `model_fields_set` lo resolvería a cambio de más código. El `model_copy`
devuelve un modelo nuevo en vez de mutar el que hay, para que dos pasos no compartan por accidente el
mismo objeto.

```python title="src/rukh/cli.py"
@data_app.command("uci")
def data_uci(
    config: PipelineOption = None,
    workers: Annotated[
        int | None, typer.Option("--workers", help="Override the pool size from the config.")
    ] = None,
    as_json: Annotated[
        bool, typer.Option("--json", help="Print the manifest as JSON only.")
    ] = False,
) -> None:
    """Convert fetched SAN movetext to legal UCI games, one parquet per month."""
    from rukh.data.pipeline import load_pipeline
    from rukh.data.uci import run

    cfg = load_pipeline(config).uci
    if workers is not None:
        cfg = cfg.model_copy(update={"workers": workers})
    manifest = run(cfg)
    if as_json:
        typer.echo(manifest.model_dump_json(indent=2))
        return
    typer.echo(f"months:   {', '.join(manifest.months)}")
    for month, count in manifest.counts.items():
        typer.echo(f"  {month}: {count} games kept")
    typer.echo(f"manifest: {cfg.out_dir}/manifest.json")
```

La base Elite de Lichess reúne partidas de jugadores de 2500+ contra 2300+, sin bullet, en un zip
por mes. M4 la usa para el afinado "como los maestros". Lo interesante de este fichero es lo poco que

```python title="src/rukh/data/elite.py"
def zip_name(month: str) -> str:
    return f"lichess_elite_{month}.zip"


def zip_url(cfg: EliteConfig, month: str) -> str:
    return f"{cfg.base_url.rstrip('/')}/{zip_name(month)}"


def _download(url: str, dest: Path) -> None:
    """Stream ``url`` to ``dest`` (tests monkeypatch this)."""
    import requests

    dest.parent.mkdir(parents=True, exist_ok=True)
    tmp = dest.with_suffix(dest.suffix + ".part")
    with requests.get(url, stream=True, timeout=120) as response:
        response.raise_for_status()
        with tmp.open("wb") as fh:
            for chunk in response.iter_content(chunk_size=1 << 20):
                fh.write(chunk)
    tmp.replace(dest)


def extract_pgn(zip_path: Path, dest_dir: Path) -> Path:
    """Extract the (single) ``.pgn`` member of the zip; returns its path."""
    with zipfile.ZipFile(zip_path) as archive:
        members = [m for m in archive.namelist() if m.lower().endswith(".pgn")]
        if len(members) != 1:
            raise ValueError(f"{zip_path.name}: expected one .pgn member, found {members}")
        archive.extract(members[0], dest_dir)
    return dest_dir / members[0]
```

`_download` escribe a un `.part` y lo renombra al final, para que un zip interrumpido no pase por
completo: el nombre definitivo solo existe cuando la descarga terminó. Es la única función que toca
la red, y el test la sustituye por una que copia un zip de mentira.

`extract_pgn` falla si el zip no tiene exactamente un `.pgn`. Coger el primero daría, el día que la
recopilación cambie de formato, un dataset a medias en vez de un error que se lee.

```python title="src/rukh/data/elite.py"
def iter_pgn_rows(pgn_path: Path, month: str) -> Iterator[dict[str, object]]:
    """Yield raw rows (``RAW_COLUMNS``) from a PGN file with a light line parser.

    A new game starts when a header follows movetext or repeats a tag of the current block, so
    a game with headers but no moves is dropped instead of polluting the next one. Without a
    ``Site`` tag the game id falls back to ``month:index`` (every game still gets its own id);
    a missing or unparsable Elo is recorded as ``None``, never as 0.
    """
    headers: dict[str, str] = {}
    movetext: list[str] = []
    in_moves = False
    index = 0

    def flush(index: int) -> dict[str, object] | None:
        if not headers or not movetext:
            return None
        return {
            "Site": headers.get("Site") or f"{month}:{index}",
            "movetext": " ".join(movetext),
            "WhiteElo": _int(headers.get("WhiteElo")),
            "BlackElo": _int(headers.get("BlackElo")),
            "Result": headers.get("Result", "*"),
            "TimeControl": headers.get("TimeControl"),
            "UTCDate": headers.get("UTCDate", headers.get("Date")),
            "ECO": headers.get("ECO"),
            "month": month,
        }

    with pgn_path.open(encoding="utf-8", errors="replace") as fh:
        for line in fh:
            line = line.strip()
            if line.startswith("["):
                match = _HEADER_RE.match(line)
                if match is None:
                    continue
                if in_moves or match.group(1) in headers:
                    row = flush(index)
                    if row is not None:
                        yield row
                    index += 1
                    headers, movetext, in_moves = {}, [], False
                headers[match.group(1)] = match.group(2)
            elif line:
                in_moves = True
                movetext.append(line)
    row = flush(index)
    if row is not None:
        yield row
```

Este es el trozo con miga. Un PGN es una sucesión de bloques de cabeceras entre corchetes seguidos
de líneas de jugadas. Partir por líneas en blanco es un error, porque algunos programas meten líneas
en blanco dentro del movetext.

El parser usa otra regla: **una partida nueva empieza cuando una cabecera aparece después de
jugadas, o cuando repite un tag del bloque actual**. La segunda condición cubre las partidas con
cabeceras y sin jugadas (abandonadas antes de empezar), que si no se fusionarían con la siguiente y
le robarían su `Result` y su Elo. El `index` avanza aunque `flush` descarte el bloque, así que el id
de respaldo (`month:index`) sigue siendo único.

```python title="src/rukh/data/elite.py"
def _int(value: str | None) -> int | None:
    """``None`` when the header is missing or not a number (never a fabricated 0)."""
    try:
        return int(value) if value is not None else None
    except ValueError:
        return None


def _batches(rows: Iterator[dict[str, object]]) -> Iterator[list[dict[str, object]]]:
    batch: list[dict[str, object]] = []
    for row in rows:
        for name in RAW_COLUMNS:
            row.setdefault(name, None)
        batch.append(row)
        if len(batch) >= BATCH_GAMES:
            yield batch
            batch = []
    if batch:
        yield batch
```

```python title="src/rukh/data/elo_bins.py"
def sample_bins(
    sources: list[Path],
    target: Path,
    n_per_bin: int,
    seed: int,
    duckdb_cfg: DuckDbConfig | None = None,
) -> dict[str, int]:
    """DuckDB: ``bin = avg(white_elo, black_elo) // 100 * 100``; keep ``n_per_bin`` by hash.

    The seed shifts the hash, not the id: ``hash(game_id + seed)`` overflowed BIGINT for ids
    near the top of the range.
    """
    files = ", ".join(f"'{p.as_posix()}'" for p in sources)
    con = connect(duckdb_cfg)
    try:
        con.execute(
            f"""
            COPY (
              SELECT * EXCLUDE (rk)
              FROM (
                SELECT *,
                       row_number() OVER (PARTITION BY bin ORDER BY hash(game_id) + {seed}) AS rk
                FROM (
                  SELECT *, ((white_elo + black_elo) // 2) // 100 * 100 AS bin
                  FROM read_parquet([{files}], hive_partitioning = false)
                )
              )
              WHERE rk <= {int(n_per_bin)}
              ORDER BY bin, rk
            ) TO '{target.as_posix()}' (FORMAT PARQUET, COMPRESSION ZSTD)
            """
        )
        rows = con.execute(
            f"SELECT bin, count(*) FROM read_parquet('{target.as_posix()}') "
            "GROUP BY bin ORDER BY bin"
        ).fetchall()
    finally:
        con.close()
    return {str(int(b)): int(n) for b, n in rows}
```

<Src file="src/rukh/data/elo_bins.py" tag="p1" lines="28-66" />

La consulta se lee de dentro afuera. El nivel interno calcula el tramo: la media de los dos Elo,
truncada a la centena. Es la media y no el Elo de un bando porque lo que determina cómo se juega es
el nivel de la mesa.

El de en medio numera las filas de cada tramo ordenando por un hash del id. Es un muestreo
determinista: impredecible respecto a cualquier propiedad de la partida, y **igual en cada
ejecución**. El de fuera se queda con las primeras `n_per_bin` de cada tramo.

<Callout kind="roto" title="Un id que ocupa todo su rango no admite aritmética">
  `game_id` sale de un hash, así que ocupa todo el rango de un entero de 64 bits. Sumarle 42 a un id
  cercano a 2⁶³−1 desborda, y la consulta entera muere con `Overflow in addition of INT64`. Con ids
  al azar pasa rarísima vez, y eso lo hace peligroso: nadie lo ve hasta que pasa. El test de abajo,
  con ids en los extremos del `int64`, falla siempre con `hash(game_id + seed)`.

Sumar la semilla después del hash, como hace el código, deja el riesgo en 42 entre 2⁶⁴ por fila,
porque `hash()` devuelve un `UBIGINT` que también ocupa todo su rango. La forma que no desborda nunca
es no sumar: `hash(game_id, 42)`, o la semilla dentro del hash como hace `puzzles.py` con
`blake2b(seed:id)`. Vale fuera de DuckDB: **un identificador que usa todo el rango de su tipo no
admite aritmética**. Si tienes que combinarlo con algo, hazlo dentro del hash o concatenando texto.

</Callout>

## Qué has aprendido

Tienes el esqueleto del pipeline: una configuración única, validada entera, que reparte su sección

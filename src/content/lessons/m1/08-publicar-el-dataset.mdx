## Qué vas a construir

El último paso del pipeline y el único que sale del disco duro. `rukh data publish` coge uno de los
siete artefactos que este módulo produce, **genera su card a partir del manifiesto** y lo sube a
Hugging Face bajo `chorcat`.

La subida son tres llamadas a una librería; lo interesante es la card. Todo lo que este módulo ha
ido registrando (filtros, conteos, hashes de fichero, la versión de `rukh` que lo generó) se vuelca
tal cual en el README del dataset, así que la página que alguien encuentra en el Hub dice con qué
filtros se construyó lo que se está descargando. Es la <Term id="manifiesto">procedencia</Term> de
las siete lecciones anteriores, convertida en documentación que no se escribe a mano y por tanto no
se queda vieja. Lo mismo vale para la ficha de un modelo en un registro interno o para el informe de
una evaluación.

Un fichero de Python, `publish.py`, una plantilla y la orden que los junta.

El docstring describe la orden entera, y hay dos cosas que conviene fijar antes de seguir.

La primera son **las dos licencias**, escritas como constantes de texto. `LICHESS_CC0` para todo lo
que deriva del volcado público de Lichess, y `ELITE_LICENSE` para la base Elite, que es distinta: la
recopilación de `database.nikonoel.fr` **no publica una licencia explícita**, aunque su contenido
venga de Lichess y sea CC0. Decir "CC0 de facto" y pedir que se cite a los dos es lo honesto; poner
"CC0" a secas sería afirmar algo que el tercero no ha dicho.

La segunda es `UCI_COLUMNS`: la documentación de las diez columnas del parquet de partidas, escrita
una vez y reutilizada por los tres datasets que comparten ese esquema. Es la misma idea que
`OUT_SCHEMA` en `uci.py`, un nivel más arriba.

`DatasetSpec` es la ficha de un artefacto publicable, y el campo que más se nota es `command`: la
orden con la que se regenera. Aparece en la card, así que cualquiera que descargue el dataset tiene
delante la línea que lo reproduce.

`exclude_counts` existe porque los manifiestos de dos pasos tienen contadores que **no son filas**.
El de las evaluaciones lleva `lines` (las líneas analizadas) y `positions` (las de entrada); el de
los pares lleva `candidates` (antes de equilibrar). Sumarlos todos para declarar el tamaño del
dataset daría una cifra inflada, y la categoría de tamaño del Hub saldría mal.

`large` marca los dos datasets de varios gigabytes, y su docstring dice para qué: elegir el método de
subida.

Las descripciones de columnas de estos dos son la única documentación que existe de esos ficheros, y
por eso están escritas con cuidado. Dos merecen leerse:

`("fen", "position before the opponent's last move (Lichess convention)")` en los puzles. Un puzle de

línea de documentación vale por media hora de depuración en M2.

    publish_dir: str = "data/publish"


class PublishResult(BaseModel):
    """What was (or would be) uploaded."""

    model_config = ConfigDict(extra="forbid")

    name: str
    repo_id: str
    repo_type: str
    dry_run: bool
    card_path: str
    files: list[str]

def size_category(rows: int) -> str:
    for limit, label in (
        (1_000, "n<1K"),
        (10_000, "1K<n<10K"),
        (100_000, "10K<n<100K"),
        (1_000_000, "100K<n<1M"),
        (10_000_000, "1M<n<10M"),
    ):
        if rows < limit:
            return label
    return "10M<n<100M"

```python title="src/rukh/data/publish.py"
def local_files(spec: DatasetSpec) -> list[Path]:
    root = resolve(spec.local_dir)
    found: list[Path] = []
    for pattern in spec.patterns:
        found.extend(sorted(root.glob(pattern)))
    return found


def read_manifest(spec: DatasetSpec) -> Manifest | None:
    path = resolve(spec.local_dir) / "manifest.json"
    if not path.is_file():
        return None
    return Manifest.model_validate_json(path.read_text("utf-8"))


def count_rows(spec: DatasetSpec, manifest: Manifest | None) -> int:
    if manifest is None:
        return 0
    return sum(v for k, v in manifest.counts.items() if k not in spec.exclude_counts)
```

`local_files` expande los patrones del spec contra el directorio local. El `sorted` de cada patrón es
lo que hace que la lista de ficheros de la card salga en el mismo orden en cualquier máquina: el
orden de `glob` depende del sistema de ficheros.

`count_rows` suma los conteos del manifiesto **saltándose** los de `exclude_counts`, que es donde ese
campo cobra sentido. Y devuelve 0 cuando no hay manifiesto, en vez de fallar: un artefacto sin
manifiesto se puede publicar, solo que su card dirá menos.

```python title="src/rukh/data/publish.py"
def render_card(spec: DatasetSpec, manifest: Manifest | None, owner: str) -> str:
    """Render the dataset card; the tokenizer uses its own README as the card."""
    if spec.repo_type == "model":
        return (resolve(spec.local_dir) / "README.md").read_text("utf-8")
    env = Environment(
        loader=FileSystemLoader(str(CARDS_DIR)),
        undefined=StrictUndefined,
        autoescape=False,
        keep_trailing_newline=True,
    )
    rows = count_rows(spec, manifest)
    context = {
        "repo_id": f"{owner}/{spec.name}",
        "license": spec.license,
        "license_text": spec.license_text,
        "pretty_name": spec.pretty_name,
        "task_categories": spec.task_categories,
        "size_category": size_category(rows),
        "source_datasets": spec.source_datasets,
        "tags": spec.tags,
        "description": spec.description,
        "command": spec.command,
        "columns": spec.columns,
        "source": spec.source,
        "rows": rows,
        "files": manifest.files if manifest else [],
        "months": manifest.months if manifest else [],
        "filters_json": json.dumps(manifest.filters if manifest else {}, indent=2, default=str),
        "counts_json": json.dumps(manifest.counts if manifest else {}, indent=2),
        "created_at": manifest.created_at.date().isoformat() if manifest else "unknown",
        "rukh_version": manifest.rukh_version if manifest else "unknown",
    }
    return env.get_template("dataset.md.jinja").render(**context)
```

Aquí está la pieza central, y la primera línea es una bifurcación importante: **el tokenizador usa su
propio README como card**. No se genera nada; se lee `artifacts/tokenizer/README.md` y se sube tal
cual. Es lo correcto porque lo que hay que contar de un tokenizador no cabe en la plantilla de un
dataset —no tiene filas, ni columnas, ni filtros— y escribirlo a mano una vez es más honesto que
inventar una plantilla para un solo caso.

`StrictUndefined` es la decisión del fichero. Por defecto, Jinja **renderiza una variable inexistente
como cadena vacía**: un `{{ licence }}` con la errata produciría una card con la línea `license:`
vacía, que el Hub rechazaría o, peor, aceptaría. Con `StrictUndefined` la plantilla lanza al
renderizar, antes de tocar la red. Es la misma decisión que `extra="forbid"` en las
configuraciones de M0, aplicada a las plantillas: fallar al construir, no al usar.

`autoescape=False` porque la salida es Markdown y no HTML; escapar convertiría cada `&` de una URL en
`&amp;`. Y `keep_trailing_newline=True` porque un fichero de texto acaba en salto de línea.

El `default=str` del `json.dumps` de los filtros es una red: los filtros de un manifiesto son un
diccionario libre y alguno puede llevar un tipo que JSON no conoce. Mejor una representación fea que
una excepción al publicar.

```python title="src/rukh/data/publish.py"
def _api():  # type: ignore[no-untyped-def]
    """The ``HfApi`` client (tests monkeypatch this)."""
    from huggingface_hub import HfApi

    return HfApi()


def upload_folder(api: object, spec: DatasetSpec, repo_id: str) -> str:
    """Upload the whole local directory in one go; returns the method that was used.

    The card is always uploaded separately from the staged copy, so ``README.md`` is excluded
    here. A ``large`` dataset uses ``upload_large_folder`` (resumable, multi-threaded) when the
    installed ``huggingface_hub`` provides it.
    """
    large = callable(getattr(api, "upload_large_folder", None))
    if spec.large and large:
        api.upload_large_folder(  # type: ignore[attr-defined]
            repo_id=repo_id,
            folder_path=str(resolve(spec.local_dir)),
            repo_type=spec.repo_type,
            allow_patterns=spec.patterns,
            ignore_patterns=["README.md"],
        )
        return "upload_large_folder"
    api.upload_folder(  # type: ignore[attr-defined]
        repo_id=repo_id,
        folder_path=str(resolve(spec.local_dir)),
        repo_type=spec.repo_type,
        allow_patterns=spec.patterns,
        ignore_patterns=["README.md"],
        commit_message="Upload data",
    )
    return "upload_folder"
```

`_api()` es la única función que crea el cliente del Hub, y su docstring dice por qué: los tests la
sustituyen. Todo el fichero se puede probar sin red porque las tres llamadas de red salen de aquí.

`upload_folder` tiene la decisión operativa del módulo. `rukh-games-1800` son casi 1 GB y
`rukh-elo-bins` otro tanto; subirlos con `upload_folder` es una sola petición larga que, si se corta a
los cuarenta minutos, se ha perdido entera. `upload_large_folder` trocea, sube en paralelo y
**reanuda**: volver a lanzarlo continúa donde se quedó.

El `callable(getattr(api, "upload_large_folder", None))` es una comprobación de capacidad y no de
versión. Pedir la versión de `huggingface_hub` y compararla obligaría a mantener un número; preguntar
si el método existe funciona con cualquier versión, y también con el doble que usan los tests.

`ignore_patterns=["README.md"]` en las dos ramas: la card se sube aparte, desde la copia preparada, y
sin esa exclusión se subiría dos veces —una desde el directorio local, si lo hubiera, y otra desde la
copia— con la del directorio local ganando.

```python title="src/rukh/data/publish.py"
def publish(name: str, cfg: PublishConfig, dry_run: bool = False) -> PublishResult:
    """Render the card and upload (or, with ``dry_run``, stage) one registry entry."""
    if name not in DATASETS:
        raise KeyError(f"unknown dataset {name!r}; known: {', '.join(DATASETS)}")
    spec = DATASETS[name]
    manifest = read_manifest(spec)
    files = local_files(spec)
    if not files:
        raise FileNotFoundError(f"nothing to publish under {resolve(spec.local_dir)}")
    repo_id = f"{cfg.owner}/{spec.name}"
    card = render_card(spec, manifest, cfg.owner)
    stage = resolve(cfg.publish_dir) / spec.name
    stage.mkdir(parents=True, exist_ok=True)
    card_path = stage / "README.md"
    card_path.write_text(card, encoding="utf-8", newline="\n")
    rel_files = [p.relative_to(resolve(spec.local_dir)).as_posix() for p in files]
    if not dry_run:
        api = _api()
        api.create_repo(repo_id, repo_type=spec.repo_type, exist_ok=True)
        upload_folder(api, spec, repo_id)
        api.upload_file(
            path_or_fileobj=str(card_path),
            path_in_repo="README.md",
            repo_id=repo_id,
            repo_type=spec.repo_type,
            commit_message="Update card",
        )
    return PublishResult(
        name=spec.name,
        repo_id=repo_id,
        repo_type=spec.repo_type,
        dry_run=dry_run,
        card_path=card_path.as_posix(),
        files=rel_files,
        rows=count_rows(spec, manifest),
    )
```

<Src file="src/rukh/data/publish.py" tag="p1" lines="368-403" />

El orden de `publish` es el que importa. Primero comprueba que el nombre existe y que **hay ficheros
que subir**, y las dos comprobaciones fallan con una excepción que la CLI convierte en un mensaje:
publicar un dataset que no se ha generado es el error más fácil de cometer y el más caro, porque la
alternativa es crear un repositorio vacío en el Hub.

Después renderiza la card y **la escribe en disco siempre**, se vaya a subir o no. Eso es lo que hace
que `--dry-run` sirva de algo: dejas la card en `data/publish/<nombre>/README.md`, la lees, y solo
entonces publicas.

Y las tres llamadas de red van en un orden concreto: crear el repositorio con `exist_ok=True` (así
publicar dos veces actualiza en vez de fallar), subir los datos, subir la card la última. Si algo se
corta, lo que queda a medias son los datos y no la documentación de unos datos que no están.

<Transfer concept="La documentación se genera del artefacto, no se escribe al lado" where="Un modelo en un registro, un esquema de API, un dataset interno, un informe de evaluación.">
  La regla que sigue esta lección es que **la card se rellena con el manifiesto**, y el manifiesto lo
  escribió el paso que produjo los datos. Nadie teclea los conteos, ni los hashes, ni los filtros. La
  consecuencia es que la documentación no puede quedarse vieja: si el dataset se regenera, la card
  cambia sola.

El modo de fallo que evita es el más común de todos: una card escrita a mano el día de la
publicación, que dice `min_elo: 2000` porque así estaba entonces, junto a un fichero que se regeneró
con 1800 tres meses después. Nadie miente; simplemente nadie vuelve a leer el README.

Y el corolario práctico: si la documentación de tu artefacto contiene un número, ese número tiene que
salir de un fichero que el proceso escribió, no de tu memoria.

</Transfer>

```python title="src/rukh/cli.py"
@data_app.command("publish")
def data_publish(
    name: Annotated[
        str | None, typer.Option("--name", help="Registry entry, e.g. rukh-games-1800.")
    ] = None,
    config: PipelineOption = None,
    dry_run: Annotated[
        bool, typer.Option("--dry-run", help="Render the card and list files; no network.")
    ] = False,
    list_names: Annotated[bool, typer.Option("--list", help="List the registry and exit.")] = False,
    as_json: Annotated[bool, typer.Option("--json", help="Print the result as JSON.")] = False,
) -> None:
    """Render the dataset card and upload one dataset (or the tokenizer) to the Hub."""
    from rukh.data.pipeline import load_pipeline
    from rukh.data.publish import DATASETS, publish

    if list_names:
        for spec in DATASETS.values():
            typer.echo(f"{spec.name:<22} {spec.repo_type:<8} {spec.local_dir}")
        return
    if name is None:
        typer.echo("error: --name is required (see --list)", err=True)
        raise typer.Exit(code=2)
    cfg = load_pipeline(config).publish
    try:
        result = publish(name, cfg, dry_run=dry_run)
    except (KeyError, FileNotFoundError) as exc:
        typer.echo(f"error: {exc}", err=True)
        raise typer.Exit(code=1) from exc
    if as_json:
        typer.echo(result.model_dump_json(indent=2))
        return
    typer.echo(f"repo:     {result.repo_id} ({result.repo_type})")
    typer.echo(f"mode:     {'dry-run (card staged, nothing uploaded)' if dry_run else 'uploaded'}")
    typer.echo(f"rows:     {result.rows}")
    typer.echo(f"card:     {result.card_path}")
    typer.echo("files:")
    for path in result.files:
        typer.echo(f"  {path}")
```

Tres modos en una orden. `--list` imprime el registro y sale, que es la forma de saber qué nombres
acepta sin leer el código. Sin `--name` sale con código 2 y un mensaje que remite a `--list`. Y con
nombre, publica o prepara.

Las dos excepciones que captura son las dos comprobaciones de `publish`: `KeyError` (nombre
desconocido) y `FileNotFoundError` (nada que subir). Las dos se convierten en un mensaje en `stderr`
y un código 1, en vez de una traza. Es el mismo patrón que `engine check` en M0.

La línea de `mode:` distingue `dry-run (card staged, nothing uploaded)` de `uploaded`, que es la
información que hay que ver cuando uno no se acuerda de si puso la bandera.

Este es el único paso en el que intervienes tú. Los anteriores se ejecutan solos; este necesita un
`HF_TOKEN` con permiso de escritura en tu cuenta, y por eso la orden viene con `--dry-run`: la card
se genera y se lee **antes** de crear nada. El flujo normal es `--dry-run`, abrir
`data/publish/<nombre>/README.md`, comprobar que los filtros y los conteos son los que esperabas, y
entonces repetir sin la bandera.

## Qué has aprendido

Cómo se convierte un pipeline de datos en algo que otra persona puede descargar y entender: un
registro de siete artefactos con sus licencias, una plantilla que se rellena con lo que los pasos ya
registraron, y una subida que se puede ensayar sin tocar la red y reanudar si se corta.

**Cómo se mide**: `uv run rukh data publish --list` imprime los siete, y
`uv run rukh data publish --name <nombre> --dry-run` deja en `data/publish/<nombre>/README.md` una
card cuya sección de filtros es el `manifest.json` del paso, tal cual. Con `HF_TOKEN`, la misma
orden sin `--dry-run` deja el repositorio en `huggingface.co/chorcat/<nombre>`.

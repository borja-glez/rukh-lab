## Qué vas a construir

El último paso del pipeline, y el único que sale del disco. `rukh data publish` coge uno de los
siete artefactos del módulo, **genera su card a partir del manifiesto** y lo sube a Hugging Face bajo
`chorcat`.

La subida son tres llamadas a una librería; lo interesante es la card. Los filtros, conteos, hashes y
la versión de `rukh` que registraron los pasos anteriores se vuelcan tal cual en el README del
dataset. Es la <Term id="manifiesto">procedencia</Term> convertida en documentación que nadie escribe
a mano y que por eso no se queda vieja, igual que valdría para la ficha de un modelo en un registro
interno. Son un fichero de Python, una plantilla y el comando que los junta.

<Callout kind="guia" title="Qué tecleas y qué traes">

- **Tecleas**: las tres dependencias nuevas de `pyproject.toml`, `src/rukh/data/publish.py`, la
  plantilla `src/rukh/data/cards/dataset.md.jinja`, el subcomando `publish` de `cli.py` y
  `test_publish.py` (plegado).
- **Traes del repo**: `artifacts/tokenizer/README.md`, la card del tokenizador, que es texto escrito
  a mano: `git checkout p1 -- artifacts/tokenizer/README.md`.
- **Para publicar de verdad**: una cuenta de Hugging Face y tu usuario en `publish.owner` (al final
  de la lección). Sin ellas, todo funciona con `--dry-run`.
- **Referencia**: `p1`.

</Callout>

```python title="src/rukh/data/publish.py"
class PublishConfig(BaseConfig):
    """Hub owner and where dry runs stage their output."""

    owner: str = "chorcat"
    publish_dir: str = "data/publish"


class PublishResult(BaseModel):
    """What was (or would be) uploaded."""

    model_config = ConfigDict(extra="forbid")

    name: str
    repo_id: str
    repo_type: str
    dry_run: bool
    card_path: str
    files: list[str]
    rows: int


def size_category(rows: int) -> str:
    for limit, label in (
        (1_000, "n<1K"),
        (10_000, "1K<n<10K"),
        (100_000, "10K<n<100K"),
        (1_000_000, "100K<n<1M"),
        (10_000_000, "1M<n<10M"),
    ):
        if rows < limit:
            return label
    return "10M<n<100M"
```

```python title="src/rukh/data/publish.py"
def local_files(spec: DatasetSpec) -> list[Path]:
    root = resolve(spec.local_dir)
    found: list[Path] = []
    for pattern in spec.patterns:
        found.extend(sorted(root.glob(pattern)))
    return found


def read_manifest(spec: DatasetSpec) -> Manifest | None:
    path = resolve(spec.local_dir) / "manifest.json"
    if not path.is_file():
        return None
    return Manifest.model_validate_json(path.read_text("utf-8"))


def count_rows(spec: DatasetSpec, manifest: Manifest | None) -> int:
    if manifest is None:
        return 0
    return sum(v for k, v in manifest.counts.items() if k not in spec.exclude_counts)
```

```python title="src/rukh/data/publish.py"
def render_card(spec: DatasetSpec, manifest: Manifest | None, owner: str) -> str:
    """Render the dataset card; the tokenizer uses its own README as the card."""
    if spec.repo_type == "model":
        return (resolve(spec.local_dir) / "README.md").read_text("utf-8")
    env = Environment(
        loader=FileSystemLoader(str(CARDS_DIR)),
        undefined=StrictUndefined,
        autoescape=False,
        keep_trailing_newline=True,
    )
    rows = count_rows(spec, manifest)
    context = {
        "repo_id": f"{owner}/{spec.name}",
        "license": spec.license,
        "license_text": spec.license_text,
        "pretty_name": spec.pretty_name,
        "task_categories": spec.task_categories,
        "size_category": size_category(rows),
        "source_datasets": spec.source_datasets,
        "tags": spec.tags,
        "description": spec.description,
        "command": spec.command,
        "columns": spec.columns,
        "source": spec.source,
        "rows": rows,
        "files": manifest.files if manifest else [],
        "months": manifest.months if manifest else [],
        "filters_json": json.dumps(manifest.filters if manifest else {}, indent=2, default=str),
        "counts_json": json.dumps(manifest.counts if manifest else {}, indent=2),
        "created_at": manifest.created_at.date().isoformat() if manifest else "unknown",
        "rukh_version": manifest.rukh_version if manifest else "unknown",
    }
    return env.get_template("dataset.md.jinja").render(**context)
```

El tokenizador usa su propio README como card: no tiene filas, columnas ni filtros, y escribirlo a
mano una vez es más honesto que inventar una plantilla para un solo caso.

**`StrictUndefined`** es la decisión del fichero. Por defecto, Jinja pinta una variable inexistente
como cadena vacía: con la errata `{{ licence }}`, la card saldría con `license:` vacía, y el Hub la
rechazaría o, peor, la aceptaría. Con `StrictUndefined` la plantilla lanza al renderizar, antes de
tocar la red. Es el `extra="forbid"` de M0 aplicado a plantillas. `autoescape=False` porque la salida
es Markdown, y `default=str` para que un tipo raro en los filtros dé una representación fea y no una
excepción al publicar.

```python title="src/rukh/data/publish.py"
def _api():  # type: ignore[no-untyped-def]
    """The ``HfApi`` client (tests monkeypatch this)."""
    from huggingface_hub import HfApi

    return HfApi()


def upload_folder(api: object, spec: DatasetSpec, repo_id: str) -> str:
    """Upload the whole local directory in one go; returns the method that was used.

    The card is always uploaded separately from the staged copy, so ``README.md`` is excluded
    here. A ``large`` dataset uses ``upload_large_folder`` (resumable, multi-threaded) when the
    installed ``huggingface_hub`` provides it.
    """
    large = callable(getattr(api, "upload_large_folder", None))
    if spec.large and large:
        api.upload_large_folder(  # type: ignore[attr-defined]
            repo_id=repo_id,
            folder_path=str(resolve(spec.local_dir)),
            repo_type=spec.repo_type,
            allow_patterns=spec.patterns,
            ignore_patterns=["README.md"],
        )
        return "upload_large_folder"
    api.upload_folder(  # type: ignore[attr-defined]
        repo_id=repo_id,
        folder_path=str(resolve(spec.local_dir)),
        repo_type=spec.repo_type,
        allow_patterns=spec.patterns,
        ignore_patterns=["README.md"],
        commit_message="Upload data",
    )
    return "upload_folder"
```

Todo el fichero se prueba sin red porque el cliente del Hub solo se crea en `_api()`.

Los dos datasets grandes rondan 1 GB cada uno. Con `upload_folder` serían una sola petición larga que,
cortada a los cuarenta minutos, se pierde entera; `upload_large_folder` trocea, sube en paralelo y
reanuda donde se quedó. El `getattr` pregunta si el método existe en vez de comparar versiones, y eso
funciona con cualquier versión y con el doble de los tests. El README se excluye porque la card se
sube aparte.

```python title="src/rukh/data/publish.py"
def publish(name: str, cfg: PublishConfig, dry_run: bool = False) -> PublishResult:
    """Render the card and upload (or, with ``dry_run``, stage) one registry entry."""
    if name not in DATASETS:
        raise KeyError(f"unknown dataset {name!r}; known: {', '.join(DATASETS)}")
    spec = DATASETS[name]
    manifest = read_manifest(spec)
    files = local_files(spec)
    if not files:
        raise FileNotFoundError(f"nothing to publish under {resolve(spec.local_dir)}")
    repo_id = f"{cfg.owner}/{spec.name}"
    card = render_card(spec, manifest, cfg.owner)
    stage = resolve(cfg.publish_dir) / spec.name
    stage.mkdir(parents=True, exist_ok=True)
    card_path = stage / "README.md"
    card_path.write_text(card, encoding="utf-8", newline="\n")
    rel_files = [p.relative_to(resolve(spec.local_dir)).as_posix() for p in files]
    if not dry_run:
        api = _api()
        api.create_repo(repo_id, repo_type=spec.repo_type, exist_ok=True)
        upload_folder(api, spec, repo_id)
        api.upload_file(
            path_or_fileobj=str(card_path),
            path_in_repo="README.md",
            repo_id=repo_id,
            repo_type=spec.repo_type,
            commit_message="Update card",
        )
    return PublishResult(
        name=spec.name,
        repo_id=repo_id,
        repo_type=spec.repo_type,
        dry_run=dry_run,
        card_path=card_path.as_posix(),
        files=rel_files,
        rows=count_rows(spec, manifest),
    )
```

<Src file="src/rukh/data/publish.py" tag="p1" lines="368-403" />

En `publish` importa el orden. Primero comprueba que hay ficheros que subir, para no crear un
repositorio vacío en el Hub. Después escribe la card en disco siempre, se vaya a subir o no, y eso es
lo que hace útil `--dry-run`. Por último, las tres llamadas de red: crear el repositorio con
`exist_ok=True` (publicar dos veces actualiza), subir los datos y subir la card la última. Si algo se
corta, queda a medias la subida de datos, no una documentación de datos que no están.

<Transfer concept="La documentación se genera del artefacto, no se escribe al lado" where="Un modelo en un registro, un esquema de API, un dataset interno, un informe de evaluación.">
  La card se rellena con el manifiesto que escribió el paso que produjo los datos; nadie teclea
  conteos ni filtros, y si el dataset se regenera, la card cambia sola. El fallo que evita es el más
  común: una card escrita a mano que dice `min_elo: 2000` junto a un fichero regenerado con 1800 tres
  meses después. Nadie miente; nadie vuelve a leer el README. Si la documentación de tu artefacto

```python title="src/rukh/cli.py"
@data_app.command("publish")
def data_publish(
    name: Annotated[
        str | None, typer.Option("--name", help="Registry entry, e.g. rukh-games-1800.")
    ] = None,
    config: PipelineOption = None,
    dry_run: Annotated[
        bool, typer.Option("--dry-run", help="Render the card and list files; no network.")
    ] = False,
    list_names: Annotated[bool, typer.Option("--list", help="List the registry and exit.")] = False,
    as_json: Annotated[bool, typer.Option("--json", help="Print the result as JSON.")] = False,
) -> None:
    """Render the dataset card and upload one dataset (or the tokenizer) to the Hub."""
    from rukh.data.pipeline import load_pipeline
    from rukh.data.publish import DATASETS, publish

    if list_names:
        for spec in DATASETS.values():
            typer.echo(f"{spec.name:<22} {spec.repo_type:<8} {spec.local_dir}")
        return
    if name is None:
        typer.echo("error: --name is required (see --list)", err=True)
        raise typer.Exit(code=2)
    cfg = load_pipeline(config).publish
    try:
        result = publish(name, cfg, dry_run=dry_run)
    except (KeyError, FileNotFoundError) as exc:
        typer.echo(f"error: {exc}", err=True)
        raise typer.Exit(code=1) from exc
    if as_json:
        typer.echo(result.model_dump_json(indent=2))
        return
    typer.echo(f"repo:     {result.repo_id} ({result.repo_type})")
    typer.echo(f"mode:     {'dry-run (card staged, nothing uploaded)' if dry_run else 'uploaded'}")
    typer.echo(f"rows:     {result.rows}")
    typer.echo(f"card:     {result.card_path}")
    typer.echo("files:")
    for path in result.files:
        typer.echo(f"  {path}")
```

## Publicar en tu cuenta de Hugging Face

Los datasets del curso viven en `chorcat`, la cuenta de su autor, y ahí no puedes escribir. Para que
los tuyos salgan con tu nombre hacen falta cuatro cosas, y ninguna toca el código.

**La cuenta.** Crea una gratuita en [huggingface.co/join](https://huggingface.co/join). Tu nombre de
usuario es el _owner_: los repositorios quedarán como `<tu-usuario>/rukh-games-1800`.

**El token.** En [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens), crea uno
de tipo **Write**. Es una contraseña: no va en el repositorio ni en ningún YAML.

**El login.** `hf` es la línea de comandos de `huggingface_hub`, que ya es dependencia del proyecto,
así que se lanza con `uv run` desde la raíz del repositorio, igual en Git Bash que en PowerShell:

```sh
uv run hf auth login
uv run hf auth whoami
```

El primero te pide el token (con `--token <token>` se lo das directamente) y lo guarda en tu carpeta
de usuario, en `.cache/huggingface/token`, que es donde lo busca el `HfApi()` de `_api`. El segundo
tiene que imprimir tu usuario. Si prefieres no guardar nada en disco, pon el token en la variable
`HF_TOKEN` solo para la sesión: `export HF_TOKEN=hf_…` en Git Bash, `$env:HF_TOKEN = 'hf_…'` en
PowerShell.

**El owner.** `rukh data publish` no pregunta a quién publica: lo lee de la sección `publish:` de
`configs/data/pipeline.yaml`, que en `p1` dice `owner: chorcat`. Cambia esa línea por tu usuario. Es
una diferencia tuya con `p1` que `git diff p1` te enseñará siempre, y a propósito. Si algún día
publicas con otro YAML (`--config`), cambia también su sección `publish:`. Con `chorcat` y tu token, la subida falla por permisos:
el Hub no deja escribir en la cuenta de otro.

Con eso, primero en seco y después de verdad:

```sh
uv run rukh data publish --name rukh-games-1800 --dry-run
uv run rukh data publish --name rukh-games-1800
```

En el primero, la línea `repo:` tiene que decir `<tu-usuario>/rukh-games-1800`; si dice `chorcat`,
el YAML no es el que crees. Los seis datasets son `rukh-games-1800`, `rukh-games-elite`,
`rukh-elo-bins`, `rukh-positions-eval`, `rukh-puzzles-split` y `rukh-pairs-dpo`, más el tokenizador,
`rukh-tokenizer`; cada uno se publica con su `--name` cuando su paso ha terminado, así que los de los
pasos largos (`evals`, `elite`) llegan con los labs del módulo. `rukh-games-1800` sube casi un giga:
`upload_large_folder` lo reanuda si se corta.

Si no quieres publicar, no pierdes nada: `--dry-run` deja la card en `data/publish/<nombre>/README.md`
y la lista de ficheros, sin tocar la red, y ningún módulo posterior lee tus datasets del Hub. M2 a M6
trabajan con lo que hay en `data/`, y lo publicado del curso sigue en `chorcat` por si necesitas
bajarlo.

<Exercise n="01" title="Lee una card antes de publicarla">

  Los filtros de `rukh-games-1800` llevan `min_plies`, `max_plies`, `legal_only` y el desglose

  `min_plies_deferred`. Los meses aparecen en la línea de `Source:` —2025-01 y 2025-02— y no hay
  ninguna marca de cuál valida: esa decisión es del entrenamiento, no del dataset, y está en el

Las filas son la suma de `manifest.counts`, que para este dataset son las partidas conservadas de
cada mes: 2 949 514 + 2 946 874 = 5 896 388. La categoría de tamaño sale de ahí: `1M<n<10M`.

fichero publicado. Solo cuenta `evaluated`. Si no se excluyeran, la card declararía un dataset varias
veces más grande de lo que es.

## Qué has aprendido

Tu pipeline de datos ya es algo que otra persona puede descargar y entender: un registro de siete
artefactos con sus licencias, una plantilla que se rellena con lo que los pasos registraron y una
subida que se ensaya sin red y se reanuda si se corta.

**Cómo se mide**: `uv run rukh data publish --list` imprime los siete, y
`uv run rukh data publish --name <nombre> --dry-run` deja en `data/publish/<nombre>/README.md` una
card cuya sección de filtros es el `manifest.json` del paso, tal cual. Con `HF_TOKEN`, el mismo
comando sin `--dry-run` deja el repositorio en `huggingface.co/datasets/<tu-usuario>/<nombre>` (o en
`huggingface.co/<tu-usuario>/rukh-tokenizer`, que es un repositorio de modelo).

Lo siguiente es la otra implementación del tokenizador, la de TypeScript del navegador, y la fixture
que comprueba que las dos dicen lo mismo.

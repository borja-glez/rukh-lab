## Qué vas a construir

Los mismos tres tokenizadores, otra vez, en TypeScript. Corren en el navegador de quien juega contra
el modelo, no comparten una línea con los de Python y tienen que producir **los mismos ids**.

Duplicar código incomoda, pero aquí no hay alternativa, y es la situación de cualquiera que sirva un
modelo en un sitio distinto de donde lo entrenó: un LLM en un móvil, un clasificador en el navegador,
un modelo exportado a otro runtime. Son cuatro ficheros en `rukh-web` y el test que los ata a la
fixture de Python.

<Callout kind="teoria" title="Por qué no se comparte el código">
  Llamar a un servidor Python en cada jugada haría depender de la red una demo que funciona sin
  conexión. Llevar Python al navegador con Pyodide son varios megabytes para ejecutar 400 líneas.
  Generar el TypeScript desde el Python con un transpilador es más código del que ahorra, y falla en
  las diferencias de semántica (la división entera, el `%` con negativos) que son las que producen
  ids distintos. Queda escribirlo dos veces y hacer que la divergencia sea imposible de pasar por
  alto, que es lo que hace la fixture.

</Callout>

## La estrategia: una fixture y dos suites

El vocabulario UCI se reimplementa copiando el orden de la enumeración. El BPE depende de los datos,
así que no se reimplementa el entrenamiento sino el codificador, que lee el `bpe.json` que entrenó
Python. Y un solo artefacto comprueba que las dos mitades dicen lo mismo: `fixtures/games.json`, las
veinte partidas que Python codificó con los tres esquemas. TypeScript las codifica por su cuenta y
compara.

Los tres JSON (`vocab.json`, `bpe.json` y la fixture) los copia a `src/lib/chess-lm/`
[`scripts/sync-tokenizer.mjs`](https://github.com/borja-glez/rukh-web/blob/9be992c/scripts/sync-tokenizer.mjs),
que antes de escribir comprueba que cada fichero es el artefacto que espera.

```ts title="src/lib/chess-lm/tokenizer.ts"
// depend on any data) implemented identically in Python (`rukh/src/rukh/tokenize/uci_vocab.py`)

const FILES = 'abcdefgh';
const RANKS = '12345678';

/** The 64 squares in file-major order: a1, a2, ..., a8, b1, ..., h8 (index `file * 8 + rank`). */
export const SQUARES: readonly string[] = Array.from({ length: 64 }, (_, i) => {
  const file = FILES[Math.floor(i / 8)];
  const rank = RANKS[i % 8];
  return `${file}${rank}`;
});

  '<bos>',
  '<eos>',
  '<mask>',
  '<unk>',
  '<1-0>',
  '<0-1>',
  '<1/2>',
```

```ts title="src/lib/chess-lm/tokenizer.ts"
function coords(square: string): [number, number] {
  return [FILES.indexOf(square[0] ?? ''), RANKS.indexOf(square[1] ?? '')];
}

/** True if `to` is reachable from `from` by a queen (same file, rank or diagonal) or a knight. */
function reachable(from: string, to: string): boolean {
  if (from === to) return false;
  const [ff, fr] = coords(from);
  const [tf, tr] = coords(to);
  const df = Math.abs(tf - ff);
  const dr = Math.abs(tr - fr);
  const queen = df === 0 || dr === 0 || df === dr;
  const knight = (df === 1 && dr === 2) || (df === 2 && dr === 1);
  return queen || knight;
}

/** Maps an Elo to its bin token: `clamp(elo, 600, 3299)` floored to hundreds, four digits. */
export function eloBin(elo: number, side: 'w' | 'b'): string {
  const clamped = Math.min(Math.max(elo, ELO_MIN), ELO_CLAMP_MAX);
  const bin = Math.floor(clamped / ELO_BIN_WIDTH) * ELO_BIN_WIDTH;
  return `<${side}${String(bin).padStart(4, '0')}>`;
}

function eloBinTokens(side: 'w' | 'b'): string[] {
  return Array.from({ length: ELO_BIN_COUNT }, (_, i) => eloBin(ELO_MIN + i * ELO_BIN_WIDTH, side));
}
```

```ts title="src/lib/chess-lm/tokenizer.ts"
/** Enumerates the 1968 pseudo-legal UCI move strings: 1792 plain moves then 176 promotions. */
export function buildMoves(): string[] {
  const moves: string[] = [];
  for (const from of SQUARES) {
    for (const to of SQUARES) {
      if (reachable(from, to)) moves.push(`${from}${to}`);
    }
  }
  for (const [fromRank, toRank] of [
    ['7', '8'],
    ['2', '1'],
  ]) {
    for (const from of SQUARES) {
      if (from[1] !== fromRank) continue;
      for (const to of SQUARES) {
        if (to[1] !== toRank) continue;
        if (Math.abs(coords(to)[0] - coords(from)[0]) > 1) continue;
        for (const piece of PROMOTION_PIECES) moves.push(`${from}${to}${piece}`);
      }
    }
  }
  return moves;
}

/** The full 2030-token vocabulary: specials, white Elo bins, black Elo bins, moves. */
export function buildVocab(): string[] {
  return [...SPECIALS, ...eloBinTokens('w'), ...eloBinTokens('b'), ...buildMoves()];
}
```

```ts title="src/lib/chess-lm/tokenizer.ts"
   * `[<bos>, <wXXXX>, <bXXXX>, ...moves, <result>, <eos>]`. When the whole game fits in `maxLen`
   * the sequence ends with `<eos>`; otherwise it is cut to the first `maxLen` ids (no result, no
   * `<eos>`), exactly as `UciTokenizer.encode_game` does in Python.
   */
  encodeGame(
    uci: string,
    whiteElo: number,
    blackElo: number,
    result: string,
    maxLen = 200,
  ): number[] {
    const resultToken = RESULT_TOKENS[result.trim()];
    if (resultToken === undefined) throw new Error(`unknown result: ${result}`);
    const ids = [
      BOS_ID,
      this.tokenId(eloBin(whiteElo, 'w')),
      this.tokenId(eloBin(blackElo, 'b')),
      ...this.encodeMoves(uci),
      this.tokenId(resultToken),
      EOS_ID,
    ];
    return ids.length <= maxLen ? ids : ids.slice(0, maxLen);
  }

  /** Token strings for a sequence of ids; out-of-range ids decode to `<unk>`. */
  decode(ids: readonly number[]): string[] {
    return ids.map((id) => this.tokens[id] ?? '<unk>');
  }
}
```

## `bpe.ts`: reproducir el codificador, no el entrenamiento

Este es el fichero difícil, y la cabecera explica por qué.

```ts title="src/lib/chess-lm/bpe.ts"
// Applies a BPE model trained with Hugging Face `tokenizers` (`models.BPE` with a
// `WhitespaceSplit` pre-tokenizer, no continuing-subword prefix and no end-of-word suffix) to
// UCI text. It reads the `tokenizer.json` that `Tokenizer.save()` writes and reproduces the
// encoder: split on whitespace, start from single characters and merge the adjacent pair with
// the lowest merge rank (leftmost on ties) until nothing merges, then map symbols to ids.
// Only that subset is implemented: a file with dropout, `fuse_unk`, `byte_fallback`, an affix or
// another pre-tokenizer is rejected by the constructor instead of being encoded incorrectly.

export interface BpeAddedToken {
  id: number;
  content: string;
  special?: boolean;
}

export interface BpeFile {
  model: {
    type?: string;
    unk_token?: string | null;
    ignore_merges?: boolean;
    dropout?: number | null;
    continuing_subword_prefix?: string | null;
    end_of_word_suffix?: string | null;
    fuse_unk?: boolean;
    byte_fallback?: boolean;
    vocab: Record<string, number>;
    merges: string[] | [string, string][];
  };
  pre_tokenizer?: { type?: string } | null;
  added_tokens?: BpeAddedToken[];
}

/** Pre-tokenizers this loader reproduces; anything else splits words differently. */
```

El JSON de `Tokenizer.save()` tiene muchas opciones que cambian cómo se codifica, y un cargador que
las ignore produce ids distintos sin avisar. La decisión del fichero es no implementar las que no se
usan y rechazar un fichero que las declare.

```ts title="src/lib/chess-lm/bpe.ts"
/**
 * Rejects a `tokenizer.json` whose options this loader does not implement, instead of encoding
 * it as if they held their default value. The supported subset is listed in the README.
 */
function assertSupported(file: BpeFile): void {
  const { model } = file;
  const unsupported = (option: string, value: unknown, expected: string): Error =>
    new Error(
      `unsupported BPE model: ${option} is ${JSON.stringify(value) ?? 'undefined'}, ` +
        `this loader only supports ${expected}`,
    );

  if (model.type !== undefined && model.type !== 'BPE') {
    throw unsupported('model.type', model.type, '"BPE"');
  }
  if (model.dropout !== undefined && model.dropout !== null) {
    throw unsupported('model.dropout', model.dropout, 'null');
  }
  for (const option of ['continuing_subword_prefix', 'end_of_word_suffix'] as const) {
    const value = model[option];
    if (value !== undefined && value !== null && value !== '') {
      throw unsupported(`model.${option}`, value, 'null or ""');
    }
  }
  for (const option of ['fuse_unk', 'byte_fallback'] as const) {
    if (model[option] === true) throw unsupported(`model.${option}`, true, 'false');
  }
  const preTokenizer = file.pre_tokenizer;
  if (preTokenizer != null && !SUPPORTED_PRE_TOKENIZERS.includes(preTokenizer.type ?? '')) {
    throw unsupported(
      'pre_tokenizer.type',
      preTokenizer.type,
      SUPPORTED_PRE_TOKENIZERS.map((type) => `"${type}"`).join(', '),
    );
  }
}

function escapeRegExp(text: string): string {
  return text.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}
```

`assertSupported` es la puerta: lanza con la opción, su valor y lo que acepta. Qué haría cada una si
se ignorase:

- `dropout` salta fusiones al azar para regularizar, así que da ids distintos en cada pasada.
- `continuing_subword_prefix` (el `##` de BERT) y `end_of_word_suffix` (el `</w>` del BPE clásico)
  cambian los propios tokens: con prefijo, `e4` en medio de palabra es `##e4`.
- `fuse_unk` junta desconocidos seguidos, y `byte_fallback` los parte en bytes.
- Otro `pre_tokenizer` parte el texto en otros sitios, y con eso cambia todo.

<Transfer concept="Rechazar lo que no implementas" where="Cualquier lector de un formato ajeno: un parser de configuración, un cliente de una API con campos opcionales, un cargador de checkpoints.">
  Al implementar un subconjunto, la tentación es ignorar lo que "no usamos", y el resultado es un
  lector que acepta cualquier fichero y da resultados silenciosamente incorrectos. Enumerar lo no
  soportado y lanzar cuesta una función, y el fallo ocurre al cargar, con un mensaje que nombra la
  opción, en vez de tres capas más allá. Es `extra="forbid"` aplicado a un formato que no controlas.

</Transfer>

```ts title="src/lib/chess-lm/bpe.ts"
export class BpeTokenizer {
  readonly vocab: ReadonlyMap<string, number>;
  readonly tokens: readonly string[];
  readonly unkId: number;
  /** Merge rank by `a\u0000b` key (the pair separator cannot appear in a token). */
  private readonly ranks: Map<string, number>;
  private readonly addedTokens: Map<string, number>;
  private readonly addedPattern: RegExp | null;
  private readonly ignoreMerges: boolean;

  constructor(file: BpeFile) {
    assertSupported(file);
    const { model } = file;
    this.vocab = new Map(Object.entries(model.vocab));
    const size = Math.max(-1, ...this.vocab.values()) + 1;
    const tokens: string[] = new Array<string>(size).fill('');
    for (const [token, id] of this.vocab) tokens[id] = token;
    this.tokens = tokens;

    const unkToken = model.unk_token ?? DEFAULT_UNK_TOKEN;
    const unkId = this.vocab.get(unkToken);
    if (unkId === undefined) throw new Error(`BPE vocabulary has no ${unkToken} token`);
    this.unkId = unkId;
    this.ignoreMerges = model.ignore_merges ?? false;

    this.ranks = new Map();
    model.merges.forEach((merge, rank) => {
      const [a, b] = typeof merge === 'string' ? splitMerge(merge) : merge;
      if (!this.vocab.has(a) || !this.vocab.has(b) || !this.vocab.has(a + b)) return;
      this.ranks.set(pairKey(a, b), rank);
    });

    this.addedTokens = new Map();
    for (const added of file.added_tokens ?? []) this.addedTokens.set(added.content, added.id);
    const contents = [...this.addedTokens.keys()].sort((x, y) => y.length - x.length);
    this.addedPattern =
      contents.length > 0 ? new RegExp(`(${contents.map(escapeRegExp).join('|')})`) : null;
  }
```

`ranks` guarda la posición de cada par en la lista de fusiones, con un carácter nulo de separador
porque no puede aparecer dentro de un token. El filtro descarta las fusiones cuyo resultado no está en
el vocabulario: el entrenador recorta al tamaño pedido y puede dejar fusiones huérfanas, que
producirían símbolos sin id. Las dos formas de `merges` cubren dos versiones del formato de
`tokenizers`.

`tokenize` aparta primero los tokens añadidos, los especiales: pasado por BPE, `<bos>` saldría como
un puñado de ids. La expresión regular los ordena de más largo a más corto para que uno que sea
prefijo de otro no gane.

```ts title="src/lib/chess-lm/bpe.ts"
  private tokenizeSpan(text: string): string[] {
    const out: string[] = [];
    for (const word of text.split(/\s+/)) {
      if (word.length > 0) out.push(...this.mergeWord(word));
    }
    return out;
  }

  private mergeWord(word: string): string[] {
    if (this.ignoreMerges && this.vocab.has(word)) return [word];
    const symbols = Array.from(word);
    for (;;) {
      let best = -1;
      let bestRank = Number.POSITIVE_INFINITY;
      for (let i = 0; i + 1 < symbols.length; i++) {
        const rank = this.ranks.get(pairKey(symbols[i]!, symbols[i + 1]!));
        if (rank !== undefined && rank < bestRank) {
          bestRank = rank;
          best = i;
        }
      }
      if (best < 0) return symbols;
      symbols.splice(best, 2, symbols[best]! + symbols[best + 1]!);
    }
  }
}
```

Y aquí está el algoritmo: desde los caracteres sueltos, en cada vuelta se aplica **el par adyacente
con el rango más bajo**, la fusión más temprana, hasta que no queda ninguno. El `<` estricto decide
los empates a favor del par de más a la izquierda, como `tokenizers`; con `<=` saldría otra
segmentación.

<Callout kind="roto" title="Aplicar las fusiones como si fueran un conjunto">
  Lo ingenuo es recorrer la palabra y unir cualquier par que esté en la tabla, y eso deja correr una

juega peor en el navegador que en las pruebas, y nadie miraría el tokenizador.

```ts title="tests/parity.test.ts"
// Parity with the Python tokenizers (`rukh/src/rukh/tokenize/`). The JSON files under
// src/lib/chess-lm/ are synced from ../rukh/artifacts/tokenizer with `pnpm sync:tokenizer`; these
// tests fail (never skip) when they are missing.
import { existsSync, readFileSync } from 'node:fs';
import { resolve } from 'node:path';
import { describe, expect, it } from 'vitest';
import { buildVocab, UciTokenizer } from '../src/lib/chess-lm/tokenizer';
import { SanCharTokenizer } from '../src/lib/chess-lm/san-chars';
import { loadBpe, type BpeFile } from '../src/lib/chess-lm/bpe';

const dir = resolve(import.meta.dirname, '../src/lib/chess-lm');

interface VocabFile {
  version: number;
  specials: string[];
  tokens: string[];
}

interface FixtureGame {
  uci: string;
  san: string;
  white_elo: number;
  black_elo: number;
  result: string;
  uci_ids: number[];
  san_ids: number[];
  bpe_ids: number[];
}

interface FixtureFile {
  games: FixtureGame[];
}

function readJson<T>(name: string): T {
  const path = resolve(dir, name);
  if (!existsSync(path)) {
    throw new Error(`fixture missing: ${path} (run \`pnpm sync:tokenizer\`)`);
  }
  return JSON.parse(readFileSync(path, 'utf8')) as T;
}

function readGames(): FixtureGame[] {
  const fixture = readJson<FixtureFile | FixtureGame[]>('fixtures/games.json');
  const games = Array.isArray(fixture) ? fixture : fixture.games;
  if (!Array.isArray(games) || games.length === 0) {
    throw new Error('fixture missing: fixtures/games.json has no games');
  }
  return games;
}
```

```ts title="tests/parity.test.ts"
describe('parity with Python', () => {
  it('vocab.json matches buildVocab() one to one', () => {
    const vocab = readJson<VocabFile>('vocab.json');
    expect(vocab.tokens).toEqual(buildVocab());

  it('UciTokenizer.encodeGame reproduces uci_ids', () => {
    const tokenizer = new UciTokenizer();

      expect(
        tokenizer.encodeGame(game.uci, game.white_elo, game.black_elo, game.result),

      ).toEqual(game.uci_ids);

  it('SanCharTokenizer.encode reproduces san_ids', () => {
    const tokenizer = new SanCharTokenizer();
```

  como desde M0. Después pasa el test de paridad:

```sh
node scripts/sync-tokenizer.mjs

```

y `fixtures/games.json`; el test
tiene que dar cinco en verde: el vocabulario uno a uno, las veinte partidas y los tres esquemas. Si
falla con `fixture missing`, la copia no se hizo; si falla un `game N`, esa partida es la que hay que
mirar.

</Callout>

<Callout kind="mundo-real" title="Tres copias del mismo fichero">
  `rukh-web` y `rukh-lab` tienen cada uno su copia de los artefactos del tokenizador: tres copias del

  clonar el repositorio de ML. Cada web tiene su test de paridad y un test de hash compara las copias
  entre sí; el hash no detecta que dos copias diverjan a la vez del original, y la paridad sí. Cuando
  dupliques un artefacto, duplica también la comprobación.

<Exercise n="01" title="Rompe la paridad de dos formas distintas">
  En una copia de `rukh-web`, quita el `padStart(4, '0')` de `eloBin` (deja `String(bin)`) y ejecuta
  `pnpm test`. ¿Qué tests fallan? Después déjalo como estaba y cambia el orden de
  `PROMOTION_PIECES` a `['q', 'b', 'r', 'n']`. ¿Qué falla ahora, y cuál de los dos fallos habrías
  detectado con una fixture de veinte partidas normales?

<Solution>
  Sin el `padStart`, los tokens de Elo pasan a ser `<w600>` en vez de `<w0600>`: fallan
  `vocab.json matches buildVocab() one to one` —los 54 tokens de Elo, del id 8 al 61, no coinciden— y
  `UciTokenizer.encodeGame reproduces uci_ids` en las veinte partidas, porque todas llevan dos
  tokens de Elo. Es un fallo ruidoso.

Con el orden de las promociones cambiado falla el primer test con un diff de los 176 últimos tokens,
y `encodeGame` solo falla en las partidas de la fixture que tienen una promoción. Si la fixture
fuesen veinte partidas normales, ese segundo test pasaría y el único que lo detectaría sería el
primero.

**Una fixture solo cubre lo que contiene.** Por eso el primer test compara las dos enumeraciones
enteras, y por eso el test de Python exige que la fixture tenga enroques por los dos flancos y una
promoción a caballo.

</Solution>
</Exercise>

## Qué has aprendido

Un modelo servido lejos de donde se entrenó acaba con dos tokenizadores. Para que esa duplicación no
se convierta en una divergencia silenciosa has montado una enumeración que no depende de datos, un
artefacto exportado desde el lado de referencia y un test en cada copia que lo reproduce token a
token.

**Cómo se mide**: `pnpm test` en `rukh-web` pasa las cinco comprobaciones de paridad sobre las veinte
partidas; `buildVocab().length === 2030` y `vocab.tokens` coincide uno a uno con la enumeración.

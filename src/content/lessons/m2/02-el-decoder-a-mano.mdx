## Qué vas a construir

El modelo entero: tres ficheros, 257 líneas contando el `__init__.py`, y 159 de tests. Es poco, y
ese es el argumento para escribirlo a mano en vez de importar `nn.TransformerDecoder`: cabe en una
sentada, y cuando en M3 el encoder sea «lo mismo sin la máscara causal» sabrás qué frase cambias.
Todo está aquí, en el tag `p2`; si copias los bloques en orden, tienes `src/rukh/models/`.

<Src file="src/rukh/models/config.py" tag="p2" lines="1-9" />

`BaseConfig` es el modelo de pydantic con `extra="forbid"` de M0: una clave desconocida es un error.
Aquí importa más que en ninguna otra config, porque un `n_layers: 16` con la ese de más produciría un
modelo de doce capas sin que nadie lo supiera.

```python title="src/rukh/models/config.py"
class DecoderConfig(BaseConfig):
    """Shape of a ``MoveDecoder``.

    ``d_ff`` defaults to ``4 * d_model`` and ``pos`` picks learned positional embeddings or
    rotary embeddings (RoPE) applied to the queries and keys of every head.
    """

    vocab_size: int = 2030
    n_layer: int = 12
    n_head: int = 8
    d_model: int = 512
    d_ff: int | None = None  # None -> 4 * d_model
    block: int = 200
    dropout: float = 0.0
    pos: Literal["learned", "rope"] = "learned"
    tie_embeddings: bool = True
```

<Src file="src/rukh/models/config.py" tag="p2" lines="12-27" />

Las decisiones que no son evidentes:

- `d_ff: int | None = None`: el ancho del MLP casi siempre es `4 * d_model`, y `None` significa «el
  que toca», para no tener que cambiar dos campos al cambiar de talla.
- **`dropout: float = 0.0`**, a propósito: con 240 millones de tokens y 39 millones de parámetros no
  hay escasez de datos contra la que regularizar. El encoder de M3 lo enciende, porque verá muchas
  menos etiquetas.
- `pos = "learned"` por el argumento de la lección anterior. <Term id="rope">RoPE</Term> queda
  detrás de una bandera, escrito y probado, para que la decisión cambie algún día por una medida.
- `block: int = 200` es el contexto, y reaparece en el recorte del prompt, el límite
  de <Term id="ply">plies</Term>, el exportador y los metadatos del `.onnx`. Vive aquí porque es del
  modelo.

```python title="src/rukh/models/config.py"
    @model_validator(mode="after")
    def _check(self) -> DecoderConfig:
        if self.d_model % self.n_head:
            raise ValueError(f"d_model={self.d_model} is not divisible by n_head={self.n_head}")
        if min(self.vocab_size, self.n_layer, self.n_head, self.d_model, self.block) < 1:
            raise ValueError("vocab_size, n_layer, n_head, d_model and block must be positive")
        if not 0.0 <= self.dropout < 1.0:
            raise ValueError(f"dropout must be in [0, 1), got {self.dropout}")
        if self.d_ff is not None and self.d_ff < 1:
            raise ValueError(f"d_ff must be positive, got {self.d_ff}")
        if self.pos == "rope" and (self.d_model // self.n_head) % 2:
            raise ValueError("rope needs an even head dimension")
        return self
```

<Src file="src/rukh/models/config.py" tag="p2" lines="29-41" />

El validador corre después de construir el objeto y cubre las tres formas de pedir un modelo
imposible: una anchura que no se reparte entre las cabezas, un número no positivo y RoPE con una
dimensión de cabeza impar (la rotación va por parejas). Sin él, `d_model=100, n_head=8` fallaría
mucho más tarde, dentro de un `view()`, con un mensaje que no menciona ninguno de tus dos números.

## `decoder.py`: el modelo

La cabecera declara el contrato del fichero.

```python title="src/rukh/models/decoder.py"
"""``MoveDecoder``: a hand-written GPT decoder over the fixed UCI vocabulary.

Pure model code: it knows about tensors and nothing about the data pipeline, so it can be
imported by the training loop, the sampler and the ONNX exporter alike. Blocks are pre-norm
(``x = x + attn(ln1(x))``; ``x = x + mlp(ln2(x))``), attention is causal through
``F.scaled_dot_product_attention(..., is_causal=True)``, the MLP uses GELU and the language
modelling head is tied to the token embedding.
"""

from __future__ import annotations

import math

import torch
from torch import Tensor, nn
from torch.nn import functional as F

from rukh.models.config import DecoderConfig

# ``<pad>`` is id 0 in every scheme; the loss must ignore it (see ``loader.IGNORE_INDEX``).
IGNORE_INDEX = 0
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="1-21" />

«Código de modelo puro: sabe de tensores y nada del pipeline de datos». Por eso el bucle, el
muestreador y el exportador pueden importarlo sin arrastrarse unos a otros.

**`IGNORE_INDEX = 0` es `<pad>`**, el número más caro de olvidar del módulo. Sin él en la entropía
cruzada, el modelo aprende con toda confianza que después de cualquier cosa viene `<pad>`, porque es
verdad en los datos: todas las secuencias cortas acaban rellenas.

```python title="src/rukh/models/decoder.py"
def rope_tables(
    seq_len: int, head_dim: int, device: torch.device, base: float = 10_000.0
) -> tuple[Tensor, Tensor]:
    """``(cos, sin)`` of shape ``(seq_len, head_dim)`` for rotary position embeddings."""
    inv_freq = 1.0 / (base ** (torch.arange(0, head_dim, 2, dtype=torch.float32) / head_dim))
    angles = torch.outer(torch.arange(seq_len, dtype=torch.float32), inv_freq)
    full = torch.cat([angles, angles], dim=-1)
    return full.cos().to(device), full.sin().to(device)
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="24-31" />

`inv_freq` reparte 32 frecuencias entre las 64 dimensiones de una cabeza, y el `cat` duplica los
ángulos porque la variante por mitades espera la tabla entera. Todo en `float32` aunque se entrene
en <Term id="bf16">bf16</Term>: siete bits de mantisa no bastan para que la posición 199 tenga la
fase que le toca.

```python title="src/rukh/models/decoder.py"
def apply_rope(x: Tensor, cos: Tensor, sin: Tensor) -> Tensor:
    """Rotate ``x`` of shape ``(B, H, T, D)`` by the angles of the first ``T`` positions."""
    t = x.shape[-2]
    cos_t = cos[:t].to(dtype=x.dtype).view(1, 1, t, -1)
    sin_t = sin[:t].to(dtype=x.dtype).view(1, 1, t, -1)
    half = x.shape[-1] // 2
    rotated = torch.cat([-x[..., half:], x[..., :half]], dim=-1)
    return x * cos_t + rotated * sin_t
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="34-41" />

`cos[:t]` recorta la tabla a la longitud real, y los ángulos bajan a la precisión del tensor después
de haberse calculado bien.

```python title="src/rukh/models/decoder.py"
class CausalSelfAttention(nn.Module):
    """Multi-head causal self-attention with a single fused ``qkv`` projection."""

    def __init__(self, cfg: DecoderConfig) -> None:
        super().__init__()
        self.n_head = cfg.n_head
        self.head_dim = cfg.head_dim
        self.dropout = cfg.dropout
        self.qkv = nn.Linear(cfg.d_model, 3 * cfg.d_model)
        self.proj = nn.Linear(cfg.d_model, cfg.d_model)
        self.resid_drop = nn.Dropout(cfg.dropout)
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="44-54" />

Una sola matriz `qkv` produce consulta, clave y valor. Las cabezas no son parámetros sino una
reinterpretación de sus columnas, y por eso ocho cuestan lo que una.

<Callout kind="roto" title="Los nombres de los módulos son el formato de disco">
  `ln1`, `attn.qkv`, `attn.proj`, `ln2`, `mlp.fc` y `mlp.proj` son las claves de todos los
  checkpoints escritos. Renombrar uno parece una refactorización y es una incompatibilidad
  silenciosa: `load_state_dict` con `strict=False` carga lo que reconoce y deja el resto en la
  inicialización, y el modelo arranca, entrena y es otro. Por eso `rukh.train.load_state` comprueba
  a mano, después de cargar, que no falta ni sobra ninguna clave. Es el aviso «some weights were not
  initialized» de Hugging Face: léelo siempre, porque el modelo funciona igual y ya no es el que
  crees.
</Callout>

```python title="src/rukh/models/decoder.py"
    def forward(self, x: Tensor, cos: Tensor | None = None, sin: Tensor | None = None) -> Tensor:
        batch, seq, _ = x.shape
        q, k, v = self.qkv(x).split(x.shape[-1], dim=2)
        shape = (batch, seq, self.n_head, self.head_dim)
        q = q.view(shape).transpose(1, 2)
        k = k.view(shape).transpose(1, 2)
        v = v.view(shape).transpose(1, 2)
        if cos is not None and sin is not None:
            q = apply_rope(q, cos, sin)
            k = apply_rope(k, cos, sin)
        out = F.scaled_dot_product_attention(
            q, k, v, dropout_p=self.dropout if self.training else 0.0, is_causal=True
        )
        out = out.transpose(1, 2).contiguous().view(batch, seq, -1)
        return self.resid_drop(self.proj(out))
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="56-70" />

El `forward` de la atención es un baile de formas donde se equivoca todo el mundo la primera vez.
`split` da tres tensores `(B, T, d)`, el `view` parte la última dimensión en cabezas y el
`transpose(1, 2)` las pone delante del tiempo: `(B, H, T, D)`. Ese orden importa, porque la atención
multiplica las dos últimas dimensiones; con `(B, T, H, D)` mezclaría cabezas y posiciones y el modelo
entrenaría igual de contento dando basura.

A la vuelta, el `contiguous()` es obligatorio: tras un `transpose` la memoria está en otro orden y
`view` se niega a reinterpretarla. Y el `dropout_p` se apaga a mano al evaluar, porque la función no
consulta `self.training`.

```python title="src/rukh/models/decoder.py"
class Mlp(nn.Module):
    """Position-wise GELU feed-forward network."""

    def __init__(self, cfg: DecoderConfig) -> None:
        super().__init__()
        self.fc = nn.Linear(cfg.d_model, cfg.ff)
        self.proj = nn.Linear(cfg.ff, cfg.d_model)
        self.drop = nn.Dropout(cfg.dropout)

    def forward(self, x: Tensor) -> Tensor:
        return self.drop(self.proj(F.gelu(self.fc(x))))
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="73-83" />

Dos tercios de los parámetros de un bloque. La salida se llama `proj` a propósito: es el nombre que
busca la inicialización escalada.

```python title="src/rukh/models/decoder.py"
class Block(nn.Module):
    """One pre-norm transformer block."""

    def __init__(self, cfg: DecoderConfig) -> None:
        super().__init__()
        self.ln1 = nn.LayerNorm(cfg.d_model)
        self.attn = CausalSelfAttention(cfg)
        self.ln2 = nn.LayerNorm(cfg.d_model)
        self.mlp = Mlp(cfg)

    def forward(self, x: Tensor, cos: Tensor | None = None, sin: Tensor | None = None) -> Tensor:
        x = x + self.attn(self.ln1(x), cos, sin)
        return x + self.mlp(self.ln2(x))
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="86-98" />

El bloque <Term id="pre-norm">pre-norm</Term> en dos líneas: la normalización está dentro de cada
rama, y el camino recto es la autopista por la que el gradiente llega de la pérdida al embedding
sin pasar por doce peajes.

```python title="src/rukh/models/decoder.py"
class MoveDecoder(nn.Module):
    """GPT decoder over move tokens: ``forward`` returns ``(logits, loss)``.

    ``logits`` is always ``(B, T, vocab_size)``; ``loss`` is ``None`` unless ``targets`` is
    given, in which case it is the mean cross entropy with ``ignore_index=0`` (``<pad>``).
    """

    def __init__(self, cfg: DecoderConfig | None = None) -> None:
        super().__init__()
        self.cfg = cfg or DecoderConfig()
        self.tokens = nn.Embedding(self.cfg.vocab_size, self.cfg.d_model)
        self.positions = (
            nn.Embedding(self.cfg.block, self.cfg.d_model) if self.cfg.pos == "learned" else None
        )
        self.drop = nn.Dropout(self.cfg.dropout)
        self.blocks = nn.ModuleList(Block(self.cfg) for _ in range(self.cfg.n_layer))
        self.ln_f = nn.LayerNorm(self.cfg.d_model)
        self.lm_head = nn.Linear(self.cfg.d_model, self.cfg.vocab_size, bias=False)
        if self.cfg.tie_embeddings:
            self.lm_head.weight = self.tokens.weight
        if self.cfg.pos == "rope":
            cos, sin = rope_tables(self.cfg.block, self.cfg.head_dim, torch.device("cpu"))
            self.register_buffer("rope_cos", cos, persistent=False)
            self.register_buffer("rope_sin", sin, persistent=False)
        self.apply(self._init_weights)
        scale = 0.02 / math.sqrt(2 * self.cfg.n_layer)
        for name, param in self.named_parameters():
            if name.endswith("proj.weight"):
                nn.init.normal_(param, mean=0.0, std=scale)
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="101-129" />

La tabla de posiciones solo existe si `pos == "learned"`; con RoPE el atributo queda en `None`, que
es lo que consulta el `forward`. Tres detalles que se pagan si cambian de orden:

1. **El atado no copia**: hace que dos nombres apunten al mismo tensor. Atar después de entrenar
   tiraría uno de los dos.
2. Las tablas de RoPE son buffers `persistent=False`: guardarlas sería guardar algo recalculable y
   fijar el contexto dentro del fichero de pesos.
3. La inicialización escalada va la última; al revés, `apply` borraría el ajuste.

```python title="src/rukh/models/decoder.py"
    @staticmethod
    def _init_weights(module: nn.Module) -> None:
        if isinstance(module, nn.Linear):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)
            if module.bias is not None:
                nn.init.zeros_(module.bias)
        elif isinstance(module, nn.Embedding):
            nn.init.normal_(module.weight, mean=0.0, std=0.02)
```

```python title="src/rukh/models/decoder.py"
    def num_params(self, non_embedding: bool = True) -> int:
        """Parameter count; ``non_embedding`` drops the learned position table (nanoGPT rule)."""
        total = sum(p.numel() for p in self.parameters())

```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="140-145" />

`non_embedding=True` resta la tabla de posiciones, la convención de nanoGPT, para comparar modelos
con contextos distintos. No resta la de tokens, porque atada también es la capa de salida y sí hace
cómputo.

```python title="src/rukh/models/decoder.py"
    def forward(self, idx: Tensor, targets: Tensor | None = None) -> tuple[Tensor, Tensor | None]:
        """Logits ``(B, T, V)`` for ``idx`` ``(B, T)`` and, with ``targets``, the scalar loss."""
        seq = idx.shape[-1]
        if seq > self.cfg.block:
            raise ValueError(f"sequence of {seq} tokens is longer than block {self.cfg.block}")
        x = self.tokens(idx)
        cos = sin = None
        if self.positions is not None:
            steps = torch.arange(seq, device=idx.device)
            x = x + self.positions(steps)
        else:
            cos, sin = self.rope_cos, self.rope_sin
        x = self.drop(x)
        for block in self.blocks:
            x = block(x, cos, sin)
        logits = self.lm_head(self.ln_f(x))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(
                logits.reshape(-1, logits.shape[-1]),
                targets.reshape(-1),
                ignore_index=IGNORE_INDEX,
            )
        return logits, loss
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="147-170" />

Las posiciones aprendidas se suman al embedding; RoPE viaja como `(cos, sin)` hasta la atención, que
interpreta `None` como «sin rotación». La guarda de la primera línea da un `ValueError` con los dos
números en vez de un `IndexError` inútil. Y la pérdida se calcula dentro del modelo, para que el
bucle sea `_, loss = model(x, y)` y el mismo modelo sirva para entrenar e inferir.

```python title="src/rukh/models/decoder.py"
    @torch.no_grad()
    def next_logits(self, idx: Tensor) -> Tensor:
        """Logits of the last step only, ``(B, vocab_size)``, cropped to the block size."""
        cropped = idx[:, -self.cfg.block :]
        logits, _ = self(cropped)
        return logits[:, -1, :]
```

<Src file="src/rukh/models/decoder.py" tag="p2" lines="172-177" />

El `@torch.no_grad()` impide que una partida de doscientos plies acumule un grafo de autograd que
nadie va a derivar. El recorte `idx[:, -block:]` es solo una red de seguridad: se lleva por delante
la cabecera, y el muestreador de «Muestrear jugadas» recorta de otra manera.

## Los tests, que son el contrato

Quince tests que corren en CPU en menos de un segundo y que M3 heredará casi enteros. Si alguna vez
escribes o afinas otro modelo de secuencias, estos son los que merece la pena copiar: formas,
causalidad, relleno ignorado, determinismo y unos pasos de gradiente que bajan la pérdida.

```python title="tests/unit/test_decoder.py"
TOY = DecoderConfig(vocab_size=64, n_layer=2, n_head=4, d_model=32, block=16)
```

```python title="tests/unit/test_decoder.py"
def test_a_few_steps_of_gradient_descent_reduce_the_loss() -> None:
    torch.manual_seed(5)
    model = MoveDecoder(TOY)
    idx = toy_batch(seq=8, seed=6)
    targets = torch.roll(idx, -1, dims=1)
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-2)
    losses = []
    for _ in range(10):
        _, loss = model(idx, targets)
        assert loss is not None
        losses.append(loss.detach().item())
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
    assert losses[-1] < losses[0]
```

## El contrato, escrito antes que el código

```python title="src/rukh/models/encoder.py"
"""``PositionEncoder``: a hand-written bidirectional transformer over positions.

The brother of ``MoveDecoder``, and deliberately built from the same ``rukh.models.layers``
blocks: the whole difference is the attention mask. The decoder answers "what comes next?", so
a position may only look left; the encoder answers "what is this position?", so every token
sees every other one, including the ones after it. That is why the test that proves the decoder
right (a future token never changes a past logit) has to fail here, and ``test_encoder`` asserts
the opposite.

Two input schemes share the class (``EncoderConfig.input``):

``moves``
    the game so far in the P1 UCI vocabulary, the very tokens the decoder was trained on, so
    the masked-move head can be tied to the embedding and a pretrained decoder's intuition is
    directly comparable.
``squares``
    the 69 tokens of ``rukh.models.squares``, the position itself rather than its history.

Padding is expressed as a key mask, not as a special attention: ``attention_mask`` is ``True``
on real tokens and ``False`` on ``<pad>``, and the padded keys are switched off for every
query. The rows of padded queries are still computed (nobody reads them) and at least one real
token per row is required, otherwise softmax would see an entirely masked row and return NaN.
"""

from __future__ import annotations

import math
from typing import Literal

import torch
from torch import Tensor, nn
from torch.nn import functional as F

from rukh.models import layers
from rukh.models.config import EncoderConfig
from rukh.models.layers import rope_tables
```

El último párrafo es el que contiene una decisión y no una descripción: **el relleno se expresa
como máscara de claves, no como una atención especial**.

Hay dos formas de tratar el relleno en un encoder. Una es enmascarar las **claves**: cada posición
puede consultar a todas menos a las de relleno. La otra es enmascarar también las **consultas**: las
filas de las posiciones de relleno ni siquiera se calculan. La segunda suena mejor —ahorra trabajo—
y es la que produce `NaN`, porque una fila cuyas claves están todas apagadas le da al softmax una
fila entera de `-inf` y el softmax de eso no es cero, es indefinido. Rukh calcula esas filas, no las
mira nunca, y exige que cada secuencia tenga al menos un token real. Cuesta unos microsegundos de
cómputo inútil y quita una familia entera de `NaN` que aparecen tres capas más abajo.

## Dos constantes, y una de ellas es la lección

```python title="src/rukh/models/encoder.py"
PAD_ID = 0
"""``<pad>`` is id 0 in both schemes."""

MMM_IGNORE_INDEX = -100
"""Label of a position the masked-move loss must skip.

Not the decoder's ``0``. ``0`` is ``<pad>`` in **both** schemes, so using it to mean "nothing to
predict" would overload one id with two jobs: the loss could no longer tell a position it must
skip from a position where the right answer happens to be ``<pad>``. The decoder gets away with
it because its target is the next token of a packed stream and ``<pad>`` is never a target there;
here the distinction has to be explicit, and ``-100`` is outside every vocabulary, so "not
predicted" and "predict ``<pad>``" stay different things.
"""
```

El docstring de `MMM_IGNORE_INDEX` es el porqué que la lección 1 anticipó, escrito donde vive la
constante. La versión corta: en M2 «no puntúes esto» y «predice `<pad>`» querían decir lo mismo,
porque el relleno nunca era un objetivo legítimo. Aquí sí puede serlo, así que el valor que significa
«esta posición no entra en la pérdida» tiene que ser un número que no sea el id de nada. `-100` es
además la convención de PyTorch y de Hugging Face, lo que ahorra explicarlo cada vez que alguien lee
el código.

Guarda el matiz de por qué esto es peligroso: **elegir mal esa constante no lanza ninguna
excepción**. Simplemente unas cuantas posiciones dejan de puntuar, o puntúan sin deber, y la curva de
pérdida sale preciosa. Lo caza un test que cuenta, no uno que comprueba formas; está en la lección 5.

## La función que existe solo para el exportador

```python title="src/rukh/models/encoder.py"
def _tracing() -> bool:
    """``True`` while ``torch.export`` or ``torch.compile`` is capturing a graph.

    The padding check below reads a tensor to decide whether to raise, and a data-dependent
    branch like that is precisely what a graph capture cannot represent. Under ``torch.export``
    it would send the exporter back to the deprecated TorchScript tracer (D-027); under
    ``torch.compile`` it is worse in a quieter way — Dynamo cannot prove the condition, so it
    graph-breaks around it on **every** masked step of the MMM loop, which is a synchronisation
    point plus two half-graphs per step for a check that has already passed. Eager behaviour is
    unchanged: outside a capture both calls are ``False`` and the ValueError is raised as before.
    """
    return torch.compiler.is_exporting() or torch.compiler.is_compiling()
```

<Src file="src/rukh/models/encoder.py" tag="p3" lines="53-64" />

Doce líneas de las que once son explicación, y con razón: es el tipo de código que alguien borra por
«limpieza» en un año si no está escrito por qué está.

El problema que resuelve es general y lo vas a volver a ver. Una comprobación de validez que **lee
un tensor** para decidir si lanza —aquí, `if not mask.any(...)`— es una bifurcación que depende de
los datos, y una captura de grafo no puede representar eso: el grafo tiene que ser el mismo para
cualquier entrada. Bajo `torch.export`, el exportador se rinde y vuelve al tracer antiguo de
TorchScript, que es el camino que M2 dejó cerrado a propósito. Bajo `torch.compile` es peor de una
forma más silenciosa: Dynamo no puede demostrar la condición, así que corta el grafo alrededor de
ella en **cada** paso, y un corte de grafo es un punto de sincronización entre CPU y GPU más dos
mitades que se compilan por separado. El coste no es la comprobación, es el corte.

La solución no es quitar la comprobación —protege de un `NaN` real— sino apagarla exactamente
mientras alguien captura. Fuera de una captura, `is_exporting()` e `is_compiling()` son `False` y el
comportamiento es el de siempre. Y la propiedad que hace que apagarla sea legítimo está en la última
frase: **el grafo exportado es una función pura de su entrada de todos modos**, así que una
comprobación que solo sirve para dar un mensaje mejor no cambia lo que el grafo calcula.

<Transfer concept="Guardas que dependen de los datos bajo una captura de grafo" where="Cualquier modelo que se exporte, compile o trace: ONNX, TensorRT, torch.compile, XLA.">
  La regla operativa es corta: **una validación que lee un tensor es una bifurcación de datos, y las
  bifurcaciones de datos no se capturan**. Antes de exportar un modelo, busca los `if` que miran
  dentro de un tensor —comprobaciones de rango, `assert` sobre conteos, ramas según una longitud— y
  decide para cada uno si va fuera de la función que se captura o si se apaga durante la captura.

El síntoma cuando no lo haces no suele ser un error claro. Es un exportador que «funciona» pero cae
a un camino antiguo, un `torch.compile` que no acelera nada porque rompe el grafo veinte veces por
paso, o una forma que se queda fijada al valor que tenía el tensor de ejemplo.

</Transfer>

## El constructor: `causal=False` y un atado condicional

```python title="src/rukh/models/encoder.py"
class PositionEncoder(nn.Module):
    """Bidirectional transformer encoder: ``forward`` returns the hidden states ``(B, T, d)``."""

    def __init__(self, cfg: EncoderConfig | None = None) -> None:
        super().__init__()
        self.cfg = cfg or EncoderConfig()
        self.tokens = nn.Embedding(self.cfg.tokens, self.cfg.d_model)
        self.positions = (
            nn.Embedding(self.cfg.seq, self.cfg.d_model) if self.cfg.pos == "learned" else None
        )
        self.drop = nn.Dropout(self.cfg.dropout)
        self.blocks = nn.ModuleList(
            layers.Block(
                self.cfg.d_model, self.cfg.n_head, self.cfg.ff, self.cfg.dropout, causal=False
            )
            for _ in range(self.cfg.n_layer)
        )
        self.ln_f = nn.LayerNorm(self.cfg.d_model)
        self.mlm_head = nn.Linear(self.cfg.d_model, self.cfg.tokens, bias=False)
        if self.cfg.tie_embeddings and self.cfg.input == "moves":
            # Tied only for ``moves``: it is the P1 vocabulary, where the embedding and the head
            # describe the same 2 030 moves. The 47 square tokens are too few to be worth tying.
            self.mlm_head.weight = self.tokens.weight
        if self.cfg.pos == "rope":
            cos, sin = rope_tables(self.cfg.seq, self.cfg.head_dim, torch.device("cpu"))
            self.register_buffer("rope_cos", cos, persistent=False)
            self.register_buffer("rope_sin", sin, persistent=False)
        self.apply(layers.init_weights)
        scale = 0.02 / math.sqrt(2 * self.cfg.n_layer)
        for name, param in self.named_parameters():
            if name.endswith("proj.weight"):
                nn.init.normal_(param, mean=0.0, std=scale)
```

Léelo al lado del `__init__` de `MoveDecoder` de M2: es la misma secuencia de líneas. Embedding de
tokens, tabla de posiciones si toca, dropout, la pila de bloques, la normalización final, la cabeza,
el atado, las tablas de RoPE, la inicialización. Lo único que cambia de verdad es `causal=False` en
la construcción de los bloques y que la cabeza se llama `mlm_head` en vez de `lm_head`, porque
predice una jugada **tapada** y no la siguiente.

Tres detalles que sí son decisiones.

**`self.cfg.tokens` y `self.cfg.seq` en vez de `vocab_size` y `block`.** Las propiedades de
`EncoderConfig` de la lección anterior resuelven el esquema, así que este constructor no pregunta ni
una vez por `cfg.input` para decidir un tamaño. El único `if` que mira el esquema es el del atado,
que es una decisión y no una cuenta.

**El atado es condicional y el decoder lo tenía incondicional.** `tie_embeddings and input == "moves"`:
atar significa que el vector que representa `e2e4` y el vector contra el que se puntúa `e2e4` son el
mismo objeto, y eso solo tiene sentido si la entrada y la salida son el mismo vocabulario. Con 2 030
jugadas, atar ahorra 779 520 parámetros —el 5 % del modelo— y además impone esa simetría, que es lo
que uno quiere que signifique un <Term id="embedding">embedding</Term>. Con 47 tokens de casillas, lo
que se ahorraría son 18 048 parámetros y a cambio se obligaría al embedding de entrada a hacer de
clasificador de salida sin ninguna razón.

**La inicialización escalada de las proyecciones residuales**, `0.02 / sqrt(2 · n_layer)`, es la de
GPT-2 y se aplica después de `self.apply(layers.init_weights)`, sobrescribiendo lo que aquella puso.
El orden importa: al revés, la inicialización general borraría la escalada. Cada bloque suma dos
veces al residuo (atención y MLP), así que con ocho capas hay dieciséis sumas y la varianza del
residuo crecería con la profundidad si cada proyección de salida empezara con la misma escala que
las demás. Dividir por `sqrt(2 · n_layer)` compensa exactamente ese crecimiento. La regla `name.endswith("proj.weight")` alcanza tanto a `attn.proj` como a `mlp.proj`, que son precisamente las dos que escriben en el residuo.

## Contar parámetros y leer el relleno

    def num_params(self, non_embedding: bool = True) -> int:

## La guarda que impide el NaN

```python title="src/rukh/models/encoder.py"
    @staticmethod
    def _key_mask(attention_mask: Tensor | None) -> Tensor | None:
        """``(B, T)`` into the ``(B, 1, 1, T)`` boolean key mask SDPA expects."""
        if attention_mask is None:
            return None
        mask = attention_mask.bool()
        if mask.dim() != 2:
            raise ValueError(f"attention_mask must be (B, T), got {tuple(attention_mask.shape)}")
        if not _tracing() and not bool(mask.any(dim=-1).all()):
            # An entirely masked row would make softmax return NaN, so it is refused here rather
            # than debugged three layers down. The check reads a tensor, which is exactly what
            # `torch.export` cannot trace (a data-dependent guard), and skipping it under the
            # exporter is what keeps the encoder on the modern exporter instead of the
            # deprecated tracer: the exported graph is a pure function of its input either way.
            raise ValueError("every sequence needs at least one unmasked token")
        return mask[:, None, None, :]
```

<Src file="src/rukh/models/encoder.py" tag="p3" lines="112-127" />

Dieciséis líneas que hacen tres cosas, y la de en medio es la única que se ve.

La primera es el cambio de forma: `mask[:, None, None, :]` convierte `(B, T)` en `(B, 1, 1, T)`.
Esos dos ejes de tamaño uno son la cabeza de atención y la consulta, y al ser uno se **difunden**:
la misma máscara de claves vale para las seis cabezas y para las doscientas consultas de la
secuencia. Si en vez de difundir se materializara la matriz `(B, n_head, T, T)`, un lote de 96
secuencias de 200 tokens con seis cabezas serían veintitrés millones de booleanos por capa, y no
aportarían nada que no esté en los 19 200 de la versión difundida.

La segunda es la comprobación de forma. Un `attention_mask` de `(B, 1, T)` —que es lo que devuelve
más de una librería— se difundiría sin protestar contra el eje de las cabezas y enmascararía otra
cosa. Que falle con el mensaje `attention_mask must be (B, T)` cuesta dos líneas.

La tercera es la guarda del `NaN`. `mask.any(dim=-1)` dice, por secuencia, si le queda algún token
real; `.all()` exige que le quede a todas. Una fila sin ninguno haría que el softmax de la atención
recibiera una fila entera de `-inf` y devolviera `NaN`, que se propaga en silencio hasta el `loss` y
lo convierte en `nan` ocho capas después, cuando ya no hay forma de saber de dónde salió. Y aquí
está el `not _tracing()` de la función anterior: la comprobación **solo** se salta bajo una captura
de grafo.

<Callout kind="hoy" title="Dónde aparece una fila entera de relleno, que no es un caso imposible">
  Parece un caso de laboratorio y no lo es. Aparece en cuanto un lote se arma con un `collate` que
  rellena hasta un múltiplo fijo y alguna secuencia viene vacía porque un filtro la dejó sin tokens;
  o en la última tanda de un `DataLoader` con `drop_last=False` cuando el conjunto no es múltiplo
  del tamaño de lote y el resto se completa con ceros. El error de arriba convierte esos dos casos
  en un fallo de un segundo en vez de en una tirada de cuarenta minutos que acaba en `nan`.
</Callout>

## El `forward`, que es el del decoder con un argumento más

```python title="src/rukh/models/encoder.py"
    def forward(self, idx: Tensor, attention_mask: Tensor | None = None) -> Tensor:
        """Hidden states ``(B, T, d_model)``; ``attention_mask`` is ``True`` on real tokens."""
        seq = idx.shape[-1]
        if seq > self.cfg.seq:
            raise ValueError(f"sequence of {seq} tokens is longer than block {self.cfg.seq}")
        key_mask = self._key_mask(attention_mask)
        x = self.tokens(idx)
        cos = sin = None
        if self.positions is not None:
            steps = torch.arange(seq, device=idx.device)
            x = x + self.positions(steps)
        else:
            cos, sin = self.rope_cos, self.rope_sin
        x = self.drop(x)
        for block in self.blocks:
            x = block(x, cos, sin, key_mask)
        return self.ln_f(x)
```

<Src file="src/rukh/models/encoder.py" tag="p3" lines="129-145" />

La diferencia de fondo con el `forward` de `MoveDecoder` está en el tipo de retorno: **devuelve los
estados ocultos, no logits**. El decoder termina en `lm_head` porque solo tiene una pregunta; el
encoder devuelve `(B, T, d_model)` y deja que quien llame decida qué hacer con ese tensor —la cabeza
de jugada tapada, el pooling, las tres cabezas supervisadas, los embeddings que se exportan en la
lección 9—. Esa es la forma que tiene el código de decir «una posición admite muchas preguntas».

La comprobación de longitud está antes de tocar nada porque el fallo natural sería otro y peor: con
posiciones aprendidas, una secuencia más larga que la tabla daría un error de índice dentro de
`nn.Embedding`, que menciona un tamaño de tabla y no la longitud que se pasó. Con RoPE ni siquiera
fallaría: `cos[:t]` se quedaría corto en silencio.

La línea del bucle, `block(x, cos, sin, key_mask)`, es donde se junta todo lo de la lección 2: la
máscara viaja hasta `F.scaled_dot_product_attention`, y como no es `None`, `is_causal` se apaga solo.

## La cabeza de jugada tapada

```python title="src/rukh/models/encoder.py"
    def masked_lm(
        self, idx: Tensor, labels: Tensor | None = None, attention_mask: Tensor | None = None
    ) -> tuple[Tensor, Tensor | None]:
        """Masked-move logits ``(B, T, V)`` and, with ``labels``, the scalar loss.

        ``labels`` is ``MMM_IGNORE_INDEX`` wherever nothing was masked; see ``rukh.train.mmm``.
        """
        logits = self.mlm_head(self(idx, attention_mask))
        loss = None
        if labels is not None:
            loss = F.cross_entropy(
                logits.reshape(-1, logits.shape[-1]),
                labels.reshape(-1),
                ignore_index=MMM_IGNORE_INDEX,
            )
        return logits, loss
```

<Src file="src/rukh/models/encoder.py" tag="p3" lines="147-162" />

La <Term id="mlm">MLM</Term> en once líneas. El `reshape(-1, …)` aplana lote y tiempo en una sola
dimensión porque `F.cross_entropy` espera `(N, C)` y `(N,)`; no hay ninguna sutileza ahí más que no
equivocarse de orden.

Donde sí la hay es en `ignore_index`. La entropía cruzada de PyTorch, con `reduction="mean"` (el
valor por defecto), divide por **el número de posiciones que no están ignoradas**, no por `N`. Eso es
justo lo que hace falta: la pérdida es la media sobre las posiciones tapadas, así que un lote donde
el sorteo tapó pocas jugadas no produce un número artificialmente pequeño. El precio es un caso
degenerado que conviene conocer: si en un lote **ninguna** posición está tapada, el denominador es
cero y la pérdida sale `nan`. No es un error del código —es aritmética— y por eso el bucle de
entrenamiento de la lección 5 comprueba `torch.isfinite(loss)` antes de acumular.

Que la firma devuelva `(logits, loss)` y no solo la pérdida es lo que permite que el bucle de
validación calcule la exactitud top-1 con los mismos logits, sin una segunda pasada hacia delante.

## El pooling, y por qué el `clamp`

```python title="src/rukh/models/encoder.py"
    def pool(
        self,
        idx: Tensor,
        how: Literal["cls", "mean"] = "mean",
        attention_mask: Tensor | None = None,
    ) -> Tensor:
        """One vector per sequence, ``(B, d_model)``: the position's representation.

        ``cls`` takes position 0 (``<bos>`` for ``moves``, ``<cls>`` for ``squares``) and
        ``mean`` averages the real tokens only. Without an explicit ``attention_mask`` the
        padding is read off ``idx`` itself, so ``pool(idx, "mean")`` never averages ``<pad>``
        into the representation, which is the whole point of the operation.
        """
        if how not in ("cls", "mean"):
            raise ValueError(f"how must be 'cls' or 'mean', got {how!r}")
        mask = self.padding_mask(idx) if attention_mask is None else attention_mask.bool()
        hidden = self(idx, mask)
        if how == "cls":
            return hidden[:, 0]
        weights = mask.unsqueeze(-1).to(hidden.dtype)
        return (hidden * weights).sum(dim=1) / weights.sum(dim=1).clamp(min=1.0)
```

<Src file="src/rukh/models/encoder.py" tag="p3" lines="164-184" />

Aquí está la operación que convierte un encoder en un extractor de representaciones, y son dos
líneas de aritmética con tres decisiones dentro.

**La máscara se deriva de `idx` cuando no se la pasan.** Es lo que hace que el caso correcto sea el
caso por defecto: quien llama a `pool(idx)` sin pensar obtiene la media de los tokens reales, no la
media de los tokens reales y del relleno. El argumento explícito sigue estando para el llamante que
tiene una máscara distinta —por ejemplo el afinado, que reutiliza la que ya calculó.

**La media se escribe como suma ponderada partida por el peso total**, no como `hidden[mask].mean()`.
La razón es la forma: `hidden[mask]` aplana el lote entero en una lista de vectores y pierde a qué
secuencia pertenece cada uno, así que habría que reagrupar. Multiplicar por una máscara de ceros y
unos y sumar por el eje del tiempo hace lo mismo por lote, sin ramas, y es lo que un kernel de GPU
sabe hacer rápido.

**`clamp(min=1.0)` en el denominador.** El caso que evita —una secuencia entera de relleno— ya está
prohibido arriba por `_key_mask`, así que es un cinturón además del tirante, y aun así merece la pena:
`pool` se puede llamar con una máscara explícita distinta de la que `_key_mask` validó, y una
división por cero no da una excepción en PyTorch, da `inf` o `nan`. Un `clamp` de un carácter frente
a un vector de `nan` que se propaga a través de tres cabezas lineales.

El `if how not in (…)` de arriba parece burocracia y no lo es: `how` viene de un YAML
(`pooling: mean` en las configuraciones de la lección 6), y un `pooling: media` escrito por alguien
que trabaja en español caería silenciosamente en la rama de la media si la comprobación fuera
`if how == "cls": … else: media`.

START = "rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq -"


def toy_model(seed: int = 0, **overrides: object) -> PositionEncoder:
    """A deterministic two-layer encoder in eval mode."""
    torch.manual_seed(seed)
    return PositionEncoder(TOY.model_copy(update=overrides)).eval()


def toy_batch(batch: int = 2, seq: int = 8, seed: int = 1) -> torch.Tensor:
    generator = torch.Generator().manual_seed(seed)
    return torch.randint(1, TOY.vocab_size, (batch, seq), generator=generator)

def test_a_later_token_does_change_the_earlier_outputs(pos: str) -> None:
    """The inverse of the decoder's causality test: this model is bidirectional on purpose."""
    model = toy_model(pos=pos)
    idx = toy_batch(seq=12)
    cut = 5
    changed = idx.clone()
    changed[:, cut + 1 :] = (changed[:, cut + 1 :] + 7) % (TOY.vocab_size - 1) + 1
    assert not torch.equal(idx, changed)
    with torch.no_grad():
        base, other = model(idx), model(changed)
    assert not torch.allclose(base[:, : cut + 1], other[:, : cut + 1], atol=1e-5)

Este es **el** test del módulo. En M2 el mismo experimento terminaba en `assert torch.allclose(…)`:
cambiar un token futuro no podía mover ni un decimal de un logit pasado, y si lo movía es que la
máscara causal se había roto. Aquí el `assert` lleva un `not` delante, y el módulo entero está en esa
negación.

Dos cosas del montaje merecen leerse. `(x + 7) % (vocab_size - 1) + 1` cambia todos los tokens de la
cola **y se mantiene dentro de `[1, vocab_size - 1]`**, es decir, nunca produce un 0: si produjera
relleno, el resultado podría explicarse por el relleno y no por la bidireccionalidad. Y el
`assert not torch.equal(idx, changed)` de antes comprueba que la transformación cambió algo de
verdad; sin él, un cambio que por aritmética dejara el tensor igual haría que el test pasara por el
motivo equivocado, que es el modo de fallo clásico de un test cuya aserción es una negación.

El `parametrize` sobre `pos` está porque la bidireccionalidad no debe depender de cómo se codifique
la posición. Con RoPE la posición entra dentro de la atención y no como una suma al principio, así
que es un camino de código distinto y merece su comprobación.

def test_padding_does_not_leak_into_the_real_tokens() -> None:
    model = toy_model()
    short = toy_batch(seq=6, seed=2)
    padded = torch.cat([short, torch.zeros((2, 4), dtype=torch.long)], dim=1)
    with torch.no_grad():
        plain = model(short, model.padding_mask(short))
        with_padding = model(padded, model.padding_mask(padded))
    assert torch.allclose(plain, with_padding[:, :6], atol=1e-5)
    # Without the mask the padding is just another token and does change the answer.
    with torch.no_grad():
        unmasked = model(padded)
    assert not torch.allclose(plain, unmasked[:, :6], atol=1e-5)

El primero es el test que de verdad prueba que la máscara sirve, y lo prueba **por los dos lados**.
La primera mitad dice que con máscara la respuesta no depende de cuánto relleno viaje con la
secuencia. La segunda dice que sin máscara **sí** depende, y esa mitad es la que impide que el test
pase por casualidad: si la máscara no hiciera nada, las dos comparaciones darían el mismo resultado y
la segunda aserción fallaría.

Es un patrón que vale la pena copiar: **un test de un mecanismo comprueba que sin el mecanismo el
resultado cambia**. Si no, lo único que has demostrado es que el modelo no mira la entrada.

Las dos últimas aserciones son el contrato de `MMM_IGNORE_INDEX` convertido en código, y hay que
leerlas juntas.

`torch.isnan(…)` con todas las etiquetas ignoradas **documenta el `nan` en vez de esconderlo**. Ya
sabes de dónde viene: `reduction="mean"` divide por el número de posiciones puntuadas y ahí son
cero. Escribirlo como aserción tiene dos efectos: deja claro que es aritmética y no un fallo, y
convierte en una rotura de test cualquier cambio futuro que decida devolver `0.0` en ese caso —que
sería lo peor de los dos mundos, porque un cero se suma a la media de la época sin que nadie lo note.

La de `pad_label` es la que justifica la constante entera: una etiqueta de valor 0 produce una
pérdida **finita**, o sea que se puntúa. En el decoder de M2, con `ignore_index=0`, esa misma
etiqueta habría desaparecido de la pérdida sin decir nada.

def test_a_few_steps_of_gradient_descent_reduce_the_loss() -> None:
    torch.manual_seed(5)
    model = PositionEncoder(TOY)
    idx = toy_batch(seq=8, seed=6)
    labels = torch.full_like(idx, MMM_IGNORE_INDEX)
    labels[:, ::2] = idx[:, ::2]
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-2)
    losses = []
    for _ in range(10):
        _, loss = model.masked_lm(idx, labels)
        assert loss is not None
        losses.append(loss.detach().item())
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
    assert losses[-1] < losses[0]

El primero recorre las validaciones de la lección 2, y el `n_layers=3` del principio —con la ese— es
el test de `extra="forbid"`: una errata en un YAML tiene que ser un error y no un valor por defecto

El último es el más barato y el que más veces salva. Diez pasos de `AdamW` sobre un lote fijo tienen
que bajar la pérdida, y si no bajan, algo estructural está roto: un gradiente que no llega —una
`detach` de más, un `no_grad` mal puesto— o una máscara que impide aprender. No comprueba que el
modelo sea bueno; comprueba que **puede aprender**, que es lo que hace falta antes de gastar
dieciséis minutos de GPU.

## Qué has aprendido

El modelo entero: 184 líneas de las que la mitad son el decoder de M2 con otro nombre, y la otra
mitad son tres cosas que el decoder no necesitaba —una máscara de claves para el relleno, una
etiqueta que significa «no puntúes esto» y que no se puede confundir con un id, y una reducción de
la secuencia a un vector que no promedia lo que no existe.

**Cómo se mide**: `uv run pytest tests/unit/test_encoder.py -q` pasa los once tests (trece casos,
contando el `parametrize`), y entre ellos el que en M2 tenía que fallar. `PositionEncoder(EncoderConfig()).num_params(False)` imprime 15 052 800.

Lo siguiente son las tres cabezas que leen ese vector y el traductor de FEN a 69 tokens, que es la
segunda representación de entrada del experimento del módulo.

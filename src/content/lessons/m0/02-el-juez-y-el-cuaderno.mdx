## Qué vas a construir

Las dos piezas sin las que ningún número de este curso significaría nada: el <Term id="oraculo">oráculo</Term>
que dice si una jugada fue legal y cómo de buena, y el cuaderno
donde queda anotado con qué código y qué configuración salió cada medida. En código son cuatro
ficheros y 402 líneas, y al terminar `rukh info` funciona y `rukh engine check` juega una partida
contra Stockfish con la fuerza limitada.

El orden importa: primero se decide **quién juzga** y **dónde se anota**, y solo después se entrena
algo. Al revés, acabas con un modelo y ninguna forma de decir si es mejor que el anterior.

## Traer el motor: `scripts/get_stockfish.py`

Stockfish no es una dependencia de Python: es un ejecutable. El script lo descarga de las
_releases_ oficiales de GitHub y lo deja en `tools/stockfish/`, que está en el `.gitignore`.

```python title="scripts/get_stockfish.py"
"""Download Stockfish 19 into ``tools/stockfish/`` (gitignored). Idempotent.

Usage: ``uv run python scripts/get_stockfish.py [--force]``

Windows gets ``stockfish-windows-x86-64-universal.zip`` (sf_19 ships no separate avx2 build; the
universal binary picks the best code path at runtime). Linux gets
``stockfish-ubuntu-x86-64-avx2.tar``. The executable ends up as ``tools/stockfish/stockfish.exe``
or ``tools/stockfish/stockfish``.
"""

from __future__ import annotations

import argparse
import io
import os
import platform
import shutil
import stat
import sys
import tarfile
import urllib.request
import zipfile
from pathlib import Path

RELEASE = "sf_19"
BASE_URL = f"https://github.com/official-stockfish/Stockfish/releases/download/{RELEASE}"
ASSETS = {
    "Windows": "stockfish-windows-x86-64-universal.zip",
    "Linux": "stockfish-ubuntu-x86-64-avx2.tar",
}
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="1-30" />

Todo con la biblioteca estándar: `urllib.request` en vez de `requests`, `zipfile` y `tarfile` en vez
de una herramienta externa. Es un script que se ejecuta una vez por máquina y no merece una
dependencia.

La versión está clavada en `RELEASE = "sf_19"`, no es "la última". Un juez que cambia de versión
entre dos medidas convierte una comparación en un misterio: Stockfish gana decenas de Elo por
versión, así que la misma escalera de `UCI_Elo` medida con sf_19 y con sf_20 no da lo mismo.

```python title="scripts/get_stockfish.py"


def repo_root() -> Path:
    home = os.environ.get("RUKH_HOME")
    return Path(home).expanduser().resolve() if home else Path(__file__).resolve().parents[1]


def target_path(dest: Path) -> Path:

def download(url: str) -> bytes:

    request = urllib.request.Request(url, headers={"User-Agent": "rukh/get_stockfish"})
    with urllib.request.urlopen(request, timeout=120) as response:
        return response.read()
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="31-46" />

`repo_root()` repite la lógica de `paths.root()` en vez de importarla, y es a propósito: este script
se ejecuta con `uv run python scripts/...`, que no necesita que el paquete `rukh` esté instalado. Un
script cuyo único trabajo es preparar el entorno no debería depender del entorno que prepara.

El `User-Agent` explícito no es cortesía: la API de GitHub rechaza peticiones sin él.

```python title="scripts/get_stockfish.py"


def is_executable_member(name: str) -> bool:
    """True for the engine binary inside the release archive, never for a ``src/`` file.

    Windows archives ship ``stockfish-<variant>.exe``; the others ship a plain binary with no
    extension. Both archives also contain the sources under ``src/``, which must be skipped.
    """
    path = Path(name)
    if "src" in path.parts or not path.name.startswith("stockfish"):
        return False
    if platform.system() == "Windows":
        return path.suffix == ".exe"
    return path.suffix == ""
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="47-60" />

Esta función existe porque el archivo de Stockfish trae **el ejecutable y las fuentes**. Dentro de
`src/` hay un fichero llamado `stockfish.cpp` cuyo nombre empieza por `stockfish`, así que un filtro
por prefijo a secas se lo lleva. En Linux, además, el ejecutable no tiene extensión y `stockfish.cpp`
sí: de ahí las dos ramas por plataforma.

Es el tipo de detalle que no se descubre leyendo: se descubre cuando `rukh engine check` falla con
un error de UCI porque intentó lanzar un fichero de C++ como si fuera un motor.

```python title="scripts/get_stockfish.py"


def extract_executable(asset: str, payload: bytes, target: Path) -> None:
    """Pull the single ``stockfish*`` executable out of the archive into ``target``."""
    target.parent.mkdir(parents=True, exist_ok=True)
    if asset.endswith(".zip"):
        with zipfile.ZipFile(io.BytesIO(payload)) as archive:
            names = [
                n for n in archive.namelist() if not n.endswith("/") and is_executable_member(n)
            ]
            if not names:
                raise SystemExit(f"no stockfish executable inside {asset}")
            with archive.open(names[0]) as src, target.open("wb") as dst:
                shutil.copyfileobj(src, dst)
    else:
        with tarfile.open(fileobj=io.BytesIO(payload), mode="r:*") as archive:
            members = [
                m for m in archive.getmembers() if m.isfile() and is_executable_member(m.name)
            ]
            if not members:
                raise SystemExit(f"no stockfish executable inside {asset}")
            src = archive.extractfile(members[0])
            if src is None:
                raise SystemExit(f"cannot read {members[0].name} from {asset}")
            with src, target.open("wb") as dst:
                shutil.copyfileobj(src, dst)
    if platform.system() != "Windows":
        target.chmod(target.stat().st_mode | stat.S_IXUSR | stat.S_IXGRP | stat.S_IXOTH)
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="61-88" />

El archivo se descomprime **en memoria** (`io.BytesIO(payload)`) y se copia solo el miembro que
interesa: nada de extraer 60 MB de fuentes al disco para borrarlas después. Y en Linux hay que poner
el bit de ejecución a mano, porque ni `zipfile` ni `tarfile` conservan permisos cuando se copia el
contenido de un miembro a un fichero nuevo. Sin esa última línea, `popen_uci` falla con un
`PermissionError` que no dice nada.

```python title="scripts/get_stockfish.py"
def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    parser.add_argument("--force", action="store_true", help="Re-download even if present.")
    parser.add_argument(
        "--dest",
        type=Path,
        default=repo_root() / "tools" / "stockfish",

    args = parser.parse_args(argv)

    system = platform.system()
    asset = ASSETS.get(system)
    if asset is None:
        print(f"unsupported platform {system!r}; download Stockfish manually", file=sys.stderr)
        return 2

    target = target_path(args.dest)
    if target.is_file() and not args.force:
        print(f"already present: {target}")
        return 0

    payload = download(f"{BASE_URL}/{asset}")
    print(f"received {len(payload) / 1e6:.1f} MB")
    extract_executable(asset, payload, target)
    print(f"installed {target}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

<Src file="src/rukh/engine.py" tag="p0" lines="1-24" />

Dos excepciones y no una, y la jerarquía está elegida: `EngineNotFound` hereda de `RuntimeError`
(falta algo en la máquina, se arregla instalando) y `EngineError` de `ValueError` (lo que hay no vale,
se arregla cambiando la configuración). Quien las captura las trata distinto, y la CLI las distingue
en el mensaje.

`MOVE_TIME_SECONDS = 0.05` es una constante del módulo porque va a aparecer en la evaluación de M2:
el tiempo por jugada es parte de la fuerza del motor, y un número mágico repetido en dos sitios es
una forma silenciosa de medir con dos jueces distintos.

```python title="src/rukh/engine.py"


def find_stockfish() -> Path | None:
    """Locate Stockfish: ``RUKH_STOCKFISH``, then ``tools/stockfish/``, then ``PATH``.

    When ``RUKH_STOCKFISH`` is set it wins outright and must point at an existing file;
    otherwise ``EngineNotFound`` is raised instead of silently falling through.
    """
    env = os.environ.get("RUKH_STOCKFISH")
    if env:
        candidate = Path(env)
        if not candidate.is_file():
            raise EngineNotFound(f"RUKH_STOCKFISH={env} is not a file")
        return candidate
    tools = paths.tools_dir() / "stockfish"
    for pattern in ("stockfish*.exe", "stockfish"):
        for candidate in sorted(tools.glob(pattern)):
            if candidate.is_file():
                return candidate
    which = shutil.which("stockfish")
    return Path(which) if which else None
```

<Src file="src/rukh/engine.py" tag="p0" lines="40-60" />

El orden de búsqueda es parte del contrato del proyecto, no una comodidad: **la variable de entorno
gana, después el binario del repositorio, y solo al final el del sistema**. Un repositorio que trae
su propio motor tiene que ganarle al que haya instalado la máquina, o dos ordenadores miden con dos
jueces distintos y las tablas dejan de ser comparables.

El detalle que parece inconsistente y no lo es: si `RUKH_STOCKFISH` está puesta y **no** apunta a un
fichero, la función **lanza** en vez de seguir buscando. Devolver `None` sería tratar una errata en
una variable de entorno como "no hay motor", y el usuario acabaría midiendo con el Stockfish del
sistema creyendo que usa el que él eligió. Que una ruta explícita y equivocada sea un error, y una
ausencia de motor no lo sea, es la distinción correcta.

`sorted(tools.glob(pattern))` ordena porque `glob` no garantiza orden y en una carpeta con
`stockfish-avx2.exe` y `stockfish.exe` querrías siempre el mismo.

```python title="src/rukh/engine.py"


def engine_check(elo: int = 1400, plies: int = 40, seed: int = 0) -> EngineCheckResult:
    """Open Stockfish, limit it to ``elo`` and play ``plies`` half-moves against a random mover.

    Stockfish plays White, the seeded random player plays Black. Raises ``EngineNotFound`` when
    no binary is available, ``EngineError`` when the binary does not expose ``UCI_Elo`` and
    ``ValueError`` when ``elo`` is outside the engine's range.
    """
    path = find_stockfish()
    if path is None:
        raise EngineNotFound(
            "Stockfish not found: run `uv run python scripts/get_stockfish.py` "
            "or set RUKH_STOCKFISH"
        )

    rng = random.Random(seed)
    board = chess.Board()
    nodes_hint: int | None = None
    plies_played = 0

    with chess.engine.SimpleEngine.popen_uci(str(path)) as engine:
        name = str(engine.id.get("name", "unknown"))
        try:
            option = engine.options["UCI_Elo"]
            uci_elo_min, uci_elo_max = int(option.min), int(option.max)
        except (
            KeyError,
            TypeError,
            chess.engine.EngineError,
            chess.engine.EngineTerminatedError,
        ) as exc:
            raise EngineError(f"{path} ({name}) does not expose UCI_Elo; is it Stockfish?") from exc
        if not uci_elo_min <= elo <= uci_elo_max:
            raise ValueError(f"UCI_Elo {elo} outside [{uci_elo_min}, {uci_elo_max}]")
        engine.configure({"UCI_LimitStrength": True, "UCI_Elo": elo})
```

<Src file="src/rukh/engine.py" tag="p0" lines="61-96" />

Aquí están los dos números que sostienen toda la evaluación del curso, y la línea que más
entrenamientos ha estropeado en la historia de este tipo de proyectos.

**Los dos números.** `uci_elo_min` y `uci_elo_max` no se escriben a mano: se **leen** de la tabla de
opciones que el propio motor declara al arrancar, por el protocolo <Term id="uci">UCI</Term>. En
sf_19 salen 1320 y 3190. Ese es el rango en el que se le puede pedir a Stockfish que juegue peor de
lo que sabe, y con él se estima el <Term id="elo-estimado">Elo</Term> de cada modelo en M2. La
diferencia entre leerlo y suponerlo es la diferencia entre una escalera calibrada y una tabla que
hay que rehacer: M2 cuenta lo que costó descubrir que el suelo son 1320 y no 1000.

**La línea.** `engine.configure({"UCI_LimitStrength": True, "UCI_Elo": elo})` necesita **las dos**
opciones. `UCI_LimitStrength` es el interruptor que enciende el debilitamiento; `UCI_Elo` a solas se
ignora mientras el interruptor esté apagado. Poner el Elo y olvidar el interruptor es la forma
clásica de medir un motor a plena fuerza y publicar el resultado como un rival de 1500: tu modelo
pierde 20-0 y la conclusión que sacas es sobre el modelo.

<Callout kind="roto" title="Cuatro excepciones para una consulta">
  Ese `except (KeyError, TypeError, chess.engine.EngineError, chess.engine.EngineTerminatedError)`
  no es paranoia. Preguntar por `UCI_Elo` a un ejecutable que no es Stockfish falla de cuatro
  maneras según qué sea: un motor UCI de verdad sin esa opción da `KeyError`; uno que la declara sin
  rango da `TypeError` al convertir `None` a `int`; un binario que habla UCI mal da `EngineError`; y
  un ejecutable que no habla UCI en absoluto se muere y da `EngineTerminatedError`. Las cuatro
  significan lo mismo para quien llama —"esto no es Stockfish"— y las cuatro deben decírselo con esa
  frase, no con una traza.
</Callout>

La partida de prueba: Stockfish con las blancas contra un jugador aleatorio con semilla. No mide
nada —el rival es aleatorio— pero recorre el camino completo: abrir el motor, configurarlo, pedirle
jugadas, aplicarlas, detectar el final. Si algo de eso está roto, se sabe aquí y no a mitad de una
evaluación de 160 partidas.

`board.is_game_over(claim_draw=True)` y `board.result(claim_draw=True)` con el mismo argumento en
los dos sitios. `claim_draw` incluye las tablas que hay que **reclamar** (triple repetición, regla
de las cincuenta jugadas) además de las automáticas. Si el bucle terminara con `claim_draw=True` y
el resultado se leyera con el valor por defecto, una partida acabada por repetición saldría como
`*`, sin resultado.

`rng = random.Random(seed)` es un generador propio, no `random.seed()` global: dos llamadas con la
misma semilla dan la misma partida, y ninguna de las dos altera el estado aleatorio del resto del
proceso.

Las opciones cuando no hay motor, de más barata a más cara:

- **Reglas y esquemas.** ¿El JSON valida? ¿La cita existe en el documento? Detecta la forma rota,
  no el contenido malo. Es el equivalente de la máscara de legalidad de este proyecto.
- **Tests.** En código son un oráculo casi tan bueno como un motor, con la trampa de que solo ven
  lo que cubren.
- **Un LLM como juez.** Barato y escalable, y con sesgos que hay que medir: prefiere respuestas
  largas, prefiere su propio estilo, y si le enseñas dos respuestas se deja llevar por el orden.
  Sirve **si** lo calibras contra un puñado de juicios humanos y publicas ese acuerdo.
- **Personas.** Lo más caro, lo más lento y lo único que mide de verdad lo que te importa. Por eso
  se usa en pequeño: para calibrar los otros tres.

La regla práctica: **no elijas el oráculo más barato, elige el más barato que se parezca a la
decisión real**, y mide en qué se diferencian. Un proyecto que solo valida la forma acabará
optimizando la forma.

</Transfer>

<Callout kind="entrevista" title="¿Por qué no usas Stockfish para jugar y ya está?">

  partidas. En la práctica, además, un modelo pequeño corre en el navegador y un motor completo no
  cabe en una demo estática.

## `tracking.py`: el cuaderno de laboratorio

<Term id="mlflow">MLflow</Term> guarda cada ejecución con su configuración, sus métricas por paso y
sus artefactos. Aquí se usa en su modo más simple: una base SQLite en `mlruns/mlflow.db`, sin
servidor.

```python title="src/rukh/tracking.py"
"""Local MLflow tracking: SQLite store under ``mlruns/`` and a run helper."""

from __future__ import annotations

import subprocess
import sys
from collections.abc import Iterator, Mapping
from contextlib import contextmanager
from typing import Any

from rukh import __version__, paths

EXPERIMENT = "rukh"


def tracking_uri(create: bool = True) -> str:
    """SQLite tracking URI ``sqlite:///<MLRUNS_DIR>/mlflow.db``; creates the directory if asked."""
    mlruns = paths.mlruns_dir()
    if create:
        mlruns.mkdir(parents=True, exist_ok=True)
    return f"sqlite:///{(mlruns / 'mlflow.db').as_posix()}"
```

Un solo experimento (`EXPERIMENT = "rukh"`) para todo el proyecto, y los modelos y etapas se

```python title="src/rukh/tracking.py"
def flatten(config: Mapping[str, Any], prefix: str = "") -> dict[str, str]:
    """Flatten nested mappings into ``a.b=value`` string params (lists become their repr)."""
    flat: dict[str, str] = {}
    for key, value in config.items():
        name = f"{prefix}{key}"
        if isinstance(value, Mapping):
            flat.update(flatten(value, prefix=f"{name}."))
        else:
            flat[name] = str(value)
    return flat
```

MLflow solo acepta parámetros planos: clave y cadena. Las configuraciones del proyecto son YAML con

```python title="src/rukh/tracking.py"


def git_sha() -> str | None:
    """Full SHA of the source tree (``paths.package_root()``), or None when it is not a git repo.

    The source tree is used on purpose: ``RUKH_HOME`` may point at a data directory that is
    not a checkout, and the tag must identify the code that produced the run.
    """
    try:
        out = subprocess.run(
            ["git", "rev-parse", "HEAD"],
            cwd=paths.package_root(),
            capture_output=True,
            text=True,
            check=True,
            timeout=10,
        )
    except (OSError, subprocess.SubprocessError):
        return None
    sha = out.stdout.strip()
    return sha or None
```

<Src file="src/rukh/tracking.py" tag="p0" lines="34-54" />

Aquí se cobra la separación de las dos raíces de `paths.py`. El SHA se pide en `package_root()` —el
árbol de fuentes— y no en `root()`, porque `RUKH_HOME` puede apuntar a un disco de datos que no es un
repositorio. El tag tiene que identificar **el código que produjo la ejecución**.

Devuelve `None` en vez de fallar cuando no hay git, y captura `OSError` (git no instalado) y
`SubprocessError` (el `check=True` cuando el directorio no es un repositorio, y el `timeout`). Que
una ejecución no tenga SHA es información; que no se pueda entrenar sin git instalado sería una
decisión absurda.

```python title="src/rukh/tracking.py"
        if params:

        yield run
```

```python title="src/rukh/env.py"


def _torch_info() -> tuple[str | None, bool, str | None]:
    """Return (torch version, cuda available, gpu name); all empty if torch is missing."""
    try:
        import torch
    except ImportError:
        return None, False, None
    cuda = bool(torch.cuda.is_available())
    gpu = torch.cuda.get_device_name(0) if cuda else None
    return torch.__version__, cuda, gpu
```

del usuario, y tratarla como "no hay motor" acabaría midiendo con el Stockfish del sistema
mientras tú crees que usas otro.

```python title="tests/unit/test_tracking.py"
def test_tracking_uri_points_to_sqlite_under_mlruns(rukh_home: Path) -> None:
    uri = tracking_uri(create=False)
    assert uri == f"sqlite:///{(rukh_home / 'mlruns' / 'mlflow.db').as_posix()}"
    assert not (rukh_home / "mlruns").exists()
    tracking_uri()
    assert (rukh_home / "mlruns").is_dir()


def test_flatten_nested_dict() -> None:
    assert flatten({"a": {"b": 1, "c": {"d": "x"}}, "e": [1, 2]}) == {
        "a.b": "1",
        "a.c.d": "x",
        "e": "[1, 2]",
    }


def test_start_run_logs_flattened_params_and_tags(rukh_home: Path) -> None:
    with start_run("t", {"a": {"b": 1}}, tags={"purpose": "test"}) as run:
        run_id = run.info.run_id
    assert (rukh_home / "mlruns" / "mlflow.db").is_file()

    mlflow.set_tracking_uri(tracking_uri())
    runs = mlflow.search_runs(experiment_names=["rukh"], output_format="list")
    found = [r for r in runs if r.info.run_id == run_id]
    assert len(found) == 1
    logged = found[0]
    assert logged.info.run_name == "t"
    assert logged.data.params["a.b"] == "1"
    assert logged.data.tags["rukh_version"] == __version__
    assert logged.data.tags["purpose"] == "test"
    assert logged.info.status == "FINISHED"
```

El primero comprueba las dos mitades del parámetro `create`: con `create=False` la URI se construye y
el directorio **no existe**; con la llamada por defecto, existe. Es la propiedad que hace que
`rukh info` sea inocuo.

El tercero es el test más caro del fichero y el que más cubre: abre una ejecución de verdad contra una
base SQLite de verdad (en el directorio temporal de la fixture), y después **la lee con MLflow** para
comprobar que los parámetros llegaron aplanados, que los dos tags automáticos están y que la
ejecución quedó en `FINISHED`. Ese último `assert` es el que detecta que el gestor de contexto no cierra
bien: una ejecución que se queda en `RUNNING` para siempre no falla nada, solo ensucia el cuaderno.

```python title="tests/unit/test_tracking.py"
def test_git_sha_is_the_source_tree_sha_even_with_rukh_home_elsewhere(
    rukh_home: Path, repo_root: Path
) -> None:
    if shutil.which("git") is None:
        pytest.skip("git is not installed")
    if not (repo_root / ".git").exists():
        pytest.skip("source tree is not a git checkout")
    assert not (rukh_home / ".git").exists()
    sha = git_sha()
    assert sha is not None and re.fullmatch(r"[0-9a-f]{40}", sha), sha
```

<Exercise n="02" title="Registra tu primera ejecución">
  Desde `uv run python`, abre una ejecución a mano y míralo en la interfaz:

```python
from rukh.tracking import start_run

with start_run("hola", {"modelo": {"capas": 4}, "lr": 3e-4}) as run:
    print(run.info.run_id)
```

Después `uv run rukh mlflow ui` y busca la ejecución. ¿Qué parámetros tiene y con qué nombres? ¿Qué
tags? ¿Y qué pasa si el bloque `with` lanza una excepción a mitad?

<Solution>
  Los parámetros son `modelo.capas = "4"` y `lr = "0.0003"`: aplanados con punto y convertidos a
  cadena, que es lo único que MLflow acepta. Los tags incluyen `rukh_version` (`0.0.1`) y
  `git_sha` con el commit de tu checkout.

Si el bloque lanza, `mlflow.start_run` marca la ejecución como `FAILED` al salir del gestor de
contexto y la excepción se propaga. Eso es justo lo que se quiere: una ejecución interrumpida se
distingue de una terminada en la interfaz, y por eso el test comprueba `status == "FINISHED"` en el
camino bueno.

</Solution>

## Qué has aprendido

El proyecto ya tiene juez y cuaderno. Stockfish está en disco, verificado por UCI, y el rango en el
que se le puede pedir que juegue peor se **lee** del motor y no se supone: 1320-3190. Cada ejecución
que se abra a partir de ahora deja su configuración completa y el SHA del código que la produjo en
una base local, y las model cards de M6 se generarán desde ahí.

**Cómo se mide**: `uv run rukh info` muestra `cuda: True` y una ruta en `stockfish`;
`uv run rukh engine check` devuelve `uci_elo_min 1320` y `uci_elo_max 3190`;
`uv run pytest -m unit -q` pasa (los dos tests con marca `engine` quedan fuera del filtro) y
`uv run pytest -m engine -q` pasa con el binario instalado.

Lo siguiente son los datos: seis mil millones de partidas de las que hay que traerse unos pocos
gigabytes, con cada filtro justificado y un manifiesto que permita comprobar después qué entró de
verdad.

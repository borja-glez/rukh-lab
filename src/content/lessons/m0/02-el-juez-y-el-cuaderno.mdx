## Qué vas a construir

Las dos piezas sin las que ningún número de este curso significaría nada: el <Term id="oraculo">oráculo</Term>
que dice si una jugada fue legal y cómo de buena, y el cuaderno donde queda anotado con qué código
y qué configuración salió cada medida. Son cuatro ficheros; al terminar, `rukh info` funciona y
`rukh engine check` juega una partida contra Stockfish con la fuerza limitada.

Van antes que cualquier entrenamiento porque, sin ellas, acabas con un modelo y ninguna forma de
decir si es mejor que el anterior.

## Traer el motor: `scripts/get_stockfish.py`

Stockfish no es una dependencia de Python: es un ejecutable. El script lo descarga de las
_releases_ oficiales de GitHub y lo deja en `tools/stockfish/`, que está en el `.gitignore`.

```python title="scripts/get_stockfish.py"
"""Download Stockfish 19 into ``tools/stockfish/`` (gitignored). Idempotent.

Usage: ``uv run python scripts/get_stockfish.py [--force]``

Windows gets ``stockfish-windows-x86-64-universal.zip`` (sf_19 ships no separate avx2 build; the
universal binary picks the best code path at runtime). Linux gets
``stockfish-ubuntu-x86-64-avx2.tar``. The executable ends up as ``tools/stockfish/stockfish.exe``
or ``tools/stockfish/stockfish``.
"""

from __future__ import annotations

import argparse
import io
import os
import platform
import shutil
import stat
import sys
import tarfile
import urllib.request
import zipfile
from pathlib import Path

RELEASE = "sf_19"
BASE_URL = f"https://github.com/official-stockfish/Stockfish/releases/download/{RELEASE}"
ASSETS = {
    "Windows": "stockfish-windows-x86-64-universal.zip",
    "Linux": "stockfish-ubuntu-x86-64-avx2.tar",
}
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="1-30" />

Todo con la biblioteca estándar (`urllib.request`, `zipfile`, `tarfile`): un script que se ejecuta
una vez por máquina no merece una dependencia.

La versión está clavada en `RELEASE = "sf_19"`. Stockfish gana decenas de Elo por versión, así que
la misma escalera de `UCI_Elo` medida con sf_19 y con sf_20 no da lo mismo: un juez que cambia de
versión entre dos medidas convierte la comparación en un misterio.


`repo_root()` repite la lógica de `paths.root()` en vez de importarla: un script que prepara el
entorno no debería depender del paquete que ese entorno instala. El `User-Agent` explícito está
porque GitHub rechaza peticiones sin él.

```python title="scripts/get_stockfish.py"


def is_executable_member(name: str) -> bool:
    """True for the engine binary inside the release archive, never for a ``src/`` file.

    Windows archives ship ``stockfish-<variant>.exe``; the others ship a plain binary with no
    extension. Both archives also contain the sources under ``src/``, which must be skipped.
    """
    path = Path(name)
    if "src" in path.parts or not path.name.startswith("stockfish"):
        return False
    if platform.system() == "Windows":
        return path.suffix == ".exe"
    return path.suffix == ""
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="47-60" />

El archivo de Stockfish trae el ejecutable y las fuentes, y dentro de `src/` hay un `stockfish.cpp`
que un filtro por prefijo a secas se lleva. En Linux, además, el ejecutable no tiene extensión y
`stockfish.cpp` sí: de ahí las dos ramas. Sin esta función, `rukh engine check` falla con un error de
UCI porque intenta lanzar un fichero de C++ como si fuera un motor.

```python title="scripts/get_stockfish.py"


def extract_executable(asset: str, payload: bytes, target: Path) -> None:
    """Pull the single ``stockfish*`` executable out of the archive into ``target``."""
    target.parent.mkdir(parents=True, exist_ok=True)
    if asset.endswith(".zip"):
        with zipfile.ZipFile(io.BytesIO(payload)) as archive:
            names = [
                n for n in archive.namelist() if not n.endswith("/") and is_executable_member(n)
            ]
            if not names:
                raise SystemExit(f"no stockfish executable inside {asset}")
            with archive.open(names[0]) as src, target.open("wb") as dst:
                shutil.copyfileobj(src, dst)
    else:
        with tarfile.open(fileobj=io.BytesIO(payload), mode="r:*") as archive:
            members = [
                m for m in archive.getmembers() if m.isfile() and is_executable_member(m.name)
            ]
            if not members:
                raise SystemExit(f"no stockfish executable inside {asset}")
            src = archive.extractfile(members[0])
            if src is None:
                raise SystemExit(f"cannot read {members[0].name} from {asset}")
            with src, target.open("wb") as dst:
                shutil.copyfileobj(src, dst)
    if platform.system() != "Windows":
        target.chmod(target.stat().st_mode | stat.S_IXUSR | stat.S_IXGRP | stat.S_IXOTH)
```

<Src file="scripts/get_stockfish.py" tag="p0" lines="61-88" />

El archivo se descomprime en memoria (`io.BytesIO(payload)`) y se copia solo el miembro que
interesa. En Linux hay que poner el bit de ejecución a mano, porque ni `zipfile` ni `tarfile`
conservan permisos al copiar un miembro a un fichero nuevo; sin esa última línea, `popen_uci` falla
con un `PermissionError` que no dice nada.

```python title="scripts/get_stockfish.py"
def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    parser.add_argument("--force", action="store_true", help="Re-download even if present.")
    parser.add_argument(
        "--dest",
        type=Path,
        default=repo_root() / "tools" / "stockfish",
        help="Destination directory (default: <repo>/tools/stockfish).",
    )
    args = parser.parse_args(argv)

    system = platform.system()
    asset = ASSETS.get(system)
    if asset is None:
        print(f"unsupported platform {system!r}; download Stockfish manually", file=sys.stderr)
        return 2

    target = target_path(args.dest)
    if target.is_file() and not args.force:
        print(f"already present: {target}")
        return 0

    payload = download(f"{BASE_URL}/{asset}")
    print(f"received {len(payload) / 1e6:.1f} MB")
    extract_executable(asset, payload, target)
    print(f"installed {target}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## `engine.py`: encontrar el motor y comprobar que es Stockfish

```python title="src/rukh/engine.py"

from __future__ import annotations

import os
import random
import shutil
from pathlib import Path

import chess
import chess.engine
from pydantic import BaseModel, ConfigDict

from rukh import paths

MOVE_TIME_SECONDS = 0.05


class EngineNotFound(RuntimeError):
    """No Stockfish binary could be located."""


class EngineError(ValueError):
    """The engine started but does not behave like Stockfish (no usable ``UCI_Elo``)."""
```

<Src file="src/rukh/engine.py" tag="p0" lines="1-24" />

Dos excepciones con padres distintos: `EngineNotFound` hereda de `RuntimeError` (falta algo en la
máquina, se arregla instalando) y `EngineError` de `ValueError` (lo que hay no vale, se arregla
cambiando la configuración).

`MOVE_TIME_SECONDS = 0.05` es una constante del módulo porque la evaluación de M2 la reutiliza. El
tiempo por jugada es parte de la fuerza del motor; repetirlo como número mágico en dos sitios es una
forma silenciosa de medir con dos jueces distintos.

```python title="src/rukh/engine.py"


def find_stockfish() -> Path | None:
    """Locate Stockfish: ``RUKH_STOCKFISH``, then ``tools/stockfish/``, then ``PATH``.

    When ``RUKH_STOCKFISH`` is set it wins outright and must point at an existing file;
    otherwise ``EngineNotFound`` is raised instead of silently falling through.
    """
    env = os.environ.get("RUKH_STOCKFISH")
    if env:
        candidate = Path(env)
        if not candidate.is_file():
            raise EngineNotFound(f"RUKH_STOCKFISH={env} is not a file")
        return candidate
    tools = paths.tools_dir() / "stockfish"
    for pattern in ("stockfish*.exe", "stockfish"):
        for candidate in sorted(tools.glob(pattern)):
            if candidate.is_file():
                return candidate
    which = shutil.which("stockfish")
    return Path(which) if which else None
```

<Src file="src/rukh/engine.py" tag="p0" lines="40-60" />

El orden de búsqueda es parte del contrato: **la variable de entorno gana, después el binario del
repositorio y al final el del sistema**. Si el motor del sistema ganara al del repositorio, dos
ordenadores medirían con dos jueces distintos.

Si `RUKH_STOCKFISH` está puesta y no apunta a un fichero, la función lanza en vez de seguir
buscando. Devolver `None` trataría una errata como "no hay motor", y acabarías midiendo con el
Stockfish del sistema creyendo que usas el que elegiste.

`sorted(...)` porque `glob` no garantiza orden, y con `stockfish-avx2.exe` y `stockfish.exe` en la
misma carpeta querrías siempre el mismo.

```python title="src/rukh/engine.py"


def engine_check(elo: int = 1400, plies: int = 40, seed: int = 0) -> EngineCheckResult:
    """Open Stockfish, limit it to ``elo`` and play ``plies`` half-moves against a random mover.

    Stockfish plays White, the seeded random player plays Black. Raises ``EngineNotFound`` when
    no binary is available, ``EngineError`` when the binary does not expose ``UCI_Elo`` and
    ``ValueError`` when ``elo`` is outside the engine's range.
    """
    path = find_stockfish()
    if path is None:
        raise EngineNotFound(
            "Stockfish not found: run `uv run python scripts/get_stockfish.py` "
            "or set RUKH_STOCKFISH"
        )

    rng = random.Random(seed)
    board = chess.Board()
    nodes_hint: int | None = None
    plies_played = 0

    with chess.engine.SimpleEngine.popen_uci(str(path)) as engine:
        name = str(engine.id.get("name", "unknown"))
        try:
            option = engine.options["UCI_Elo"]
            uci_elo_min, uci_elo_max = int(option.min), int(option.max)
        except (
            KeyError,
            TypeError,
            chess.engine.EngineError,
            chess.engine.EngineTerminatedError,
        ) as exc:
            raise EngineError(f"{path} ({name}) does not expose UCI_Elo; is it Stockfish?") from exc
        if not uci_elo_min <= elo <= uci_elo_max:
            raise ValueError(f"UCI_Elo {elo} outside [{uci_elo_min}, {uci_elo_max}]")
        engine.configure({"UCI_LimitStrength": True, "UCI_Elo": elo})
```

<Src file="src/rukh/engine.py" tag="p0" lines="61-96" />

Aquí están los dos números que sostienen toda la evaluación del curso. `uci_elo_min` y
`uci_elo_max` se leen de la tabla de opciones que el motor declara al arrancar, por el
protocolo <Term id="uci">UCI</Term>; en sf_19 salen 1320 y 3190. Es el rango en el que se le puede pedir a
Stockfish que juegue peor de lo que sabe, y con él se estima el <Term id="elo-estimado">Elo</Term>
de cada modelo en M2. Al leerlo en vez de suponerlo, la escalera de rivales queda calibrada contra
el motor que de verdad tienes.

Las cuatro excepciones del `except` son las cuatro formas en que falla preguntar por `UCI_Elo` a
algo que no es Stockfish: sin esa opción, `KeyError`; declarada sin rango, `TypeError`; UCI mal
hablado, `EngineError`; un ejecutable que no habla UCI, `EngineTerminatedError`. Para quien llama,
las cuatro significan «esto no es Stockfish».

<Callout kind="roto" title="`UCI_Elo` sin `UCI_LimitStrength`">
  `engine.configure` recibe las dos opciones, y no sobra ninguna. `UCI_LimitStrength` es el
  interruptor que enciende el debilitamiento; `UCI_Elo` a solas se ignora mientras el interruptor
  esté apagado, sin error ni aviso. Olvidarlo es la forma clásica de medir contra un motor a plena
  fuerza creyendo que es un rival de 1500: tu modelo pierde 20-0 y la conclusión que sacas es sobre
  el modelo, cuando el fallo estaba en el juez.

Es un modo de fallo que vas a encontrar lejos del ajedrez: un parámetro que solo cuenta si otro
está activado. En `generate` de Hugging Face, `temperature` y `top_k` no hacen nada si
`do_sample=False`. Cuando un ajuste no mueve el resultado, antes de sacar conclusiones comprueba que
de verdad se está aplicando.

</Callout>

La partida de prueba enfrenta a Stockfish, con blancas, con un jugador aleatorio con semilla. No
mide nada, pero recorre el camino completo: abrir el motor, configurarlo, pedirle jugadas,
aplicarlas, detectar el final. Si algo de eso está roto, lo sabes aquí y no a mitad de una evaluación
de 160 partidas.

`claim_draw=True` va en los dos sitios, `is_game_over` y `result`. Incluye las tablas que hay que
reclamar (triple repetición, cincuenta jugadas); si el bucle parara por repetición y el resultado se
leyera sin el argumento, la partida saldría como `*`, sin resultado.

`random.Random(seed)` es un generador propio: la misma semilla da la misma partida y no altera el
estado aleatorio del resto del proceso.

La partida se mide en <Term id="ply">plies</Term>, medias jugadas: `1. e4 e5` son dos. `--plies 40`
es un tope; `plies_played` dice cuántas se jugaron de verdad.

```bash title="Terminal"
uv run rukh engine check --elo 1400 --plies 40
```

Las opciones cuando no hay motor, de más barata a más cara:

- Reglas y esquemas. ¿El JSON valida? ¿La cita existe en el documento? Detectan la forma rota, no
  el contenido malo; son el equivalente de la máscara de legalidad de este proyecto.
- Tests. En código son un oráculo casi tan bueno como un motor, con la trampa de que solo ven lo que
  cubren.
- Un LLM como juez. Barato y escalable, con sesgos que hay que medir: prefiere respuestas largas y su
  propio estilo, y se deja llevar por el orden en que le enseñas dos respuestas. Sirve si lo
  calibras contra un puñado de juicios humanos y publicas ese acuerdo.
- Personas. Lo más caro y lo único que mide de verdad lo que te importa. Por eso se usa en pequeño,
  para calibrar los otros tres.

Elige **el oráculo más barato que se parezca a la decisión real**, y mide en qué se diferencian. Un
proyecto que solo valida la forma acabará optimizando la forma.

</Transfer>

<Callout kind="entrevista" title="¿Por qué no usas Stockfish para jugar y ya está?">
  Porque el objetivo no es jugar bien, sino aprender cómo un modelo de lenguaje llega a jugar bien
  sin que nadie le programe las reglas. Stockfish calcula; el modelo predice. La gracia (y lo que se
  puede medir) es cuánto de lo que calcula el primero acaba emergiendo en el segundo solo por leer
  partidas. En la práctica, además, un modelo pequeño corre en el navegador y un motor completo no
  cabe en una demo estática.
</Callout>

## `tracking.py`: el cuaderno de laboratorio

<Term id="mlflow">MLflow</Term> guarda cada ejecución con su configuración, sus métricas por paso y
sus artefactos. Aquí se usa en su modo más simple: una base SQLite en `mlruns/mlflow.db`, sin
servidor.

```python title="src/rukh/tracking.py"
"""Local MLflow tracking: SQLite store under ``mlruns/`` and a run helper."""

from __future__ import annotations

import subprocess
import sys
from collections.abc import Iterator, Mapping
from contextlib import contextmanager
from typing import Any

from rukh import __version__, paths

EXPERIMENT = "rukh"


def tracking_uri(create: bool = True) -> str:
    """SQLite tracking URI ``sqlite:///<MLRUNS_DIR>/mlflow.db``; creates the directory if asked."""
    mlruns = paths.mlruns_dir()
    if create:
        mlruns.mkdir(parents=True, exist_ok=True)
    return f"sqlite:///{(mlruns / 'mlflow.db').as_posix()}"
```

<Src file="src/rukh/tracking.py" tag="p0" lines="1-21" />

Un solo experimento (`EXPERIMENT = "rukh"`) para todo el proyecto; los modelos y etapas se
distinguen por el nombre de la ejecución y los tags. Un experimento por módulo parece más ordenado,
pero comparar `rukh-small` con `rukh-medium-v4-dpo` obligaría a cruzar dos, y la tabla única compara
justo eso.

`create=False` existe para `rukh info`, que informa de dónde está la base sin crear el directorio:
un diagnóstico no debe modificar el disco. `as_posix()` porque SQLite quiere barras hacia delante
también en Windows.

```python title="src/rukh/tracking.py"


def flatten(config: Mapping[str, Any], prefix: str = "") -> dict[str, str]:
    """Flatten nested mappings into ``a.b=value`` string params (lists become their repr)."""
    flat: dict[str, str] = {}
    for key, value in config.items():
        name = f"{prefix}{key}"
        if isinstance(value, Mapping):
            flat.update(flatten(value, prefix=f"{name}."))
        else:
            flat[name] = str(value)
    return flat
```

<Src file="src/rukh/tracking.py" tag="p0" lines="22-33" />

MLflow solo acepta parámetros planos, clave y cadena, y las configuraciones del proyecto son YAML
anidado (`model.layers`, `optim.lr`). Una lista se guarda como su `repr` (`"[1, 2]"`): no es bonito,
pero es fiel.

Se registra toda la configuración, no una selección de hiperparámetros «importantes»: seis semanas
después, la diferencia entre dos ejecuciones siempre está en el campo que no parecía importante. En
una aplicación con LLMs pasa lo mismo con la versión del prompt, del modelo o del índice de un RAG:
si no quedan anotadas junto a cada evaluación, no sabrás qué cambió entre la que iba bien y la que
no.

```python title="src/rukh/tracking.py"


def git_sha() -> str | None:
    """Full SHA of the source tree (``paths.package_root()``), or None when it is not a git repo.

    The source tree is used on purpose: ``RUKH_HOME`` may point at a data directory that is
    not a checkout, and the tag must identify the code that produced the run.
    """
    try:
        out = subprocess.run(
            ["git", "rev-parse", "HEAD"],
            cwd=paths.package_root(),
            capture_output=True,
            text=True,
            check=True,
            timeout=10,
        )
    except (OSError, subprocess.SubprocessError):
        return None
    sha = out.stdout.strip()
    return sha or None
```

```python title="src/rukh/tracking.py"
def start_run(
    name: str,
    config: Mapping[str, Any],
    tags: Mapping[str, str] | None = None,
) -> Iterator[Any]:
    """Start an MLflow run in the local store with ``config`` logged as flattened params.

    Tags always include ``rukh_version`` and, when the project lives in a git repo, ``git_sha``.
    Yields the active ``mlflow.ActiveRun``.

    import mlflow

    mlflow.set_tracking_uri(tracking_uri())
    mlflow.set_experiment(EXPERIMENT)

    if sha:
        run_tags["git_sha"] = sha
    if tags:
        run_tags.update(tags)

        params = flatten(config)
        if params:
            mlflow.log_params(params)
        yield run
```

## `env.py`: qué tiene esta máquina, antes de lanzar nada

`env.py` es lo que hay detrás de `rukh info`: una foto de la máquina con qué Python, qué `torch` y si
ve la GPU, dónde está Stockfish, cuál es la base de MLflow y dónde están los datos.

Existe porque los peores fallos de un entorno no dan error: un `torch` de CPU en una máquina con GPU,
o un Stockfish distinto del que crees. `rukh info` los enseña en un segundo, y es lo primero que se
ejecuta en una máquina nueva o después de un `uv sync`.

`torch`, `gpu` y `stockfish` son `str | None` porque pueden faltar legítimamente; `cuda` es `bool`
porque la respuesta a "¿hay CUDA?" siempre es sí o no.

```python title="src/rukh/env.py"


def _torch_info() -> tuple[str | None, bool, str | None]:
    """Return (torch version, cuda available, gpu name); all empty if torch is missing."""
    try:
        import torch
    except ImportError:
        return None, False, None
    cuda = bool(torch.cuda.is_available())
    gpu = torch.cuda.get_device_name(0) if cuda else None
    return torch.__version__, cuda, gpu
```

<Src file="src/rukh/env.py" tag="p0" lines="28-38" />

Se captura `ImportError` y nada más. Un `torch` que falta es información; un `torch` que revienta
al importarse es un problema real que debe verse con su traza. Capturar `Exception` convertiría una
instalación corrupta en un `torch: null` silencioso. `get_device_name(0)` solo se llama si hay CUDA,
porque sin GPU lanza.

```python title="src/rukh/env.py"
def collect() -> EnvReport:
    """Collect the environment report. Never raises because torch or Stockfish are absent."""

        stockfish=str(stockfish) if stockfish else None,
```

lanza `EngineNotFound` en ese caso. Es lo correcto: una ruta explícita y equivocada es un error
del usuario, y tratarla como "no hay motor" acabaría midiendo con el Stockfish del sistema
mientras tú crees que usas otro.

  Desde `uv run python`, abre una ejecución a mano y míralo en la interfaz:

```python
from rukh.tracking import start_run
```

Después `uv run rukh mlflow ui` y busca la ejecución. ¿Qué parámetros tiene y con qué nombres? ¿Qué
tags? ¿Y qué pasa si el bloque `with` lanza una excepción a mitad?

<Solution>
  Los parámetros son `modelo.capas = "4"` y `lr = "0.0003"`: aplanados con punto y convertidos a
  cadena, que es lo único que MLflow acepta. Los tags incluyen `rukh_version` (`0.0.1`) y
  `git_sha` con el commit de tu checkout.

Si el bloque lanza, `mlflow.start_run` marca la ejecución como `FAILED` al salir del gestor de
contexto y la excepción se propaga. Eso es justo lo que se quiere: una ejecución interrumpida se
distingue de una terminada en la interfaz, y por eso el test comprueba `status == "FINISHED"` en el
camino bueno.

</Solution>

## Qué has aprendido

El proyecto ya tiene juez y cuaderno. Stockfish está en disco, verificado por UCI, y el rango en el
que se le puede pedir que juegue peor se lee del motor en vez de suponerse: 1320-3190. Cada ejecución
que se abra a partir de ahora deja su configuración completa y el SHA del código que la produjo en
una base local, y las model cards de M6 se generarán desde ahí.

`uv run rukh engine check` devuelve `uci_elo_min 1320` y `uci_elo_max 3190`;
`uv run pytest -m unit -q` pasa (los dos tests con marca `engine` quedan fuera del filtro) y
`uv run pytest -m engine -q` pasa con el binario instalado.

## Qué vas a construir

Dos ficheros nuevos con un solo producto: una fila de la tabla única que mide un modelo que no
entrenó nadie de este curso, con el mismo instrumento que todas las demás.

El modelo es el nanoGPT de ajedrez de Adam Karvonen: 8 capas, 25,7 M de parámetros, entrenado sobre
16 millones de partidas de Lichess escritas en PGN carácter a carácter. Tiene números publicados por
su autor, así que si nuestra fila cae donde esos números dicen, el harness es creíble; si no, lo
primero que hay que explicar es la diferencia.

`eval/karvonen.py` reimplementa la red y la convierte en un `Player` del proyecto;
`eval/karvonen_suite.py` le pasa la suite entera (posiciones, puzles, escalera) sin cambiar una
regla. Todo el trabajo está en sostener dos exigencias a la vez: reproducir su modelo tal cual lo
entrenó su autor y medirlo con nuestro código, sin excepciones.

## Por qué una fila que no es nuestra

Una tabla de modelos propios medidos con un harness propio no demuestra nada sobre el harness. Es
lo que hace cualquier equipo que evalúa un LLM: antes de creerse su banco de pruebas, le pasa un
modelo público con números conocidos y comprueba que salen donde deben. El docstring lo dice en su
primer párrafo.

```python title="src/rukh/eval/karvonen.py"
"""Adam Karvonen's chess nanoGPT as a ``Player``: the public baseline of the results table.

A table of our own models measured by our own harness proves nothing about the harness. One row
has to be a model somebody else built, published and described, put through *exactly* the same
ladder, positions and puzzles as ours -- if that row lands where its author's own numbers say it
should, the harness is credible; if it does not, the difference is the first thing to explain.

The baseline is the 8-layer, 25 M parameter character-level GPT of ``adamkarvonen/chess_llms``
(``lichess_8layers_ckpt_no_optimizer.pt``), trained with Karpathy's nanoGPT on 16 M Lichess games
written as ``;1.e4 e5 2.Nf3 Nc6`` -- one character per token, a ``;`` before every game, no space
after the move number. That format is reproduced here to the character, because the author's
own README warns that performance drops without the ``;``; the model has no Elo header and no
result, so it is asked the same question as ours with less information, which the reader should
keep in mind when comparing rows.

The network is nanoGPT's ``GPT`` reimplemented in a hundred lines rather than imported: the
checkpoint is a ``torch.compile`` state dict with ``_orig_mod.`` prefixes and nothing else, and
a baseline that pulls in a training repository to run inference is a baseline nobody rebuilds.
The vocabulary (``meta.pkl`` in his ``chess_llm_interpretability`` repository) is 32 characters,
pinned here by SHA-256 and by value.
"""
```

Tres decisiones anunciadas ahí:

- Se reimplementa la red en vez de importarla. nanoGPT es un repositorio de entrenamiento, no una
  librería, y un <Term id="baseline-publico">baseline público</Term> que solo corre mientras otro
  repositorio siga siendo compatible es una promesa que caduca. Cuatro clases de `nn.Module` con los
  mismos nombres de parámetros pesan menos.
- El formato del prompt se copia a la letra. El README del autor avisa de que el rendimiento cae sin
  el `;` inicial, y un modelo mal preguntado es la forma más fácil de que un baseline salga bajo.
- Se dice lo que el modelo no tiene. No lleva cabecera de Elo ni resultado, así que se le pregunta
  lo mismo que a los nuestros con menos información, y eso se escribe en el docstring, en las notas
  del resultado y en la card.

El <Term id="vocabulario">vocabulario</Term> está escrito dos veces: como los 32 caracteres de
`VOCAB` y como el SHA-256 del `meta.pkl` del autor. La constante permite correr sin red, que es lo
que necesitan los tests; el hash comprueba, cuando el fichero está, que la constante no se ha
desincronizado del original.

Con esos 32 caracteres (espacio, dígitos, punto, punto y coma, letras de piezas y casillas, y los
signos de captura, jaque, mate, promoción y enroque) se escribe cualquier <Term id="san">SAN</Term>
que `python-chess` pueda producir, y nada más: el modelo no puede escribir un token de Elo aunque
quisiera. `MAX_NEW_CHARS = 10` es un tope de seguridad: una jugada SAN ocupa como mucho siete
caracteres (`exd8=Q+`), y el tope evita que un modelo que olvide el espacio final genere para
siempre.

## nanoGPT, solo lo que el diccionario de estado necesita

La red es la de Karpathy, escrita hasta donde el diccionario de estado lo necesita: los mismos
nombres, las mismas formas, ni un módulo de más.

```python title="src/rukh/eval/karvonen.py"
@dataclass(frozen=True)
class GPTConfig:
    """nanoGPT's ``model_args`` as the checkpoint carries them; ``dropout`` is unused here."""

    n_layer: int = 8
    n_head: int = 8
    n_embd: int = 512
    block_size: int = 1023
    bias: bool = False
    vocab_size: int = 32
    dropout: float = 0.0
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="77-87" />

Un `dataclass` congelado y no pydantic: este objeto no se valida contra un YAML escrito por una
persona, se construye desde el `model_args` que el checkpoint lleva dentro. Los valores por defecto
son los de su modelo de 8 capas, y `block_size: 1023` (no 1024) es el de su entrenamiento: copiar el
número raro es reproducir, redondearlo es aproximar.

```python title="src/rukh/eval/karvonen.py"
class _Attention(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.n_head, self.n_embd = cfg.n_head, cfg.n_embd
        self.c_attn = nn.Linear(cfg.n_embd, 3 * cfg.n_embd, bias=cfg.bias)
        self.c_proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=cfg.bias)

    def forward(self, x: Tensor) -> Tensor:
        batch, length, width = x.shape
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)
        shape = (batch, length, self.n_head, width // self.n_head)
        q, k, v = (t.view(shape).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.c_proj(y.transpose(1, 2).contiguous().view(batch, length, width))


class _MLP(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.c_fc = nn.Linear(cfg.n_embd, 4 * cfg.n_embd, bias=cfg.bias)
        self.c_proj = nn.Linear(4 * cfg.n_embd, cfg.n_embd, bias=cfg.bias)

    def forward(self, x: Tensor) -> Tensor:
        return self.c_proj(F.gelu(self.c_fc(x)))


class _Block(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.ln_1 = nn.LayerNorm(cfg.n_embd, bias=cfg.bias)
        self.attn = _Attention(cfg)
        self.ln_2 = nn.LayerNorm(cfg.n_embd, bias=cfg.bias)
        self.mlp = _MLP(cfg)

    def forward(self, x: Tensor) -> Tensor:
        x = x + self.attn(self.ln_1(x))
        return x + self.mlp(self.ln_2(x))
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="90-126" />

Si vienes de M2, esto te resultará familiar. Las diferencias son las que separan un decoder de 2022
del nuestro:

- Los nombres son los de nanoGPT (`c_attn`, `c_proj`, `c_fc`, `ln_1`, `ln_2`). `load_state_dict`
  compara claves, así que al reimplementar un modelo ajeno los nombres son parte del formato del
  fichero.
- `c_attn` produce las tres proyecciones de golpe (`3 * n_embd`) y se parten con `split`: una
  multiplicación grande en vez de tres pequeñas.
- Posición absoluta aprendida (`wpe`, en el bloque siguiente), no <Term id="rope">RoPE</Term>. Por
  eso `block_size` es un límite duro.
- <Term id="pre-norm">Pre-norm</Term> con `LayerNorm` sin sesgo y GELU, la receta de GPT-2. Nada de
  eso cambia lo que aquí se mide.

`F.scaled_dot_product_attention(..., is_causal=True)` delega la <Term id="mascara-causal">máscara
causal</Term> a PyTorch en vez de construirla a mano como el nanoGPT original. Es de los pocos sitios
donde el código no es el del autor línea a línea, y es seguro porque la operación está especificada.

```python title="src/rukh/eval/karvonen.py"
class GPT(nn.Module):
    """Karpathy's nanoGPT, exactly as far as the state dict needs: same names, same shapes."""

    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.cfg = cfg
        self.transformer = nn.ModuleDict(
            {
                "wte": nn.Embedding(cfg.vocab_size, cfg.n_embd),
                "wpe": nn.Embedding(cfg.block_size, cfg.n_embd),
                "h": nn.ModuleList([_Block(cfg) for _ in range(cfg.n_layer)]),
                "ln_f": nn.LayerNorm(cfg.n_embd, bias=cfg.bias),
            }
        )
        self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        self.transformer.wte.weight = self.lm_head.weight  # tied, as nanoGPT ties them

    def forward(self, idx: Tensor) -> Tensor:
        """Logits over the vocabulary at every position of ``idx`` (``batch, length``)."""
        length = idx.shape[1]
        if length > self.cfg.block_size:
            raise ValueError(f"sequence of {length} exceeds block size {self.cfg.block_size}")
        pos = torch.arange(length, device=idx.device)
        x = self.transformer.wte(idx) + self.transformer.wpe(pos)
        for block in self.transformer.h:
            x = block(x)
        return self.lm_head(self.transformer.ln_f(x))
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="129-155" />

El `nn.ModuleDict` llamado `transformer` con `wte`, `wpe`, `h` y `ln_f` es, otra vez, el formato del
fichero. `self.transformer.wte.weight = self.lm_head.weight` ata
los <Term id="tied-embeddings">tied embeddings</Term> asignando el mismo objeto, y el test lo comprueba
con `data_ptr()`. El `forward` no acepta etiquetas ni devuelve pérdida: la mitad del original es
entrenamiento, y cada línea que no está es una línea que no puede estar mal.

## Cargar un checkpoint que pasó por `torch.compile`

```python title="src/rukh/eval/karvonen.py"
def strip_compiled(state: dict[str, Any]) -> dict[str, Any]:
    """The state dict without the ``_orig_mod.`` that ``torch.compile`` leaves on every key."""
    return {key.removeprefix(COMPILED_PREFIX): value for key, value in state.items()}


def load_karvonen(checkpoint: Path | str, device: str | None = None) -> GPT:
    """The model of a nanoGPT checkpoint (``model_args`` plus ``model``), in eval mode."""
    payload = torch.load(Path(checkpoint), map_location="cpu", weights_only=True)
    args = {k: v for k, v in payload["model_args"].items() if k in GPTConfig.__dataclass_fields__}
    model = GPT(GPTConfig(**args))
    model.load_state_dict(strip_compiled(payload["model"]))
    return model.to(device or "cpu").eval()
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="158-169" />

`torch.compile` envuelve el modelo en un objeto llamado `_orig_mod`, y ese nombre se cuela delante de
todas las claves al guardar. Un checkpoint compilado no carga en un modelo sin compilar, y el error
es una lista de doscientas claves inesperadas que no dice por qué. `removeprefix`, que no hace nada
si el prefijo no está, hace al cargador indiferente a cómo se entrenó.

El filtro `if k in GPTConfig.__dataclass_fields__` tira las claves que la configuración no tiene: lo
contrario de `extra="forbid"` de M0, y aquí es lo correcto, porque `model_args` es un fichero de otro
proyecto que puede llevar claves de entrenamiento que no describen la arquitectura. Y `.eval()` antes
de devolver, siempre: un modelo en modo entrenamiento da números ligeramente distintos sin fallar
nunca.

```python title="src/rukh/eval/karvonen.py"
def read_meta(path: Path | str) -> dict[str, int]:
    """``stoi`` of ``meta.pkl``, refused unless it is byte for byte the pinned file."""
    raw = Path(path).read_bytes()
    digest = hashlib.sha256(raw).hexdigest()
    if digest != META_SHA256:
        raise ValueError(f"{path}: sha256 {digest} is not the pinned {META_SHA256}")
    stoi = dict(pickle.loads(raw)["stoi"])  # noqa: S301 - the hash above pins the bytes
    if stoi != STOI:
        raise ValueError(f"{path}: vocabulary differs from the one this player writes")
    return stoi
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="172-181" />

El orden es toda la seguridad de esta función: el hash se comprueba antes de deserializar.
`pickle.loads` sobre un fichero descargado ejecuta código arbitrario (ruff lo marca con `S301`), y el
`noqa` lleva su razón al lado: los bytes ya están fijados por el hash. La segunda comprobación, que
el `stoi` del fichero sea igual a la constante, atrapa a quien edite `VOCAB` en el código.

```python title="src/rukh/eval/karvonen.py"
def ensure_karvonen(download: bool = True, local_dir: Path | str | None = None) -> Path:
    """The checkpoint on disk (downloading it and ``meta.pkl`` when allowed), and its path.

    The Hub repository is somebody else's, so this is not a ``rukh pull`` artefact -- nothing here
    is published by the course, nothing can be. ``huggingface_hub`` caches the 100 MB file once.
    """
    directory = Path(local_dir) if local_dir is not None else paths.resolve(LOCAL_DIR)
    checkpoint = directory / CHECKPOINT_FILE
    meta = directory / "meta.pkl"
    if not checkpoint.is_file():
        if not download:
            raise FileNotFoundError(f"{checkpoint} is not on disk (rukh eval karvonen pulls it)")
        import huggingface_hub

        log.info("downloading %s/%s", HF_REPO, CHECKPOINT_FILE)
        directory.mkdir(parents=True, exist_ok=True)
        huggingface_hub.hf_hub_download(HF_REPO, CHECKPOINT_FILE, local_dir=str(directory))
    if not meta.is_file() and download:
        import urllib.request

        log.info("downloading %s", META_URL)
        with urllib.request.urlopen(META_URL, timeout=60) as response:  # noqa: S310 - https, pinned
            meta.write_bytes(response.read())
    if meta.is_file():
        read_meta(meta)
    return checkpoint
```

## La transcripción, a la letra

```python title="src/rukh/eval/karvonen.py"
def transcript(board: chess.Board) -> str:
    """The game on ``board`` in the author's format: ``;1.e4 e5 2.Nf3`` and, for White, ``3.``.

    When Black is to move the text ends on White's move with no trailing space: the model writes
    the space itself, as it did in training, and a prompt that carried it would be a spelling it
    never saw. Replayed from the root because SAN depends on the position it is written in.
    """
    replay = board.root()
    parts: list[str] = []
    for move in board.move_stack:
        san = replay.san(move)
        parts.append(f"{replay.fullmove_number}.{san}" if replay.turn == chess.WHITE else san)
        replay.push(move)
    if replay.turn == chess.WHITE:
        parts.append(f"{replay.fullmove_number}.")
    return ";" + " ".join(parts)
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="212-227" />

La función tiene tres trampas, y ninguna falla: producen un prompt razonable que el modelo responde
peor.

- El espacio final. Cuando le toca a las negras, el texto acaba en la jugada de las blancas sin
  espacio: el modelo lo escribe él mismo, porque así lo vio al entrenar. Por eso `write` acepta un
  espacio como primer carácter.
- El número de jugada solo delante de las blancas y pegado: `1.e4`, no `1. e4`.
- El <Term id="san">SAN</Term> se calcula con el tablero anterior a la jugada. SAN depende del
  contexto (`Nbd2` solo existe donde dos caballos llegan a d2), y calcularlo después daría
  notaciones que el modelo no reconoce.

`board.root()` y no `chess.Board()`, porque si el tablero empezó en un FEN la raíz es esa.

## El jugador

`KarvonenPlayer` implementa la misma interfaz `Player` que usa el decoder para jugar contra
Stockfish, así que entra en `play_rungs` sin adaptadores.

```python title="src/rukh/eval/karvonen.py"
class KarvonenPlayer:
    """A ``rukh.infer.Player`` that writes SAN one character at a time from the transcript.

    Same accounting as ``QwenPlayer`` (``QwenStats``, ``parse_san_answer``, first legal move as the
    fallback and never a second sample), so its failure breakdown is comparable with that row.
    """

    def __init__(
        self,
        model: GPT,
        stats: QwenStats | None = None,
        temperature: float = 0.0,
        top_k: int | None = None,
        seed: int | None = None,
        max_new_chars: int = MAX_NEW_CHARS,
        max_plies: int = DECODER_PLIES,
    ) -> None:
        self.model = model
        self.stats = stats if stats is not None else QwenStats()
        self.temperature, self.top_k, self.max_new_chars = temperature, top_k, max_new_chars
        self.max_plies = max_plies
        self.device = next(model.parameters()).device
        self.generator: torch.Generator | None = None
        if seed is not None:
            self.generator = torch.Generator(device="cpu").manual_seed(seed)

    @property
    def limit(self) -> int:
        """Plies this player can carry: the decoder's number, so every row plays the same game."""
        return self.max_plies

    def start(self, white_elo: int, black_elo: int) -> None:
        """Nothing to set: this model has no rating header, which is part of what it is."""

    def observe(self, move: chess.Move) -> None:
        """Nothing to record: the board carries the history and the transcript is built from it."""
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="230-265" />

`start` y `observe` existen porque el protocolo los pide y aquí no hacen nada: no hay cabecera de Elo
que configurar, y la partida se reconstruye del tablero cada vez. Un método vacío con un docstring
que dice por qué está vacío es información; sin él parece un olvido.

`max_plies = DECODER_PLIES` importa el límite de <Term id="ply">plies</Term> del decoder: una partida
que se corta antes se adjudica, y adjudicar más veces cambia el resultado. Y el generador va en CPU
aunque el modelo esté en GPU, porque da la misma secuencia en cualquier máquina.

```python title="src/rukh/eval/karvonen.py"
    def _next(self, logits: Tensor) -> int:
        if self.temperature <= 0 or self.top_k == 1:
            return int(logits.argmax())
        logits = logits / self.temperature
        if self.top_k is not None and self.top_k < logits.numel():
            cutoff = torch.topk(logits, self.top_k).values[-1]
            logits = logits.masked_fill(logits < cutoff, -math.inf)
        probs = F.softmax(logits, dim=-1).cpu()
        return int(torch.multinomial(probs, 1, generator=self.generator))

    def write(self, prompt: str) -> str:
        """Characters the model appends to ``prompt``, up to the space that ends the move."""
        ids = [STOI[char] for char in prompt]
        written: list[str] = []
        with torch.no_grad():
            for _ in range(self.max_new_chars):
                window = ids[-self.model.cfg.block_size :]
                logits = self.model(torch.tensor([window], device=self.device))[0, -1]
                char = VOCAB[self._next(logits.float())]
                if char == ";" or (char == " " and "".join(written).strip()):
                    break  # a new game, or the end of the move
                written.append(char)
                ids.append(STOI[char])
        return "".join(written)
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="267-290" />

`_next` es el muestreo de M2: <Term id="temperatura">temperatura</Term>
y <Term id="top-k">top-k</Term>, con el atajo de `argmax` cuando la temperatura es cero o `top_k` es
1, que además evita dividir por cero. La condición de parada de `write` merece leerse dos veces:

```
if char == ";" or (char == " " and "".join(written).strip()):
```

Para en el punto y coma porque eso significa que el modelo ha decidido empezar otra partida. Y para
en el espacio solo si ya ha escrito algo que no es espacio: ese `strip()` permite el turno de las
negras, cuyo primer carácter es el espacio que el modelo escribe él mismo. Sin él, las negras
devolverían siempre la cadena vacía.

`logits.float()` antes de muestrear, porque `multinomial` sobre fp16 pierde resolución en la cola.
`window = ids[-block_size:]` recorta por la izquierda las partidas que no caben en 1023 caracteres,
lo único que se puede hacer con posición absoluta aprendida.

```python title="src/rukh/eval/karvonen.py"
    def answer(self, board: chess.Board) -> str:
        """The raw continuation the model writes for this position."""
        return self.write(transcript(board))

    def propose(self, board: chess.Board) -> tuple[chess.Move | None, str]:
        """What the model wrote, parsed, with the outcome named. No mask, no rescue."""
        move, outcome = parse_san_answer(board, self.answer(board))
        self.stats.record(outcome)
        return move, outcome

    def choose(self, board: chess.Board) -> tuple[chess.Move | None, bool]:
        """The move to play and whether its own answer was usable; ``QwenPlayer``'s rule exactly."""
        move, _ = self.propose(board)
        if move is not None:
            return move, True
        legal = list(board.legal_moves)
        return (legal[0] if legal else None), False
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="292-308" />

Tres métodos en capas. `propose` mide: devuelve lo que el modelo propuso y lo apunta en las
estadísticas. `choose` juega: si la propuesta no sirve, toma la primera jugada legal y devuelve
`False` para que quien cuente sepa que esa no la eligió el modelo. El rescate es la primera legal, no
un sorteo por logits como en el decoder, porque es lo que hace `QwenPlayer`: así las dos filas
externas tienen el mismo rescate y su desglose de fallos se lee en la misma escala.

## Los puzles: reconstruir la partida que el modelo no puede leer

Un puzle llega como una posición FEN, y este modelo no sabe leer un FEN: una transcripción que
empieza en la jugada 23 sin nada delante es un texto que nunca vio.

```python title="src/rukh/eval/karvonen.py"
def prefix_board(board: chess.Board, history: list[int], tok: Any) -> chess.Board:
    """``board`` with the real game in front of it, rebuilt from the decoder's prompt ids.

    A puzzle board starts from a FEN and its history lives only in the tokens the decoder reads.
    This model cannot read a FEN at all -- a transcript that begins at move 23 with no moves is
    text it never saw -- so the game is replayed from the UCI tokens and used when it reaches the
    puzzle's position. When it does not (a line-only parquet), the board is returned as it is and
    the caller counts that the model played blind.
    """
    replay = chess.Board()
    for token in tok.decode(history):
        if token.startswith("<"):
            continue
        try:
            replay.push_uci(token)
        except ValueError:
            return board
    same = replay.fen().split(" ")[:4] == board.fen().split(" ")[:4]
    return replay if same else board


class KarvonenSource:
    """The ``MoveSource`` the puzzle suite expects; ``blind`` counts the prompts with no game."""

    def __init__(self, player: KarvonenPlayer, tok: Any) -> None:
        self.player, self.tok = player, tok
        self.blind = 0

    def __call__(self, board: chess.Board, history: list[int]) -> chess.Move | None:
        prompted = prefix_board(board, history, self.tok)
        if prompted is board:
            self.blind += 1
        move, _ = self.player.choose(prompted)
        return move


def karvonen_source(player: KarvonenPlayer, tok: Any) -> KarvonenSource:
    """Puzzles are scored on the move the model *chooses*, fallback included, as for Qwen."""
    return KarvonenSource(player, tok)
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="311-349" />

`prefix_board` traduce entre los dos mundos: decodifica a UCI los tokens del prompt del decoder, los
reproduce desde el principio y comprueba que la posición a la que llega es la del puzle.

La comprobación es lo importante. Compara los cuatro primeros campos del FEN (piezas, turno,
enroques y al paso) y deja fuera los dos contadores, que pueden diferir sin que la posición sea otra.
Si falla, devuelve el tablero original sin inventarse nada, y `prompted is board` es la señal: la
identidad del objeto distingue «se reconstruyó» de «no se pudo» sin un segundo valor de retorno.

Esos casos, `blind`, se cuentan y se publican. Un puzle respondido a ciegas es una pregunta casi
imposible, y si el parquet no trae el prefijo de la partida, el porcentaje de este modelo es un
suelo, no una medición. Esconder el conteo sería publicar una tasa baja como si midiera al modelo.

<Transfer concept="Los datos que un sistema no puede leer" where="Cualquier evaluación que compara modelos con interfaces distintas: uno que ve imágenes y otro que ve su descripción, uno con memoria y otro sin ella.">
  Cuando dos sistemas no aceptan la misma entrada, puedes traducir la entrada al formato de cada uno,
  empobrecer la de todos hasta el mínimo común, o medir a cada uno como puede y decir qué le faltó.
  Aquí se traduce con `prefix_board` y, cuando la traducción falla, se cuenta. Bajar a todos al
  mínimo parece lo más justo y casi nunca lo es: quitarle al decoder la cabecera de Elo empeoraría
  nuestra medida sin mejorar la suya, y la comparación no describiría a ninguno de los dos como se
  usa.

</Transfer>

class _Scripted(nn.Module):
    """A stand-in for the network that writes a fixed string, one character per call."""

    def __init__(self, text: str) -> None:
        super().__init__()
        self.cfg = TOY
        self.script = list(text)
        self.dummy = nn.Parameter(torch.zeros(1))

    def forward(self, idx: Tensor) -> Tensor:
        logits = torch.full((1, idx.shape[1], 32), -10.0)
        char = self.script.pop(0) if self.script else " "
        logits[0, -1, STOI[char]] = 10.0
        return logits


def test_writing_stops_at_the_space_that_ends_the_move() -> None:
    assert KarvonenPlayer(_Scripted("Nf3 Nc6 3.")).write(";1.e4 e5 2.") == "Nf3"
    # Black's move starts with the space the model writes itself; the second space ends it.
    assert KarvonenPlayer(_Scripted(" e5 2.Nf3")).write(";1.e4") == " e5"
    # A new game delimiter means the model thinks the game is over: nothing was written.
    assert KarvonenPlayer(_Scripted(";1.e4")).write(";1.e4 e5 2.") == ""
    # A cap, so a model that never writes a space cannot run for ever.
    assert KarvonenPlayer(_Scripted("a" * 40), max_new_chars=5).write(";1.") == "aaaaa"

## Qué has aprendido

Un baseline público es un modelo ajeno traído a tu instrumento, no un número copiado de un paper.
Traerlo bien exige reproducir su formato a la letra y medirlo con tu código sin excepciones.

Tres decisiones sirven en cualquier comparación contra un modelo de otros: reimplementar en vez de
importar cuando lo que importarías es un repositorio de entrenamiento; fijar por hash lo que se
descarga y validarlo antes de deserializarlo; y contar lo que el modelo ajeno no pudo responder,
porque un porcentaje sin ese conteo mide otra cosa.

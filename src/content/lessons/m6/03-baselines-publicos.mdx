## Qué vas a construir

Dos ficheros nuevos, 652 líneas, con un solo producto: una fila de la tabla única que mide un
modelo **que no entrenó nadie de este curso**, con el mismo instrumento que todas las demás.

El modelo es el nanoGPT de ajedrez de Adam Karvonen: 8 capas, 25,7 M de parámetros, entrenado sobre
16 millones de partidas de Lichess escritas en PGN carácter a carácter. Tiene números publicados por
su autor, así que si nuestra fila cae donde esos números dicen, el harness es creíble; y si no cae
ahí, la primera cosa que hay que explicar es la diferencia.

`eval/karvonen.py` reimplementa la red y la convierte en un `Player` del proyecto.
`eval/karvonen_suite.py` le pasa la suite entera —posiciones, puzles, escalera— sin cambiar una sola
regla. Todo lo que hay dentro está en tensión entre dos cosas: reproducir el modelo del autor
**exactamente** y medirlo con **nuestro** código exactamente.

## Por qué una fila que no es nuestra

Una tabla de modelos propios medidos con un harness propio no demuestra nada sobre el harness. El
docstring del fichero lo dice en su primer párrafo y merece leerse antes que el código.

```python title="src/rukh/eval/karvonen.py"
"""Adam Karvonen's chess nanoGPT as a ``Player``: the public baseline of the results table.

A table of our own models measured by our own harness proves nothing about the harness. One row
has to be a model somebody else built, published and described, put through *exactly* the same
ladder, positions and puzzles as ours -- if that row lands where its author's own numbers say it
should, the harness is credible; if it does not, the difference is the first thing to explain.

The baseline is the 8-layer, 25 M parameter character-level GPT of ``adamkarvonen/chess_llms``
(``lichess_8layers_ckpt_no_optimizer.pt``), trained with Karpathy's nanoGPT on 16 M Lichess games
written as ``;1.e4 e5 2.Nf3 Nc6`` -- one character per token, a ``;`` before every game, no space
after the move number. That format is reproduced here to the character, because the author's
own README warns that performance drops without the ``;``; the model has no Elo header and no
result, so it is asked the same question as ours with less information, which the reader should
keep in mind when comparing rows.

The network is nanoGPT's ``GPT`` reimplemented in a hundred lines rather than imported: the
checkpoint is a ``torch.compile`` state dict with ``_orig_mod.`` prefixes and nothing else, and
a baseline that pulls in a training repository to run inference is a baseline nobody rebuilds.
The vocabulary (``meta.pkl`` in his ``chess_llm_interpretability`` repository) is 32 characters,
pinned here by SHA-256 and by value.
"""
```

Tres decisiones están anunciadas ahí y las tres se ven abajo en código.

**Se reimplementa la red en vez de importarla.** nanoGPT es un repositorio de entrenamiento, no una
librería: instalarlo para hacer inferencia arrastra dependencias, scripts y una configuración global.
Un <Term id="baseline-publico">baseline público</Term> que solo corre si otro repositorio sigue
existiendo y sigue siendo compatible no es un baseline; es una promesa que caduca. Cien líneas de
`nn.Module` con los mismos nombres de parámetros pesan menos.

**El formato del prompt se copia a la letra.** El README del autor avisa de que el rendimiento cae
sin el `;` inicial. Reproducirlo es la diferencia entre medir su modelo y medir su modelo mal
preguntado, y esa segunda cosa es exactamente la forma más fácil de que un baseline salga bajo.

**Se dice lo que el modelo no tiene.** No lleva cabecera de Elo ni resultado, así que se le pregunta
lo mismo que a los nuestros con **menos información**. Eso no se compensa ni se disimula: se escribe
en el docstring, en las notas del resultado y en la card.

El <Term id="vocabulario">vocabulario</Term> está escrito **dos veces**: como los 32 caracteres de
`VOCAB` y como el SHA-256 del `meta.pkl` del autor. No es redundancia, es la única forma de tener las
dos propiedades que hacen falta. La constante permite correr sin red y sin descargar nada, que es lo
que necesitan los tests. El hash permite comprobar, cuando el fichero sí está, que la constante no se
ha desincronizado del original. Si el autor cambiara el vocabulario, `read_meta` lo diría en vez de
producir un modelo que escribe basura con una tabla de tokens de otro.

Esos 32 caracteres son todo el <Term id="token">vocabulario</Term>: un espacio, los dígitos, el punto,
el punto y coma, las letras de las piezas en mayúscula y las de las casillas en minúscula, y los
signos de captura, jaque, mate, promoción y enroque. Con eso se escribe cualquier <Term id="san">SAN</Term>
que `python-chess` pueda producir, y ninguna otra cosa: el modelo no tiene forma de escribir un token
de Elo aunque quisiera.

`MAX_NEW_CHARS = 10` es un tope de seguridad, no una regla del modelo. Una jugada SAN ocupa siete
caracteres en el peor caso (`exd8=Q+`), así que diez sobran; lo que el número garantiza es que un
modelo que se olvide de escribir el espacio final no genere para siempre.

## nanoGPT, en cien líneas

La red es la de Karpathy, y está escrita tan lejos como el diccionario de estado necesita: los mismos
nombres, las mismas formas, ni un módulo de más.

```python title="src/rukh/eval/karvonen.py"
@dataclass(frozen=True)
class GPTConfig:
    """nanoGPT's ``model_args`` as the checkpoint carries them; ``dropout`` is unused here."""

    n_layer: int = 8
    n_head: int = 8
    n_embd: int = 512
    block_size: int = 1023
    bias: bool = False
    vocab_size: int = 32
    dropout: float = 0.0
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="77-87" />

Un `dataclass` congelado y no una configuración de pydantic como el resto del proyecto. La razón es
que este objeto no se valida contra un YAML escrito por una persona: se construye desde el
`model_args` que el checkpoint del autor lleva dentro. Los valores por defecto son los de **su**
modelo de 8 capas, así que un checkpoint que no traiga alguna clave se construye igual.

`block_size: 1023` y no 1024: es el valor de su entrenamiento. Copiar el número raro en vez de
redondearlo es la diferencia entre reproducir y aproximar.

```python title="src/rukh/eval/karvonen.py"
class _Attention(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.n_head, self.n_embd = cfg.n_head, cfg.n_embd
        self.c_attn = nn.Linear(cfg.n_embd, 3 * cfg.n_embd, bias=cfg.bias)
        self.c_proj = nn.Linear(cfg.n_embd, cfg.n_embd, bias=cfg.bias)

    def forward(self, x: Tensor) -> Tensor:
        batch, length, width = x.shape
        q, k, v = self.c_attn(x).split(self.n_embd, dim=2)
        shape = (batch, length, self.n_head, width // self.n_head)
        q, k, v = (t.view(shape).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.c_proj(y.transpose(1, 2).contiguous().view(batch, length, width))


class _MLP(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.c_fc = nn.Linear(cfg.n_embd, 4 * cfg.n_embd, bias=cfg.bias)
        self.c_proj = nn.Linear(4 * cfg.n_embd, cfg.n_embd, bias=cfg.bias)

    def forward(self, x: Tensor) -> Tensor:
        return self.c_proj(F.gelu(self.c_fc(x)))


class _Block(nn.Module):
    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.ln_1 = nn.LayerNorm(cfg.n_embd, bias=cfg.bias)
        self.attn = _Attention(cfg)
        self.ln_2 = nn.LayerNorm(cfg.n_embd, bias=cfg.bias)
        self.mlp = _MLP(cfg)

    def forward(self, x: Tensor) -> Tensor:
        x = x + self.attn(self.ln_1(x))
        return x + self.mlp(self.ln_2(x))
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="90-126" />

Si vienes de M2, esto te va a resultar familiar y distinto a la vez, y las diferencias son
precisamente lo que separa un decoder de 2022 del nuestro.

**Los nombres son los de nanoGPT y no los nuestros.** `c_attn`, `c_proj`, `c_fc`, `ln_1`, `ln_2`: son
los nombres con los que el autor guardó sus tensores. Un `load_state_dict` compara claves, así que
llamar a la proyección `out_proj` porque nos gusta más significa que el checkpoint no carga. Cuando
se reimplementa un modelo ajeno, los nombres son parte del formato del fichero.

**`c_attn` produce las tres proyecciones de golpe** (`3 * n_embd`) y luego se parten con `split`. Es
lo que hace nanoGPT y es más rápido que tres capas lineales: una sola multiplicación de matrices
grande en vez de tres pequeñas.

**Posición absoluta aprendida, no <Term id="rope">RoPE</Term>.** Se ve en el bloque siguiente:
`wpe` es una tabla de embeddings indexada por posición. Nuestro decoder usa RoPE porque generaliza
mejor a longitudes que no vio; el suyo no, y por eso `block_size` es un límite duro y no una
preferencia.

**<Term id="pre-norm">Pre-norm</Term> con `LayerNorm` sin sesgo, y GELU.** Es la receta de GPT-2 que
nanoGPT copia. Nuestro decoder también es pre-norm; las diferencias están en la normalización y en la
activación, y ninguna de las dos cambia lo que aquí se mide.

`F.scaled_dot_product_attention(..., is_causal=True)` es la <Term id="mascara-causal">máscara
causal</Term> delegada a PyTorch. nanoGPT original construía la máscara triangular a mano; usar la
función de la librería da el mismo resultado numérico y elige el kernel rápido cuando puede. Es uno
de los dos sitios donde este código **no** es literalmente el del autor, y es seguro porque la
operación está especificada.

```python title="src/rukh/eval/karvonen.py"
class GPT(nn.Module):
    """Karpathy's nanoGPT, exactly as far as the state dict needs: same names, same shapes."""

    def __init__(self, cfg: GPTConfig) -> None:
        super().__init__()
        self.cfg = cfg
        self.transformer = nn.ModuleDict(
            {
                "wte": nn.Embedding(cfg.vocab_size, cfg.n_embd),
                "wpe": nn.Embedding(cfg.block_size, cfg.n_embd),
                "h": nn.ModuleList([_Block(cfg) for _ in range(cfg.n_layer)]),
                "ln_f": nn.LayerNorm(cfg.n_embd, bias=cfg.bias),
            }
        )
        self.lm_head = nn.Linear(cfg.n_embd, cfg.vocab_size, bias=False)
        self.transformer.wte.weight = self.lm_head.weight  # tied, as nanoGPT ties them

    def forward(self, idx: Tensor) -> Tensor:
        """Logits over the vocabulary at every position of ``idx`` (``batch, length``)."""
        length = idx.shape[1]
        if length > self.cfg.block_size:
            raise ValueError(f"sequence of {length} exceeds block size {self.cfg.block_size}")
        pos = torch.arange(length, device=idx.device)
        x = self.transformer.wte(idx) + self.transformer.wpe(pos)
        for block in self.transformer.h:
            x = block(x)
        return self.lm_head(self.transformer.ln_f(x))
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="129-155" />

El `nn.ModuleDict` llamado `transformer` con las claves `wte`, `wpe`, `h` y `ln_f` es, otra vez, el
formato del fichero y no una elección de diseño: así se llaman los tensores dentro del checkpoint.

`self.transformer.wte.weight = self.lm_head.weight` ata los <Term id="tied-embeddings">tied
embeddings</Term> **asignando el mismo objeto**, no copiando valores. Es lo que hace nanoGPT y es lo
que el test comprueba con `data_ptr()`: un solo tensor, no dos copias que podrían divergir.

El `forward` no acepta etiquetas ni devuelve pérdida: aquí solo se hace inferencia. Un modelo
reimplementado para medirlo es más corto que el original justamente porque la mitad del original es
entrenamiento, y cada línea que no está es una línea que no puede estar mal.

## Cargar un checkpoint que pasó por `torch.compile`

```python title="src/rukh/eval/karvonen.py"
def strip_compiled(state: dict[str, Any]) -> dict[str, Any]:
    """The state dict without the ``_orig_mod.`` that ``torch.compile`` leaves on every key."""
    return {key.removeprefix(COMPILED_PREFIX): value for key, value in state.items()}


def load_karvonen(checkpoint: Path | str, device: str | None = None) -> GPT:
    """The model of a nanoGPT checkpoint (``model_args`` plus ``model``), in eval mode."""
    payload = torch.load(Path(checkpoint), map_location="cpu", weights_only=True)
    args = {k: v for k, v in payload["model_args"].items() if k in GPTConfig.__dataclass_fields__}
    model = GPT(GPTConfig(**args))
    model.load_state_dict(strip_compiled(payload["model"]))
    return model.to(device or "cpu").eval()
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="158-169" />

`torch.compile` envuelve el modelo en un objeto que se llama `_orig_mod`, y al guardar el estado ese
nombre se cuela delante de **todas** las claves. Un checkpoint compilado no carga en un modelo sin
compilar y el error es una lista de doscientas claves inesperadas que no dice por qué. Quitar el
prefijo con `removeprefix` —que no hace nada si no está— es una línea que hace el cargador
indiferente a cómo se entrenó.

El filtro `if k in GPTConfig.__dataclass_fields__` tira las claves de `model_args` que la
configuración no tiene. Es la decisión inversa a `extra="forbid"` de M0, y aquí es la correcta: el
`model_args` es un fichero de **otro proyecto**, que puede llevar claves de entrenamiento (`bias` de
un optimizador, `dropout` de una variante) que no describen la arquitectura. Prohibirlas sería
negarse a cargar un modelo perfectamente cargable por un campo que no se usa.

`.eval()` antes de devolver, siempre. No hay dropout activo en este modelo, pero un modelo devuelto
en modo entrenamiento es la clase de detalle que produce números ligeramente distintos sin fallar
nunca.

```python title="src/rukh/eval/karvonen.py"
def read_meta(path: Path | str) -> dict[str, int]:
    """``stoi`` of ``meta.pkl``, refused unless it is byte for byte the pinned file."""
    raw = Path(path).read_bytes()
    digest = hashlib.sha256(raw).hexdigest()
    if digest != META_SHA256:
        raise ValueError(f"{path}: sha256 {digest} is not the pinned {META_SHA256}")
    stoi = dict(pickle.loads(raw)["stoi"])  # noqa: S301 - the hash above pins the bytes
    if stoi != STOI:
        raise ValueError(f"{path}: vocabulary differs from the one this player writes")
    return stoi
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="172-181" />

El orden de las tres operaciones es toda la seguridad de esta función y no se puede alterar: se
comprueba el hash **antes** de deserializar. `pickle.loads` sobre un fichero descargado de internet
ejecuta código arbitrario, y por eso ruff lo marca con `S301`. El `noqa` lleva su razón al lado: los
bytes ya están fijados por el hash de la línea de arriba, así que no hay entrada del atacante que
llegue a `pickle`.

La segunda comprobación —que el `stoi` del fichero sea igual a nuestra constante— es la que mantiene
honestas las dos copias del vocabulario. Un fichero con el hash correcto y un contenido distinto es
imposible; lo que esta línea atrapa es que alguien edite `VOCAB` en el código.

```python title="src/rukh/eval/karvonen.py"
def ensure_karvonen(download: bool = True, local_dir: Path | str | None = None) -> Path:
    """The checkpoint on disk (downloading it and ``meta.pkl`` when allowed), and its path.

    The Hub repository is somebody else's, so this is not a ``rukh pull`` artefact -- nothing here
    is published by the course, nothing can be. ``huggingface_hub`` caches the 100 MB file once.
    """
    directory = Path(local_dir) if local_dir is not None else paths.resolve(LOCAL_DIR)
    checkpoint = directory / CHECKPOINT_FILE
    meta = directory / "meta.pkl"
    if not checkpoint.is_file():
        if not download:
            raise FileNotFoundError(f"{checkpoint} is not on disk (rukh eval karvonen pulls it)")
        import huggingface_hub

        log.info("downloading %s/%s", HF_REPO, CHECKPOINT_FILE)
        directory.mkdir(parents=True, exist_ok=True)
        huggingface_hub.hf_hub_download(HF_REPO, CHECKPOINT_FILE, local_dir=str(directory))
    if not meta.is_file() and download:
        import urllib.request

        log.info("downloading %s", META_URL)
        with urllib.request.urlopen(META_URL, timeout=60) as response:  # noqa: S310 - https, pinned
            meta.write_bytes(response.read())
    if meta.is_file():
        read_meta(meta)
    return checkpoint
```

## La transcripción, a la letra

```python title="src/rukh/eval/karvonen.py"
def transcript(board: chess.Board) -> str:
    """The game on ``board`` in the author's format: ``;1.e4 e5 2.Nf3`` and, for White, ``3.``.

    When Black is to move the text ends on White's move with no trailing space: the model writes
    the space itself, as it did in training, and a prompt that carried it would be a spelling it
    never saw. Replayed from the root because SAN depends on the position it is written in.
    """
    replay = board.root()
    parts: list[str] = []
    for move in board.move_stack:
        san = replay.san(move)
        parts.append(f"{replay.fullmove_number}.{san}" if replay.turn == chess.WHITE else san)
        replay.push(move)
    if replay.turn == chess.WHITE:
        parts.append(f"{replay.fullmove_number}.")
    return ";" + " ".join(parts)
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="212-227" />

Quince líneas con tres trampas, y las tres son de las que no fallan: producen un prompt razonable que
el modelo responde peor.

**El espacio final.** Cuando le toca a las negras, el texto acaba en la jugada de las blancas **sin
espacio**. El modelo escribe el espacio él mismo, porque así lo vio en el entrenamiento. Un prompt
que ya lo trajera sería una ortografía que nunca vio, y el modelo respondería a otra pregunta. Por
eso `write` acepta que el primer carácter escrito sea un espacio y no lo trata como final de jugada.

**El número de jugada solo delante de las blancas, sin espacio detrás.** `1.e4` y no `1. e4`. Es el
formato del autor y son dos tokens de diferencia en un vocabulario de 32.

**El <Term id="san">SAN</Term> se escribe en su posición.** `replay.san(move)` con el tablero en el
estado **anterior** a la jugada, no después. SAN depende del contexto: `Nbd2` solo se escribe así
donde los dos caballos llegan a d2, y `exd5` necesita saber que hay una captura. Calcularlo sobre el
tablero final daría notaciones que el modelo no reconoce en posiciones donde la ambigüedad ya no
existe.

`board.root()` y no `chess.Board()`: si el tablero empezó en una posición dada por FEN, la raíz es esa
y no la inicial. Aquí casi siempre coinciden, y la función es correcta en el caso en que no.

## El jugador

`KarvonenPlayer` es un `Player` del proyecto: la misma interfaz que usa el decoder para jugar contra
Stockfish, así que entra en `play_rungs` sin adaptadores.

```python title="src/rukh/eval/karvonen.py"
class KarvonenPlayer:
    """A ``rukh.infer.Player`` that writes SAN one character at a time from the transcript.

    Same accounting as ``QwenPlayer`` (``QwenStats``, ``parse_san_answer``, first legal move as the
    fallback and never a second sample), so its failure breakdown is comparable with that row.
    """

    def __init__(
        self,
        model: GPT,
        stats: QwenStats | None = None,
        temperature: float = 0.0,
        top_k: int | None = None,
        seed: int | None = None,
        max_new_chars: int = MAX_NEW_CHARS,
        max_plies: int = DECODER_PLIES,
    ) -> None:
        self.model = model
        self.stats = stats if stats is not None else QwenStats()
        self.temperature, self.top_k, self.max_new_chars = temperature, top_k, max_new_chars
        self.max_plies = max_plies
        self.device = next(model.parameters()).device
        self.generator: torch.Generator | None = None
        if seed is not None:
            self.generator = torch.Generator(device="cpu").manual_seed(seed)

    @property
    def limit(self) -> int:
        """Plies this player can carry: the decoder's number, so every row plays the same game."""
        return self.max_plies

    def start(self, white_elo: int, black_elo: int) -> None:
        """Nothing to set: this model has no rating header, which is part of what it is."""

    def observe(self, move: chess.Move) -> None:
        """Nothing to record: the board carries the history and the transcript is built from it."""
```

partida que se corta antes se adjudica, y adjudicar más veces cambia el resultado.

`torch.Generator(device="cpu")` aunque el modelo esté en GPU: un generador de CPU da la misma
secuencia en cualquier máquina, mientras que uno de CUDA depende de la arquitectura. A temperatura 0
no se usa ninguno; existe para los barridos.

```python title="src/rukh/eval/karvonen.py"
    def _next(self, logits: Tensor) -> int:
        if self.temperature <= 0 or self.top_k == 1:
            return int(logits.argmax())
        logits = logits / self.temperature
        if self.top_k is not None and self.top_k < logits.numel():
            cutoff = torch.topk(logits, self.top_k).values[-1]
            logits = logits.masked_fill(logits < cutoff, -math.inf)
        probs = F.softmax(logits, dim=-1).cpu()
        return int(torch.multinomial(probs, 1, generator=self.generator))

    def write(self, prompt: str) -> str:
        """Characters the model appends to ``prompt``, up to the space that ends the move."""
        ids = [STOI[char] for char in prompt]
        written: list[str] = []
        with torch.no_grad():
            for _ in range(self.max_new_chars):
                window = ids[-self.model.cfg.block_size :]
                logits = self.model(torch.tensor([window], device=self.device))[0, -1]
                char = VOCAB[self._next(logits.float())]
                if char == ";" or (char == " " and "".join(written).strip()):
                    break  # a new game, or the end of the move
                written.append(char)
                ids.append(STOI[char])
        return "".join(written)
```

`_next` es el muestreo de M2 otra vez: <Term id="temperatura">temperatura</Term> y <Term id="top-k">top-k</Term>, con el atajo de `argmax` cuando la temperatura es cero o `top_k` es 1. El atajo no es solo velocidad: dividir por cero explotaría, y `top_k == 1` con `multinomial`
daría el mismo resultado por un camino más caro y con una fuente de aleatoriedad que no hace falta.

La condición de parada de `write` es la línea que merece leerse dos veces:

```
if char == ";" or (char == " " and "".join(written).strip()):
```

Para en el punto y coma porque eso significa que el modelo ha decidido empezar otra partida: para él,
la actual se acabó, y lo que haya escrito antes no es una jugada. Y para en el espacio **solo si ya
ha escrito algo que no es espacio**. Ese `strip()` es el que permite el caso de las negras: el primer
carácter del turno de las negras es el espacio que el modelo escribe él mismo, y tratarlo como fin de
jugada devolvería la cadena vacía siempre que jugaran negras.

`logits.float()` convierte antes de muestrear porque el modelo puede correr en media precisión y
`multinomial` sobre fp16 pierde resolución en la cola. `window = ids[-block_size:]` recorta por la
izquierda: una partida larga en caracteres se sale de las 1023 posiciones del modelo, y quedarse con
las últimas es lo único que se puede hacer con posición absoluta aprendida.

```python title="src/rukh/eval/karvonen.py"
    def answer(self, board: chess.Board) -> str:
        """The raw continuation the model writes for this position."""
        return self.write(transcript(board))

    def propose(self, board: chess.Board) -> tuple[chess.Move | None, str]:
        """What the model wrote, parsed, with the outcome named. No mask, no rescue."""
        move, outcome = parse_san_answer(board, self.answer(board))
        self.stats.record(outcome)
        return move, outcome

    def choose(self, board: chess.Board) -> tuple[chess.Move | None, bool]:
        """The move to play and whether its own answer was usable; ``QwenPlayer``'s rule exactly."""
        move, _ = self.propose(board)
        if move is not None:
            return move, True
        legal = list(board.legal_moves)
        return (legal[0] if legal else None), False
```

Tres métodos en capas, y la separación es deliberada. `propose` mide: devuelve lo que el modelo
propuso y lo apunta en las estadísticas, sin rescatar nada. `choose` juega: si la propuesta no sirve,
toma la primera jugada legal para que la partida siga, y devuelve `False` para que quien cuente sepa

el decoder. Y es la correcta aquí por una razón de comparabilidad: es exactamente lo que hace

desglose de fallos se lee en la misma escala.

## Los puzles: reconstruir la partida que el modelo no puede leer

Un puzle llega como una posición FEN y la historia vive solo en los tokens que lee el decoder. Este
modelo no sabe leer un FEN: una transcripción que empieza en la jugada 23 sin ninguna jugada delante
es un texto que nunca vio.

```python title="src/rukh/eval/karvonen.py"
def prefix_board(board: chess.Board, history: list[int], tok: Any) -> chess.Board:
    """``board`` with the real game in front of it, rebuilt from the decoder's prompt ids.

    A puzzle board starts from a FEN and its history lives only in the tokens the decoder reads.
    This model cannot read a FEN at all -- a transcript that begins at move 23 with no moves is
    text it never saw -- so the game is replayed from the UCI tokens and used when it reaches the
    puzzle's position. When it does not (a line-only parquet), the board is returned as it is and
    the caller counts that the model played blind.
    """
    replay = chess.Board()
    for token in tok.decode(history):
        if token.startswith("<"):
            continue
        try:
            replay.push_uci(token)
        except ValueError:
            return board
    same = replay.fen().split(" ")[:4] == board.fen().split(" ")[:4]
    return replay if same else board


class KarvonenSource:
    """The ``MoveSource`` the puzzle suite expects; ``blind`` counts the prompts with no game."""

    def __init__(self, player: KarvonenPlayer, tok: Any) -> None:
        self.player, self.tok = player, tok
        self.blind = 0

    def __call__(self, board: chess.Board, history: list[int]) -> chess.Move | None:
        prompted = prefix_board(board, history, self.tok)
        if prompted is board:
            self.blind += 1
        move, _ = self.player.choose(prompted)
        return move


def karvonen_source(player: KarvonenPlayer, tok: Any) -> KarvonenSource:
    """Puzzles are scored on the move the model *chooses*, fallback included, as for Qwen."""
    return KarvonenSource(player, tok)
```

<Src file="src/rukh/eval/karvonen.py" tag="p6" lines="311-349" />

La traducción entre los dos mundos es `prefix_board`: coge los identificadores de token del prompt
del decoder, los decodifica a UCI, los reproduce en un tablero desde el principio, y comprueba que la
posición a la que llega es la del puzle.

**La comprobación es lo importante.** `replay.fen().split(" ")[:4] == board.fen().split(" ")[:4]`
compara los cuatro primeros campos del FEN: piezas, turno, enroques y al paso. Deja fuera los dos
contadores —la regla de las 50 jugadas y el número de jugada—, que pueden diferir legítimamente sin
que la posición sea otra. Si la comparación falla, se devuelve el tablero original **sin inventarse
nada**, y quien llama cuenta ese caso.

**`prompted is board` como señal.** La identidad del objeto es lo que distingue «se reconstruyó» de
«no se pudo»: no hace falta un segundo valor de retorno ni una excepción, porque la función devuelve
literalmente el mismo objeto que recibió cuando no ha hecho nada. Es un truco pequeño y legible, y
el test lo comprueba con `is`.

**`blind` se cuenta y se publica.** Un puzle respondido a ciegas es una respuesta casi segura a una
pregunta imposible. Si el parquet de puzles no trae el prefijo de la partida, el porcentaje de
aciertos de este modelo es **un suelo**, no una medición, y esa frase acaba en las notas del
resultado. Esconder el conteo sería publicar una tasa baja como si midiera al modelo.

<Transfer concept="Los datos que un sistema no puede leer" where="Cualquier evaluación que compara modelos con interfaces distintas: uno que ve imágenes y otro que ve su descripción, uno con memoria y otro sin ella.">
  Cuando dos sistemas no aceptan la misma entrada, hay tres opciones: traducir la entrada al formato
  de cada uno, empobrecer la de todos hasta el mínimo común, o medir a cada uno como puede y decir
  qué le faltó. La primera es la que se hace aquí con `prefix_board`, y es la mejor cuando la
  traducción no pierde nada. La tercera es lo que se hace cuando la traducción falla, y exige la
  disciplina de contar los casos: **un número sin el conteo de lo que no se pudo traducir mide otra
  cosa**.

La segunda —bajar a todos al mínimo— parece la más justa y casi nunca lo es: quitarle al decoder la
cabecera de Elo para igualarlo con este modelo empeoraría nuestra medida sin mejorar la suya, y la
comparación resultante no describiría a ninguno de los dos como se usa.

</Transfer>

un modelo que ha perdido el hilo del formato. «SAN ambiguo» es `Nd2` donde dos caballos llegan, que
es un fallo de precisión y no de comprensión. «No escribió nada» es el modelo decidiendo que la
partida acabó. Un solo porcentaje de legalidad los mete a los cuatro en el mismo saco.

`share()` devuelve `"n/a"` cuando no se preguntó nada, en vez de dividir por cero. La misma regla de

```python title="tests/unit/test_karvonen.py"
class _Scripted(nn.Module):
    """A stand-in for the network that writes a fixed string, one character per call."""

    def __init__(self, text: str) -> None:
        super().__init__()
        self.cfg = TOY
        self.script = list(text)
        self.dummy = nn.Parameter(torch.zeros(1))

    def forward(self, idx: Tensor) -> Tensor:
        logits = torch.full((1, idx.shape[1], 32), -10.0)
        char = self.script.pop(0) if self.script else " "
        logits[0, -1, STOI[char]] = 10.0
        return logits


def test_writing_stops_at_the_space_that_ends_the_move() -> None:
    assert KarvonenPlayer(_Scripted("Nf3 Nc6 3.")).write(";1.e4 e5 2.") == "Nf3"
    # Black's move starts with the space the model writes itself; the second space ends it.
    assert KarvonenPlayer(_Scripted(" e5 2.Nf3")).write(";1.e4") == " e5"
    # A new game delimiter means the model thinks the game is over: nothing was written.
    assert KarvonenPlayer(_Scripted(";1.e4")).write(";1.e4 e5 2.") == ""
    # A cap, so a model that never writes a space cannot run for ever.
    assert KarvonenPlayer(_Scripted("a" * 40), max_new_chars=5).write(";1.") == "aaaaa"
```

## Qué has aprendido

Un baseline público no es un número copiado de un paper: es un modelo ajeno traído a tu instrumento.
Y traerlo bien cuesta dos ficheros, porque hay que reproducir **su** formato a la letra y medirlo con
**tu** código sin excepciones.

Las decisiones que se repiten fuera del ajedrez son tres. Reimplementar en vez de importar cuando lo
que se importaría es un repositorio de entrenamiento. Fijar por hash lo que se descarga y validarlo
antes de deserializarlo. Y contar explícitamente lo que el modelo ajeno **no** pudo responder —los
puzles a ciegas, la cabecera que no tiene— porque un porcentaje sin ese conteo mide otra cosa.

La lección siguiente junta las doce etapas en un solo comando y una sola fecha.

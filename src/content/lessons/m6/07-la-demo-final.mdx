## Qué vas a construir

La demo es donde el proyecto juega en público. La de M5 tenía una pantalla: cargas un modelo y juegas
contra él. La de este hito tiene tres modos sobre la misma pantalla, y deja de ser solo de quien
escribió el curso:

- Arena: dos etapas se cargan en dos workers y juegan por parejas con los colores espejados desde
  una apertura aleatoria con semilla. El marcador se convierte en una diferencia de Elo con su
  intervalo bootstrap, con la misma aritmética que `rukh eval match` de M5, y al lado se imprime
  cuántas partidas harían falta para separar una diferencia de ese tamaño del cero.
- Puzles: los 150 que exporta `labs/m6/puzzles_export.py`, preguntados como los pregunta el harness
  (con el prefijo real de la partida y los Elo) y contados con su criterio: la línea entera.
- Posición compartible: `?fen=` abre el tablero en una posición, para que una lección enlace a un
  puesto concreto.
- Y tu propio modelo: un campo que acepta el `artifacts/onnx/small/model-int8.onnx` que exportaste en
  el lab 5 de M2, sin subirlo a ninguna parte.

El código vive en el otro repositorio, `rukh-web`, en el commit
[`b0bf7af`](https://github.com/borja-glez/rukh-web/tree/b0bf7af). Las decisiones están en `src/lib/`;
las islas de Preact (`Arena.tsx`, `Puzzles.tsx`) solo orquestan esas funciones y dibujan el
resultado.

```ts title="src/lib/query.ts"
export function parseQuery(
  search: string,
  fallback = defaultStageId(detectConditions()),
  encoderFallback = defaultEncoderId(detectConditions()),
): Query {
  const params = new URLSearchParams(search.startsWith('?') ? search.slice(1) : search);
  const requested = params.get('stage') ?? fallback;
  const stage = findStage(requested) ?? findStage(fallback);
  const mock = params.get('mock') === '1' || stage === undefined || stage.kind === 'mock';
  const encoder = findEncoderStage(params.get('encoder') ?? encoderFallback);
  const mode = params.get('mode');
  const vs = params.get('vs');
  return {
    mock,
    stage: mock ? 'mock' : (stage?.id ?? fallback),
    encoder: encoder?.id ?? encoderFallback,
    color: params.get('color') === 'b' ? 'b' : 'w',
    mode: mode !== null && (MODES as readonly string[]).includes(mode) ? (mode as Mode) : 'play',
    fen: validFen(params.get('fen')),
    vs: vs !== null && findStage(vs) ? vs : null,
  };
}

/** `fen` when chess.js accepts it as a position, else null. */
export function validFen(fen: string | null): string | null {
  if (!fen) return null;
  try {
    return new Chess(fen).fen();
  } catch {
    return null;
  }
}
```

La forma es la que conviene copiar: cada parámetro se valida contra lo que existe y cae a un valor por
defecto cuando no. `?mode=cocina` abre el modo de jugar, `?vs=nada` deja la arena sin segunda etapa
y un `?fen=` con basura se ignora. Nunca una excepción ni una pantalla en blanco.

`validFen` valida construyendo: le da la cadena a `chess.js` y devuelve el FEN normalizado, o `null`
si el constructor protesta. Una expresión regular para un <Term id="fen">FEN</Term> es un error
clásico, porque dos de sus seis campos dependen de la posición. Y como lo que entra en el estado es la
salida de `chess.js` y no el texto del usuario, dos enlaces con la misma posición escrita de dos
formas dan el mismo estado y `?fen=` no puede hacer daño.

## La arena: la aritmética de M5, portada a TypeScript

{/* prettier-ignore */}
```ts title="src/lib/arena.ts"
/**
 * Arena: two stages play each other in the browser, and the difference is read off the games.
 *
 * The arithmetic is `rukh.eval.match` (M5) ported line for line: every opening is played twice
 * with the colours swapped, the score is A's points over both games, the Elo difference is
 * `400·log10(p / (1 - p))` and its interval comes from a bootstrap over the games. A match
 * measures a **difference** and nothing else: there is no third party here whose mood has to be
 * averaged (D-110), and the number is not a strength.
 *
 * Everything here is pure, so `tests/arena.test.ts` can pin the numbers against the Python
 * implementation without a model in sight.
 */
```

```ts title="src/lib/arena.ts"
/** How many plies the random openings have; six, as `rukh eval match` does by default. */
export const OPENING_PLIES = 6;
/** A game that reaches this many plies without a result counts as a draw, and is marked cut. */
export const MAX_PLIES = 300;

/** A small, seeded PRNG so a run with the same seed plays the same openings. */
export function mulberry32(seed: number): () => number {
  let state = seed >>> 0;
  return () => {
    state = (state + 0x6d2b79f5) >>> 0;
    let t = state;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

/** A random legal opening of `plies` moves in UCI; retried when it ends the game early. */
export function randomOpening(random: () => number, plies = OPENING_PLIES): string[] {
  for (;;) {
    const chess = new Chess();
    const moves: string[] = [];
    for (let i = 0; i < plies; i += 1) {
      const legal = chess.moves({ verbose: true });
      if (legal.length === 0) break;
      const pick = legal[Math.floor(random() * legal.length)];
      chess.move(pick);
      moves.push(`${pick.from}${pick.to}${pick.promotion ?? ''}`);
    }
    if (moves.length === plies && !chess.isGameOver()) return moves;
  }
}

/** `pairs` openings, each to be played twice with the colours swapped. */
export function openingBook(pairs: number, seed: number, plies = OPENING_PLIES): string[][] {
  const random = mulberry32(seed);
  return Array.from({ length: pairs }, () => randomOpening(random, plies));
}
```

<Src file="src/lib/arena.ts" repo="rukh-web" tag="b0bf7af" lines="15-52" />

`mulberry32` es un generador con semilla, porque una arena con la misma semilla tiene que jugar las
mismas aperturas; si no, ni una lección podría prometer lo que se va a ver. JavaScript no trae uno, y
cabe en diez líneas.

`randomOpening` es un rechazo-y-reintento: si las seis jugadas al azar acaban la partida (mate del
pastor incluido), se sortea otra. Un contador de intentos protegería de un caso que no va a ocurrir.
`openingBook` saca todas las aperturas de un solo generador sembrado, así que la quinta apertura de la
semilla 1 es siempre la misma y pedir más parejas no cambia las anteriores.

<Src file="src/lib/arena.ts" repo="rukh-web" tag="b0bf7af" lines="54-81" />

La propiedad del emparejamiento está en el comentario de `index`: el juego `2k` tiene a A con blancas
en la apertura `k`, y el `2k+1` cambia los colores sobre la misma apertura. Así sale la ventaja de
las blancas de la comparación, y por eso se cuenta por parejas.

`cut` cuenta aparte las partidas que llegan a 300 <Term id="ply">plies</Term> sin resultado: para el
marcador son tablas, pero «nadie supo ganar» y «se agotó el contador» no dicen lo mismo del modelo.
`separated` es la regla de M5 metida en un campo: si el intervalo contiene el cero, no hay diferencia
demostrada, y la pantalla lo dice con palabras y no solo con un color.

```ts title="src/lib/arena.ts"
/** Elo difference that explains a score, clipped away from 0 and 1 as the harness does. */
export function eloDifference(score: number): number {
  const p = Math.min(Math.max(score, 0.001), 0.999);
  return 400 * Math.log10(p / (1 - p));
}

/**
 * Percentile bootstrap of the Elo difference over the games (`samples` resamples, seeded).
 * The same estimator as `rukh.eval.match.bootstrap_interval`: resample games with replacement,
 * recompute the score, convert.
 */
export function bootstrapElo(
  scores: readonly number[],
  samples = 500,
  seed = 0,
): { low: number; high: number } | null {
  if (scores.length < 2) return null;
  const random = mulberry32(seed);
  const draws: number[] = [];
  for (let s = 0; s < samples; s += 1) {
    let total = 0;
    for (let i = 0; i < scores.length; i += 1) {
      total += scores[Math.floor(random() * scores.length)];
    }
    draws.push(eloDifference(total / scores.length));
  }
  draws.sort((a, b) => a - b);
  const at = (q: number) => draws[Math.min(draws.length - 1, Math.floor(q * draws.length))];
  return { low: at(0.025), high: at(0.975) };
}
```

<Src file="src/lib/arena.ts" repo="rukh-web" tag="b0bf7af" lines="83-112" />

El recorte de `p` a `[0,001, 0,999]` merece pararse. El Elo a partir de una proporción es
`400·log10(p / (1 − p))`, infinito en `p = 1`: quien gana todas las partidas no tiene una puntuación
identificable, solo una cota. Recortar da un número grande y finito, y es el mismo recorte que hace el
harness de Python; por eso vive aquí y no en la capa de presentación.

El <Term id="bootstrap">bootstrap</Term> es el de M5: se remuestrean las partidas (no las jugadas)
con reemplazo, se recalcula el marcador y se toman los percentiles 2,5 y 97,5 de 500 remuestreos. Con
veinte partidas, pasar de 500 a 1000 cambia decimales y cuesta el doble en el hilo principal.

```ts title="src/lib/arena.ts"
export function summarize(games: readonly ArenaGame[], seed = 0): ArenaSummary {
  const scores = games.map((game) => game.score);
  const points = scores.reduce((sum, value) => sum + value, 0);
  const score = games.length > 0 ? points / games.length : 0;
  const interval = bootstrapElo(scores, 500, seed);
  return {
    games: games.length,
    score,
    wins: scores.filter((value) => value === 1).length,
    draws: scores.filter((value) => value === 0.5).length,
    losses: scores.filter((value) => value === 0).length,
    cut: games.filter((game) => game.cut).length,
    elo: games.length > 0 ? eloDifference(score) : null,
    low: interval?.low ?? null,
    high: interval?.high ?? null,
    separated: interval !== null && (interval.low > 0 || interval.high < 0),
  };
}

/** The result of a finished game from A's point of view, given who had White. */
export function scoreFor(result: string | null, aWhite: boolean): number {
  if (result === '1-0') return aWhite ? 1 : 0;
  if (result === '0-1') return aWhite ? 0 : 1;
  return 0.5;
}

/** How many games the match needs to call an edge of `elo` points at 95 % (`labs/m5`). */
export function gamesNeeded(elo: number): number {
  const p = 1 / (1 + 10 ** (-Math.abs(elo) / 400));
  const z = 1.959963985;
  return Math.ceil((z * z * p * (1 - p)) / (p - 0.5) ** 2);
}
```

`summarize` se llama después de cada partida, así que aguanta listas de cero y de un elemento. La
pantalla muestra el marcador creciendo y el intervalo encogiéndose, que es la mejor forma de ver de
dónde sale un intervalo. `scoreFor` devuelve `0.5` por defecto, para las tablas y para el `null` de
una partida cortada, que cuenta media y se cuenta aparte.

`gamesNeeded` es la función que convierte la demo en una lección:
la <Term id="potencia-estadistica">potencia estadística</Term> de `labs/m5/games_needed_match.py` en el
navegador. Dado un tamaño de efecto en Elo, cuántas partidas hacen falta para que su intervalo del
95 % se separe del cero. Con `(p − 0,5)²` en el denominador, el coste crece con el **cuadrado** de la
precisión: ver 50 Elo pide unas 185 partidas; ver 11, 3 832.

Ese número al lado de un marcador de veinte partidas impide leer diez partidas como un veredicto: es
el intervalo dicho en la unidad en la que duele. Cualquier panel que compare dos variantes (dos
prompts, dos modelos, dos versiones de un producto) gana con esa línea al lado del marcador.

```ts title="src/lib/puzzles.ts"
 * Live puzzles: the harness's puzzle criterion (`rukh.eval.puzzles`), in the browser.

 * A puzzle is attempted the way the table measured it (D-053): the model is prompted with the
```

```ts title="src/lib/puzzles.ts"
/** UCI `e7e8q` as a `Move`. */
export function uciMove(uci: string): Move {
  return {
    from: uci.slice(0, 2),
    to: uci.slice(2, 4),
    promotion: (uci.slice(4, 5) || undefined) as Move['promotion'],
  };
}

/**
 * The game state the puzzle starts from: the real game replayed from the initial position, so
 * the prompt carries the prefix, and the board is the puzzle's FEN. Replaying the prefix must
 * land on that FEN (the first four fields); when it does not, the puzzle is malformed and is
 * skipped rather than attempted from a position the model never reached.
 */
export function puzzleStart(puzzle: Puzzle): GameState | null {
  const chess = new Chess();
  try {
    for (const uci of puzzle.prefix) chess.move(uciMove(uci));
  } catch {
    return null;
  }
  const reached = chess.fen().split(' ').slice(0, 4).join(' ');
  const expected = puzzle.fen.split(' ').slice(0, 4).join(' ');
  if (reached !== expected) return null;
  return {
    start: INITIAL_FEN,
    fen: chess.fen(),
    history: chess.history(),
    turn: chess.turn(),
    over: chess.isGameOver(),
    result: null,
  };
}

/** The moves the model has to find: the odd indices of the line. */
export function expectedMoves(puzzle: Puzzle): string[] {
  return puzzle.moves.filter((_, index) => index % 2 === 1);
}
```

`puzzleStart` es la gemela de `prefix_board` de la lección 3: reproduce la partida desde el principio
y compara los cuatro primeros campos del FEN con los del puzle. Si no coinciden, devuelve `null` y la
interfaz salta el puzle en vez de intentarlo a ciegas, que contaría como fallo del modelo un fallo
del dato.

`expectedMoves` filtra los índices impares porque en Lichess `moves[0]` es la jugada del rival que
plantea el puzle. Un `index % 2 === 1` sin comentario parece arbitrario, y es la mitad del criterio.

```ts title="src/lib/puzzles.ts"
export interface PuzzleAttempt {
  id: string;
  band: Band;
  rating: number;
  solved: boolean;
  /** Model moves that matched before the first miss. */
  correct: number;
  total: number;
  /** What the model proposed at the first miss (UCI), and what the line expected. */
  proposed: string | null;
  expected: string | null;
}

export interface BandProgress {
  band: Band;
  attempted: number;
  solved: number;
}

export function progressByBand(attempts: readonly PuzzleAttempt[]): BandProgress[] {
  return BANDS.map((band) => {
    const own = attempts.filter((attempt) => attempt.band === band);
    return { band, attempted: own.length, solved: own.filter((a) => a.solved).length };
  });
}

/** `12,3 %`-style rate, or an em dash before anything was attempted. */
export function rate(solved: number, attempted: number): string {
  if (attempted === 0) return '—';
  return `${((100 * solved) / attempted).toFixed(1).replace('.', ',')} %`;
}
```

```ts title="src/lib/byo.ts"
 * who has just finished lab 5 of M2 has their own `artifacts/onnx/small/model-int8.onnx` and no

 * page could restore by itself is a model a link could ask it to restore.

 * refuses a graph whose logits are not the tokenizer's 2030 moves wide. A `.onnx` that is not a
```

Cuatro decisiones, una por párrafo del docstring:

- «La mitad equivocada del objetivo»: la demo servía los modelos del curso, y quien acaba el lab 5
  de M2 tiene su propio `.onnx` y no podía jugar contra él, que es lo que querría hacer en ese
  momento.
- Nada sale del navegador, por construcción. No hay `fetch`, así que no hay `connect-src` que
  ensanchar; no hay Cache API, así que nada queda en disco; los bytes van del selector de ficheros al
  worker como _transferible_. Un test de extremo a extremo comprueba que cargar y jugar un modelo
  local produce cero peticiones de `.onnx`.
- La etapa local no se recuerda al recargar, por seguridad: un modelo que la página pudiera restaurar
  sola es uno que un enlace preparado podría pedirle que restaure. El precio es volver a elegir el

- Lo que rechaza un fichero malo ya estaba escrito: el contrato de M2 exige los logits de las 2030
  jugadas del tokenizador, así que un `.onnx` que no es un decoder de Rukh falla por su nombre. Aquí

```ts title="src/lib/byo.ts"
/** `model-int8.onnx` -> `model-int8.onnx`, and a hostile name to something safe to render. */
export function safeName(name: string): string {
  /* Preact escapes what it renders, so this is not about injection: it is about a 300-character
     name breaking the panel, and about control characters making the label unreadable. Written
     as a filter rather than a character class of control codes, which is exactly what
     `no-control-regex` exists to flag and where the rule is right to ask. */
  const clean = [...name]
    .filter((ch) => {
      const code = ch.codePointAt(0) ?? 0;
      return code > 0x1f && (code < 0x7f || code > 0x9f);
    })
    .join('')
    .trim();
  const base = clean.split(/[\\/]/).pop() ?? clean;
  return base.length > 48 ? `${base.slice(0, 45)}…` : base || 'modelo.onnx';
}
```

```ts title="src/lib/byo.ts"
 * The context window is read out of the file when the exporter wrote it there, and falls back to
```

```ts title="src/lib/byo.ts"
/*
 * Reading `rukh_block` out of the file.
 *
 * `rukh export` writes the context window into the ONNX `metadata_props`, and ORT Web does not
 * expose them (see `contract.ts`), which is why registry stages carry `block` by hand. A file
 * from somebody's disk has no registry entry, so the number has to come from the file.
 *
 * An ONNX file is a protobuf `ModelProto`. Walking its top-level fields is enough: every field is
 * a varint tag followed by either a varint or a length-delimited block, so the graph — the big
 * one — is skipped by advancing past its length without decoding any of it. No protobuf library,
 * no allocation, and it stops as soon as it finds the key.
 */

/** `metadata_props` in `ModelProto`; `key` and `value` in `StringStringEntryProto`. */
const METADATA_PROPS_FIELD = 14;
const KEY_FIELD = 1;
const VALUE_FIELD = 2;
const BLOCK_KEY = 'rukh_block';

interface Cursor {
  bytes: Uint8Array;
  at: number;
}

/** A protobuf varint, or null when it runs off the end or is implausibly long. */
function varint(c: Cursor): number | null {
  let result = 0;
  let shift = 0;
  while (c.at < c.bytes.length) {
    const byte = c.bytes[c.at];
    c.at += 1;
    result += (byte & 0x7f) * 2 ** shift;
    if ((byte & 0x80) === 0) return result;
    shift += 7;
    if (shift > 49) return null;
  }
  return null;
}
```

<Src file="src/lib/byo.ts" repo="rukh-web" tag="b0bf7af" lines="121-158" />

Aquí está la pieza más curiosa del hito: un lector que saca un campo de un protobuf sin una librería
de protobuf.

`rukh export` escribe la ventana de contexto en los metadatos del `.onnx`, y ONNX Runtime Web no los
expone; por eso las etapas publicadas llevan su `block` escrito en el catálogo de la demo. Un fichero
de tu disco no tiene entrada en ese catálogo, así que el número tiene que salir del fichero.

Un `.onnx` es un `ModelProto` de protobuf, y para leer un campo de primer nivel no hace falta entender
el formato entero: cada campo es un tag _varint_ seguido de un valor, y el tipo de cable del tag dice
cuánto ocupa. El grafo, los 232 MB, se salta avanzando su longitud sin decodificar nada. Es hojear
un libro en el que cada capítulo empieza diciendo cuántas páginas tiene: saltas de portada en
portada sin leer nada más hasta dar con el que buscas. La alternativa era meter `protobufjs` en el bundle, cientos de kilobytes para leer un entero.

`varint` usa `* 2 ** shift` y no `<< shift`, y esa línea hay que mirarla dos veces: los
desplazamientos de JavaScript trabajan sobre 32 bits con signo, y a partir de 32 dan la vuelta en
silencio. Multiplicar por una potencia de dos es exacto hasta 2⁵³. `shift > 49` corta un varint que no
puede ser un número plausible. Y todo el lector devuelve `null` en vez de lanzar: si el fichero no es
lo esperado, no se sabe el `block` y se usa el 200 por defecto, en vez de una pantalla roja.

```ts title="src/lib/byo.ts"
/** The `StringStringEntryProto` at `[at, end)`, as a key/value pair. */
function entry(bytes: Uint8Array, at: number, end: number): { key: string; value: string } | null {
  const c: Cursor = { bytes, at };
  let key = '';
  let value = '';
  const decoder = new TextDecoder();
  while (c.at < end) {
    const tag = varint(c);
    if (tag === null) return null;
    const field = tag >>> 3;
    const wire = tag & 7;
    if (wire !== 2) {
      if (varint(c) === null) return null;
      continue;
    }
    const length = varint(c);
    if (length === null || c.at + length > end) return null;
    const text = decoder.decode(bytes.subarray(c.at, c.at + length));
    c.at += length;
    if (field === KEY_FIELD) key = text;
    else if (field === VALUE_FIELD) value = text;
  }
  return { key, value };
}
```

`tag >>> 3` es el número de campo y `tag & 7` el tipo de cable (aquí `>>>` es seguro, el tag es
pequeño). `bytes.subarray(...)` es una vista sin copia, que en 232 MB importa. Y `c.at + length > end`
en cada lectura de longitud impide que un fichero manipulado haga leer fuera del bloque: el peor caso
pasa de una cadena basura a un `null`.

```ts title="src/lib/byo.ts"
/** The `rukh_block` the exporter wrote, or null when the file does not carry one. */
export function readBlock(bytes: Uint8Array): number | null {
  const c: Cursor = { bytes, at: 0 };
  while (c.at < bytes.length) {
    const tag = varint(c);
    if (tag === null) return null;
    const field = tag >>> 3;
    const wire = tag & 7;

    if (wire === 0) {
      if (varint(c) === null) return null;
      continue;
    }
    if (wire === 5) {
      c.at += 4;
      continue;
    }
    if (wire === 1) {
      c.at += 8;
      continue;
    }
    if (wire !== 2) return null;

    const length = varint(c);
    if (length === null || c.at + length > bytes.length) return null;
    if (field === METADATA_PROPS_FIELD) {
      const pair = entry(bytes, c.at, c.at + length);
      if (pair && pair.key === BLOCK_KEY) {
        const block = Number.parseInt(pair.value, 10);
        return Number.isInteger(block) && block > 0 && block <= 8192 ? block : null;
      }
    }
    c.at += length;
  }
  return null;
}
```

<Src file="src/lib/byo.ts" repo="rukh-web" tag="b0bf7af" lines="185-220" />

Los cuatro tipos de cable se tratan uno a uno (`0` varint, `5` cuatro bytes, `1` ocho, `2` bloque con
longitud); cualquier otro no es protobuf válido. El bucle solo entra en `entry` para el campo 14,
`metadata_props`, y para al encontrar la clave. Un `rukh_block` fuera de `(0, 8192]` se trata como
ausente: un `block` de mil millones no recortaría el prompt y el grafo fallaría con un error de forma.
Y el panel imprime bajo qué `block` juega la etapa, porque un valor por defecto es tolerable cuando se
ve.

    también un `LocalModel` para uno de los dos lados y pasarle los bytes al segundo worker. Es el
    mismo camino de `init` con `bytes` que ya existe. El problema de la aritmética no es del código:
    con veinte partidas el intervalo cubre varios cientos de Elo, y `gamesNeeded` lo dice en la
    pantalla. Enfrentar tu int8 contra el fp16 del curso y leer «no se ha medido una diferencia» es el
    resultado correcto, y es el mismo que la escalera dio en el lab 3 con 160 partidas.
  </Solution>
</Exercise>

<Exercise n="02" title="Rompe el lector de protobuf de la forma sutil">
  Cambia `result += (byte & 0x7f) * 2 ** shift` por `result |= (byte & 0x7f) << shift`. Los tests
  pasan. ¿Con qué fichero falla, y por qué es peor que un error?

  <Solution>
    Falla con cualquier campo cuya longitud pase de 2³¹, es decir con un grafo de más de 2 GB, y
    también con cualquier varint de cinco bytes o más: `<<` opera sobre 32 bits con signo, así que un
    `shift` de 28 en adelante da la vuelta y produce un entero negativo o pequeño. Lo que sale no es
    una excepción: es una longitud equivocada, con la que el bucle avanza el cursor a un sitio
    arbitrario y sigue leyendo tags que no son tags. El resultado más probable es un `null`
    y un `block` de 200 por defecto que puede ser el correcto por casualidad, así que el error se
    manifiesta como un prompt mal recortado en un modelo concreto. Los tests con ficheros pequeños no
    lo ven, y ahí está la trampa.
  </Solution>
</Exercise>

## Qué has aprendido

Una demo es donde se comprueba si lo que mediste significa algo para alguien que no lo midió, y para
eso la pantalla tiene que hacer el mismo cálculo: la fórmula del Elo con el mismo recorte, el
bootstrap sobre las mismas unidades, el criterio del puzle con el mismo prefijo. Un número del
navegador que no se compara con la tabla es un adorno.

Dos decisiones de diseño sirven fuera del ajedrez. Una entrada nueva a un sistema que ya valida se
empalma lo antes posible con el camino existente, y hereda las guardas (una línea de `??` en el
worker). Y la privacidad se construye quitando capacidades: sin `fetch` no hay nada que ensanchar,
sin almacenamiento nada que restaurar, y un test que cuenta cero peticiones es una afirmación
comprobable.

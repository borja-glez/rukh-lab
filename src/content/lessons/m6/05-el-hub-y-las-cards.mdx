## Qué vas a construir

Cuatro ficheros nuevos y un puñado de cambios que cierran el círculo del proyecto: lo que se
entrena se publica, lo que se publica se puede volver a bajar exactamente donde las configuraciones
lo esperan, y lo que dice cada card se puede contradecir con lo que hay dentro.

`hub.py` es el **catálogo**: la lista de todo lo que el curso publicó, con su repositorio, su ruta
local, los módulos que empiezan desde ahí, la fila que lleva en la tabla y cómo se mide. De esa
lista tiran cuatro cosas distintas —`rukh pull`, `rukh eval nightly`, `rukh publish cards` y
`rukh publish collection`—, y que sea una sola lista es lo que impide que las cuatro se separen.

`publish/cards.py` regenera las veintiuna cards desde lo que hay en disco y sube **solo** el
`README.md`. `publish/collection.py` monta la colección del Hub desde el mismo catálogo.
`publish/links.py` es lo que hace que cada card enlace a su lección, a su fila y a la demo.

<Callout kind="hoy" title="El que hace falta y no se puede automatizar">
  Todo lo de esta lección habla con Hugging Face. Para que funcione hace falta un token con permiso
  de escritura en `huggingface-cli login`, y todos los comandos tienen `--dry-run` precisamente
  porque la mitad de las veces lo que quieres es ver qué haría.
</Callout>

## El catálogo: una lista, cuatro consumidores

```python title="src/rukh/hub.py"
"""``rukh pull``: the published artefacts of a module, written where the configs expect them.

Every model of the course is on the Hub in the Hub's own layout -- ``config.json`` plus
``model.safetensors``, or a ``peft`` folder -- and every dataset under its own name. The
configs and the lessons, on the other hand, read files at fixed local paths:
``checkpoints/medium-v4/best.pt``, ``data/pairs/dpo-prompts.parquet``. This module maps one
onto the other, so a reader who skipped a module, or a machine that never trained anything, can
start the next module from exactly what was published, with one command:

    uv run rukh pull --module m4        # everything M4 starts from
    uv run rukh pull medium-v4 rukh-pairs-dpo

The local path of a model is its **run name** (``checkpoints/<run>/<file>``), the same spelling
``rukh.train.checkpoint.resolve_run`` accepts for a run the reader trained themselves. A pulled
model is therefore indistinguishable, to every config, from one trained locally.

Nothing here decides what is worth publishing; ``rukh publish`` does that. This is the way back.
"""
```

La frase que carga con todo es la penúltima: **un modelo descargado es indistinguible, para
cualquier configuración, de uno entrenado en local**. Eso es lo que convierte el curso en algo que
se puede seguir por partes. Un lector que se saltó M2 entera puede empezar M4 con un comando, y la
orden que la lección de M4 le pide escribir es exactamente la misma que escribiría si hubiera
entrenado el modelo él.

Conseguirlo tiene dos mitades. Esta, que escribe el fichero en la ruta estable; y `resolve_run`, en
la lección siguiente, que hace que esa ruta estable también encuentre la carpeta con marca de
tiempo que deja un entrenamiento propio.

```python title="src/rukh/hub.py"
Kind = Literal["decoder", "encoder", "reward", "adapter", "peft", "dataset"]
OWNER = "chorcat"


@dataclass(frozen=True)
class Artefact:
    """One thing ``rukh pull`` knows how to bring back, and where it lands."""

    name: str
    """What the reader types: the run or stage name of a model, the Hub name of a dataset."""
    repo: str
    kind: Kind
    target: str
    """Path under the repository root: the checkpoint file, the adapter folder or the data dir."""
    modules: tuple[str, ...]
    """The modules that start from this artefact when the reader skipped what produced it."""
    note: str
    stage: str | None = None
    """Its row in the single results table, when it has one; ``rukh eval nightly`` measures it
    under that name so the row it rewrites is the row the cards and the course already cite."""
    measure: Literal["decoder", "encoder", "qwen", "karvonen", "none"] = "none"
    """How ``nightly`` measures it: the decoder suite (adapters are merged onto their base
    first), the encoder suite, the general-model suite, the public-baseline suite (an entry
    ``nightly`` adds itself, since the weights are not the course's to pull or publish), or not
    at all (datasets, the reward model, the pretraining encoder)."""
    base: str | None = None
    """For an adapter: the checkpoint it is merged onto before it is measured."""
    lesson: str | None = None
    """Path of the course lesson that builds it, for the card's "In the course" section."""

    @property
    def repo_id(self) -> str:
        return self.repo if "/" in self.repo else f"{OWNER}/{self.repo}"
```

Nueve campos, y cada uno existe porque un consumidor distinto lo necesita. `target` y `kind` son de
`pull`. `modules` es de `--module`. `stage` y `measure` y `base` son del nightly de la lección
anterior. `lesson` es de las cards. `note` es de `--list`.

Que estén todos en el mismo objeto, y no repartidos en cuatro diccionarios paralelos, es la
decisión. Cuatro diccionarios con las mismas claves se desincronizan el día que se añade un modelo y
se olvida uno de ellos, y el síntoma es una card sin lección o una etapa sin medir.

`@dataclass(frozen=True)`: el catálogo es una constante del programa y congelarlo hace que ningún
consumidor pueda mutar una entrada por accidente y cambiársela al siguiente.

`repo_id` como propiedad y no como campo. El catálogo escribe `"rukh-tiny"` y la propiedad completa
`"chorcat/rukh-tiny"`, salvo que ya venga con barra —que es el caso del baseline de Karvonen, cuyo
`Artefact` vive en `nightly.py` y apunta a `adamkarvonen/chess_llms`. Es lo que permite que el
mismo tipo describa un repositorio nuestro y uno ajeno.

Una nota de lectura: la distinción entre `name` y `stage` es la misma que en el nightly. `name` es lo que se escribe en la terminal (`medium-v4`); `stage` es el
nombre de la fila (`medium-v4-greedy`), con el sufijo del muestreo.

Las ocho restantes. Tres cosas para leerlas:

**`kind` distingue `adapter` de `peft`.** Los dos son adaptadores <Term id="lora">LoRA</Term>, y son
dos formatos distintos: el nuestro son dos ficheros (`adapter.safetensors` y
`adapter_config.json`), el de `peft` es una carpeta entera con la convención de esa librería.
`pull` los trae de forma distinta y por eso son dos tipos.

**`base` solo lo tienen los dos adaptadores nuestros**, no el de Qwen3. Es coherente: el nightly
funde los nuestros sobre `medium-v4` antes de medirlos, mientras que el de Qwen3 lo mide su propia
suite, que carga el modelo base de Hugging Face por su cuenta.

**`rm` no tiene `stage`.** El reward model juzga pares, no juega: no hay ninguna columna de la tabla
que pueda rellenar. Publicarlo sin fila es exactamente lo correcto, y es lo que el `measure="none"`
por defecto hace posible sin una excepción escrita en ningún sitio.

Aquí sí hay dos diccionarios paralelos, y es la excepción que explica la regla de arriba. Los
datasets ya tienen su propia descripción en `DATASETS`, el registro que M1 escribió en
`data/publish.py`: repetirlos enteros aquí sería tener dos verdades sobre el mismo dataset. Lo que
falta son las dos cosas que ese registro no sabe —a qué módulos sirve y en qué lección se construye—
y viven en dos mapas por nombre que `_dataset_artefact` junta con lo demás.

`rukh-elo-bins` con una tupla vacía es un dato interesante y está documentado: es el muestreo de M1
por franjas de 100 Elo que **nadie aguas abajo lee**, porque M4 construyó el suyo. Dejarlo
publicado con cero módulos es más honesto que borrarlo del catálogo: existe, se puede descargar, y
ningún módulo lo necesita.

`spec.description.split(". ")[0]` coge la primera frase de la descripción larga del dataset. Es una
heurística, y es la clase de línea que falla el día que una descripción empiece por «Aprox. 5 M de
partidas»; aquí aguanta porque las ocho descripciones están escritas y revisadas.

```python title="src/rukh/hub.py"
def catalogue() -> list[Artefact]:
    """Every artefact ``rukh pull`` knows, models first and then the datasets."""
    return [*MODELS, *(_dataset_artefact(spec) for spec in DATASETS.values())]


def lookup(name: str) -> Artefact:
    """The artefact called ``name``: a run name, a dataset name or a Hub id."""
    for artefact in catalogue():
        if name in (artefact.name, artefact.repo, artefact.repo_id):
            return artefact
    known = ", ".join(a.name for a in catalogue())
    raise KeyError(f"nothing to pull called {name!r}; known: {known}")


def for_module(module: str) -> list[Artefact]:
    """What a reader who skipped everything before ``module`` needs on disk to start it."""
    return [artefact for artefact in catalogue() if module in artefact.modules]
```

`lookup` acepta tres formas del mismo nombre: la corta, la del repositorio y la completa con el
propietario. Es la misma comodidad del `--only` del nightly, por la misma razón: se escribe lo que
se acaba de leer, y lo que se lee depende de dónde se mire.

El `KeyError` incluye **la lista entera de lo conocido**. Con veintiún artefactos cabe en la
pantalla, y un error que dice qué sí existe ahorra un `--list`.

## La vuelta: del formato del Hub al del proyecto

```python title="src/rukh/hub.py"
def _download(repo_id: str, filename: str) -> Path:
    import huggingface_hub

    return Path(huggingface_hub.hf_hub_download(repo_id, filename))


def _load_state(repo_id: str) -> dict[str, Any]:
    """The weights of a Hub model, whichever of the two names they were published under."""
    import torch

    for name in ("model.safetensors", "pytorch_model.bin"):
        try:
            weights = _download(repo_id, name)
        except Exception as exc:  # noqa: BLE001 - a missing file only means "try the next one"
            log.debug("%s has no %s (%s)", repo_id, name, exc)
            continue
        if name.endswith(".safetensors"):
            from safetensors.torch import load_file

            return dict(load_file(str(weights)))
        return dict(torch.load(weights, map_location="cpu", weights_only=True))
    raise FileNotFoundError(f"{repo_id} holds neither model.safetensors nor pytorch_model.bin")
```

<Src file="src/rukh/hub.py" tag="p6" lines="271-292" />

`safetensors` primero y `pytorch_model.bin` después, en ese orden. El primero es el formato que el
proyecto publica y no ejecuta código al cargarse; el segundo es un `pickle` y se acepta solo porque
un repositorio antiguo podría tenerlo. El orden es la política de seguridad escrita como una tupla.

El `except Exception` de aquí es el caso menos dudoso de los tres del módulo: `hf_hub_download`
levanta excepciones de tipos distintos según la versión de la librería y según si el fallo es un
404, un problema de red o un fichero ausente en la caché, y lo único que este bucle quiere saber es
«no está, prueba el siguiente». El `log.debug` deja rastro para cuando el problema sea de red y no
de nombre.

```python title="src/rukh/hub.py"
def _model_payload(artefact: Artefact, config: dict[str, Any], state: dict[str, Any]) -> dict:
    """Fold a Hub layout back into the checkpoint payload every loader of this project reads.

    ``rukh publish`` writes the model's shape and the run's provenance into ``config.json``;
    this puts them back under the keys ``save_checkpoint`` uses. The heads of an encoder need
    the pooling they were trained with, which the card's config carries and ``build_heads``
    reads from the run config.
    """
    from rukh.models import DecoderConfig, EncoderConfig

    if artefact.kind == "reward":
        return {
            "model": state,
            "encoder_config": config["encoder"],
            "pooling": config.get("pooling"),
            "config": {"pulled_from": artefact.repo_id},
        }
    shape = EncoderConfig if artefact.kind == "encoder" else DecoderConfig
    model_cfg = {key: value for key, value in config.items() if key in shape.model_fields}
    run_cfg: dict[str, Any] = {"pulled_from": artefact.repo_id}
    if artefact.kind == "encoder" and config.get("pooling"):
        run_cfg["pooling"] = config["pooling"]
    return {
        "step": int(config.get("step") or 0),
        "model_state": state,
        "opt_state": None,
        "cfg": run_cfg,
        "model_cfg": model_cfg,
        "vocab_hash": config.get("vocab_hash"),
        "data_manifest_sha": config.get("data_manifest_sha"),
        "git_sha": config.get("git_sha"),
        "best_val": None,
    }
```

<Src file="src/rukh/hub.py" tag="p6" lines="295-327" />

Esta es la función que hace realidad la promesa del docstring. El Hub guarda un modelo como
«configuración más pesos»; el proyecto lo guarda como el `payload` que escribe `save_checkpoint`.
Traducir de uno a otro es lo que permite que `load_model` abra un fichero descargado sin saber que
lo es.

**El filtro por `shape.model_fields`** es la pieza clave. El `config.json` publicado lleva la forma
del modelo **y** la procedencia de la ejecución mezcladas, porque en una card eso se lee junto. Aquí
se separan: lo que es un campo del `DecoderConfig` va a `model_cfg`, el resto se descarta o se
reparte. Escrito así, publicar un campo nuevo en la card no rompe la vuelta.

**`opt_state: None` y `best_val: None` explícitos.** No es que se pierdan: es que **no estaban**. El
publicador quita el optimizador a propósito, y `best_val` es una propiedad de la ejecución que no
viaja. Ponerlos a `None` en vez de omitir las claves hace que el payload tenga siempre la misma
forma y que quien lo lea distinga «no hay» de «esta versión no lo escribía».

**`cfg = {"pulled_from": repo_id}`.** El fichero resultante dice de dónde vino. Es la misma idea que

```python title="src/rukh/hub.py"
def pull(artefact: Artefact, force: bool = False) -> Path:
    """Bring ``artefact`` to its local path and return that path.

    An artefact already on disk is left alone unless ``force``: a reader's own training run,
    sitting at the same stable path, must never be replaced silently by the published one.
    """
    import torch

    target = paths.resolve(artefact.target)
    if target.exists() and not force:
        log.info("%s is already there; --force replaces it", target)
        return target
    if artefact.kind == "dataset":
        import huggingface_hub

        spec = DATASETS[artefact.name]
        target.mkdir(parents=True, exist_ok=True)
        huggingface_hub.snapshot_download(
            artefact.repo_id,
            repo_type=spec.repo_type,
            local_dir=str(target),
            allow_patterns=[*spec.patterns, "manifest.json"],
        )
        return target
    if artefact.kind == "peft":
        import huggingface_hub

        target.mkdir(parents=True, exist_ok=True)
        huggingface_hub.snapshot_download(artefact.repo_id, local_dir=str(target))
        return target
    if artefact.kind == "adapter":
        target.mkdir(parents=True, exist_ok=True)
        for name in ("adapter.safetensors", "adapter_config.json"):
            source = _download(artefact.repo_id, name)
            (target / name).write_bytes(source.read_bytes())
        return target
    config = json.loads(_download(artefact.repo_id, "config.json").read_text(encoding="utf-8"))
    state = _load_state(artefact.repo_id)
    target.parent.mkdir(parents=True, exist_ok=True)
    tmp = target.with_suffix(target.suffix + ".tmp")
    torch.save(_model_payload(artefact, config, state), tmp)
    tmp.replace(target)
    return target
```

Tres decisiones de peso.

**Lo que ya está en disco no se toca.** Es la primera comprobación de la función y tiene una razón
concreta que el docstring dice: en `checkpoints/medium-v4/best.pt` puede estar **tu** entrenamiento.
Un `pull` que lo pisara sin avisar destruiría cuarenta minutos de GPU por escribir un comando de
más. `--force` existe para cuando se quiere justamente eso.

**Escritura atómica.** El modelo se guarda en `best.pt.tmp` y se renombra con `tmp.replace(target)`,
que en todos los sistemas operativos es atómico dentro del mismo volumen. Si el proceso muere a
mitad de una escritura de 460 MB, lo que queda en disco es un `.tmp` inservible y no un `best.pt`
truncado que carga a medias y falla dentro de una hora con un error incomprensible.

**`allow_patterns` en los datasets.** Un repositorio de dataset puede tener más ficheros de los que
el proyecto usa —una vista previa, un `.gitattributes`— y `snapshot_download` sin filtro los trae
todos. Restringirlo a los patrones que declara `DatasetSpec` más el `manifest.json` es lo que hace
que la carpeta descargada sea exactamente la que un `rukh data` habría producido.

Ese `manifest.json` añadido a mano al final de los patrones es el que permite comprobar los hashes
de lo descargado, incluyendo el `dpo-prompts.parquet` que la lección 2 añadió. Y ese fichero entra en

```python title="src/rukh/cli.py"
@app.command("pull")
def pull_cmd(
    names: Annotated[
        list[str] | None,
        typer.Argument(help="Run names, dataset names or Hub ids (see --list)."),
    ] = None,
    module: Annotated[
        str | None,
        typer.Option("--module", help="Pull everything a module starts from, e.g. m4."),
    ] = None,
    list_all: Annotated[
        bool, typer.Option("--list", help="Print the catalogue, by module, and exit.")
    ] = False,
    force: Annotated[
        bool, typer.Option("--force", help="Replace what is already on disk.")
    ] = False,
) -> None:
    """Bring published models and datasets to the paths the configs and the lessons read.

    A pulled model lands under its run name (`checkpoints/medium-v4/best.pt`), which is the
    spelling every config uses and the one a run you trained yourself also answers to.
    """
    from rukh.hub import catalogue, for_module, lookup, pull

    if list_all:
        for artefact in catalogue():
            modules = ",".join(artefact.modules) or "-"
            typer.echo(f"{artefact.name:<24} {modules:<15} {artefact.target}")
            typer.echo(f"{'':<24} {artefact.repo_id:<15} {artefact.note}")
        return
    wanted = []
    if module is not None:
        wanted.extend(for_module(module))
        if not wanted:
            typer.echo(f"error: nothing is catalogued for module {module!r}", err=True)
            raise typer.Exit(code=2)
    try:
        wanted.extend(lookup(name) for name in names or [])
    except KeyError as exc:
        typer.echo(f"error: {exc.args[0]}", err=True)
        raise typer.Exit(code=2) from exc
    if not wanted:
        typer.echo("error: give a name, --module or --list (see rukh pull --help)", err=True)
        raise typer.Exit(code=2)
    logging.basicConfig(level=logging.INFO, format="%(asctime)s  %(message)s")
    for chatty in ("httpx", "huggingface_hub", "urllib3"):
        logging.getLogger(chatty).setLevel(logging.WARNING)  # one line per artefact, not per GET
    for artefact in wanted:
        try:
            path = pull(artefact, force=force)
        except (FileNotFoundError, OSError) as exc:
            typer.echo(f"error: {artefact.name}: {exc}", err=True)
            raise typer.Exit(code=1) from exc
        typer.echo(f"{artefact.name:<24} {artefact.repo_id:<28} -> {path}")
```

`rukh pull` es la **única orden del proyecto que no está en un subgrupo**: está colgada de `app`
directamente, como `info`. La razón es que es la primera orden que escribe alguien que llega al
curso por la mitad, y `rukh hub pull --artefact medium-v4` sería una forma innecesariamente ceremoniosa
de decir `rukh pull medium-v4`.

El bucle que baja el nivel de registro de `httpx`, `huggingface_hub` y `urllib3` a `WARNING` es una
línea de ergonomía con un efecto grande: sin ella, bajar doce modelos imprime una línea por cada
petición HTTP y las doce líneas que interesan se pierden. El comentario dice exactamente eso.

Los tres códigos de salida están separados a propósito: `2` para un uso incorrecto —un nombre que no
existe, un módulo vacío, ningún argumento— y `1` para un fallo de ejecución. Es la convención de
Unix, y la diferencia importa cuando esto corre dentro de un script.

Y un detalle del orden: si se pasan `--module m6` **y** nombres sueltos, se acumulan los dos. No se
deduplica, así que un artefacto pedido dos veces se intenta bajar dos veces; la segunda es
instantánea porque la primera lo dejó en disco y la función se planta en la primera comprobación.

`CardRefresh` tiene la misma forma que `NightlyRecord` de la lección anterior —un registro por
elemento, con estado y detalle— y por la misma razón: un lote donde un elemento puede fallar sin
llevarse a los demás.

```python title="src/rukh/publish/cards.py"
    """Render ``artefact``'s card through its own publisher, in dry-run mode; returns the card."""
    target = resolve_run(paths.resolve(artefact.target))
    if artefact.kind == "dataset":
        from rukh.data.publish import PublishConfig, publish

        result = publish(artefact.name, PublishConfig(owner=cfg.owner), dry_run=True)
        return Path(result.card_path)
    if artefact.kind == "adapter":

        effect_path = paths.resolve(EFFECTS_DIR) / f"{artefact.name}.json"
        effect = (
            AdapterEffect.model_validate_json(effect_path.read_text(encoding="utf-8"))
            if effect_path.is_file()
            else None
```

```python title="src/rukh/publish/cards.py"
def refresh_cards(
    only: set[str] | None = None,
    dry_run: bool = False,
    cfg: ModelPublishConfig | None = None,
    api: Any | None = None,
) -> list[CardRefresh]:
    """Regenerate the card of every repository (or of ``only``); upload it unless ``dry_run``."""
    cfg = cfg or ModelPublishConfig()
    wanted = [a for a in catalogue() if not only or a.name in only or a.repo_id in only]
    client = None
    outcomes: list[CardRefresh] = []
    for artefact in wanted:
        repo_type = (
            "dataset"
            if artefact.kind == "dataset" and artefact.name != "rukh-tokenizer"
            else "model"
        )
        outcome = CardRefresh(
            name=artefact.name, repo_id=artefact.repo_id, repo_type=repo_type, status="staged"
        )
        outcomes.append(outcome)
        try:
            card = stage_card(artefact, cfg)
            outcome.card = card.as_posix()
            if not dry_run:
                client = client or api or _api()
                client.upload_file(
                    path_or_fileobj=str(card),
                    path_in_repo=README_NAME,
                    repo_id=artefact.repo_id,
                    repo_type=repo_type,
                    commit_message="docs(card): regenerated from the current table and course",
                )
                outcome.status = "uploaded"
        except Exception as exc:  # noqa: BLE001 - one card failing must not stop the rest
            log.exception("card of %s failed", artefact.name)
            outcome.status = "failed"
            outcome.detail = f"{type(exc).__name__}: {exc}"
    return outcomes
```

<Src file="src/rukh/publish/cards.py" tag="p6" lines="98-136" />

**`upload_file` y no `upload_folder`.** Es la línea que da nombre al comando: sube un fichero, el
`README.md`, y nada más. Los pesos que están arriba no se tocan, el repositorio no se vuelve a
empaquetar, y el `commit_message` deja escrito en el historial del Hub que ese commit es solo la
card.

**`client = client or api or _api()`** crea el cliente perezosamente y una sola vez. En seco no se
crea nunca, y por eso un `--dry-run` funciona sin haber hecho `login`: si el cliente se construyera
al principio de la función, ver qué haría el comando exigiría un token.

**El parámetro `api`** es la inyección que hace testeable todo esto sin red. El test le pasa un
objeto con un solo método y comprueba con qué argumentos se llamó.

**`repo_type` con su excepción escrita.** `rukh-tokenizer` es un dataset del proyecto que vive en el
Hub como repositorio de **modelo**, porque un tokenizador se publica así. La condición está en dos
sitios —aquí y en `collection.py`— y las dos veces escrita igual; es la clase de duplicación pequeña
que un día se convierte en una discrepancia.

```python title="src/rukh/publish/collection.py"
def collection_items() -> list[tuple[str, str]]:
    """``(repo id, item type)`` for every catalogued artefact, models first, in course order."""
    items: list[tuple[str, str]] = []
    for artefact in catalogue():
        item_type = (
            "dataset"
            if artefact.kind == "dataset" and artefact.name != "rukh-tokenizer"
            else "model"
        )
        if (artefact.repo_id, item_type) not in items:
            items.append((artefact.repo_id, item_type))
    return items


def sync_collection(
    cfg: ModelPublishConfig | None = None, dry_run: bool = False, api: Any | None = None
) -> CollectionSync:
    """Create the collection if it does not exist and add every catalogued repository to it."""
    cfg = cfg or ModelPublishConfig()
    items = collection_items()
    if dry_run:
        return CollectionSync(slug=None, created=False, items=[r for r, _ in items], dry_run=True)
    client = api or _api()
    existing = next((c for c in client.list_collections(owner=cfg.owner) if c.title == TITLE), None)
    created = existing is None
    collection = existing or client.create_collection(
        TITLE, namespace=cfg.owner, description=DESCRIPTION, private=False, exists_ok=True
    )
    for repo_id, item_type in items:
        client.add_collection_item(collection.slug, repo_id, item_type, exists_ok=True)
        log.info("collection %s: %s (%s)", collection.slug, repo_id, item_type)
    return CollectionSync(
        slug=collection.slug, created=created, items=[r for r, _ in items], dry_run=False
    )
```

<Src file="src/rukh/publish/collection.py" tag="p6" lines="41-74" />

**La deduplicación por lista y no por conjunto.** `if (repo_id, item_type) not in items` es O(n²) y
con veintiún elementos da exactamente igual; lo que compra es que **el orden se conserva**, que es el
orden del curso. Un `set` sería más rápido y desordenaría la colección, que es lo único que esta
función produce.

**Idempotencia por `exists_ok`, no por comprobación previa.** La alternativa sería listar lo que la
colección ya tiene y añadir la diferencia. Sería más código, una petición más, y una condición de
carrera si dos ejecuciones se solapan. Dejar que el servidor rechace el duplicado es más simple y más
correcto.

Lo que esta función **no** hace es quitar: un repositorio que desaparezca del catálogo se queda en la
colección hasta que alguien lo borre a mano. Es una asimetría deliberada —borrar cosas del Hub
automáticamente da mucho más miedo que añadirlas— y es una limitación real que conviene saber.

## La guarda que costó una tarde

La primera vez que se lanzó `rukh publish cards` no salió bien. `rukh-tiny` falló.

La evaluación registraba el SHA del fichero que midió. El fichero que `rukh pull` trae del Hub no es
ese byte a byte, porque el publicador le quitó el optimizador y la cabeza atada. Eran los mismos
pesos y la guarda no lo sabía. La solución es el hash de tensores de la lección 2, y aquí está el
otro lado.

```python title="src/rukh/publish/model.py"
    The evaluation stores ``sha256`` of the checkpoint file and, since P6, of its tensors alone
    (``weights_sha``). A different file with the same weights -- the copy ``rukh pull`` brings
    back, which ``rukh publish`` wrote without the optimizer -- passes on the second; a
    ``step-*.pt`` whose weights differ from ``best.pt`` is still refused (D-135).
    """
    if not evaluation:
        return
    measured = str(evaluation.get("model_sha") or "")
    if not measured:
        return
    from rukh.eval.cache import file_sha, weights_sha

    actual = file_sha(Path(ckpt))
    if measured == actual:
        return
    measured_weights = str(evaluation.get("weights_sha") or "")
    if measured_weights and measured_weights == weights_sha(Path(ckpt)):
        return
    raise ValueError(
        f"stage {stage!r} was measured on a different checkpoint: its results.json records "
        f"model_sha {measured[:12]} and {Path(ckpt).as_posix()} hashes to {actual[:12]}"
        + (f" (weights {measured_weights[:12]} vs the file's own)" if measured_weights else "")
        + ". Evaluate this checkpoint under this stage, or publish the one that was evaluated."
    )
```

<Src file="src/rukh/publish/model.py" tag="p6" lines="281-304" />

Las cuatro salidas tempranas están en orden de coste creciente, y eso es una decisión: sin
evaluación, se pasa; sin hash registrado, se pasa; si el hash de fichero coincide, se pasa sin
cargar nada; y solo si no coincide se abre el `.pt` y se hashean los tensores, que cuesta segundos y
memoria. El camino normal —publicar el fichero que se midió— no paga nada.

El `measured_weights and ...` con la comprobación de que el campo existe es lo que hace que una
evaluación antigua, de antes del campo, siga rechazándose igual que antes. No se aflojó la guarda
retroactivamente: se le dio una segunda forma de aceptar, y solo cuando hay con qué.

El mensaje de error dice las **dos** opciones que arreglan la situación: volver a evaluar este
checkpoint bajo esta etapa, o publicar el que se evaluó. Un error que solo dice qué está mal deja al
lector eligiendo entre acciones que no ha pensado.

## Qué has aprendido

Publicar no es subir un fichero: es dejar escrita una afirmación que otra persona pueda contradecir,
y montar el camino de vuelta para que pueda intentarlo.

Las tres piezas que lo consiguen son las de esta lección. Una **lista única** de lo que existe, de
la que tiran todos los consumidores, para que no puedan decir cosas distintas. Un **camino de vuelta**

## Qué vas a construir

`rukh eval nightly`: un comando que produce la tabla entera del proyecto, todas las etapas medidas
con la misma configuración el mismo día.

Hasta aquí cada módulo midió lo suyo el día que cerró, con el harness de aquel día: trece filas con
trece fechas y trece configuraciones. Llamar a eso tabla es generoso, porque dos filas medidas con
instrumentos distintos no se comparan.

El bucle es lo fácil. Lo difícil es que cada etapa se mide de forma distinta: el decoder con su
suite, el encoder con otra, el Qwen3 afinado con la suya, Karvonen con la de la lección anterior, y
dos filas son adaptadores de 1,6 MB que hay que fundir sobre su base antes de medirlos. Todo eso lo
sabe el catálogo, y el nightly se limita a recorrerlo.

## Lo que el fichero promete

```python title="src/rukh/eval/nightly.py"
"""``rukh eval nightly``: the whole results table from the published models, with one command.

Twelve decoder rows and four encoder rows were written one ``rukh eval`` at a time over five
milestones, each with the config of its day. This walks the catalogue of ``rukh.hub`` -- every
model the course published, with the stage name its row carries and the suite that measures it
-- and evaluates each one under the **same** config, pulling from the Hub whatever is not on
disk. What the caches already hold is not replayed, so a nightly after a nightly is minutes;
the first one is hours of engine.

It writes three things: the rows of ``artifacts/web/results.json`` it measured (upserted by
stage, the rows it did not measure are left alone), ``docs/benchmarks.md`` rendered from the
whole table, and ``artifacts/eval/nightly.json``: which stage came from which checkpoint with
which sha, how long each took and what went wrong. A table is reproducible when the last file
says how it was made.
"""
```

<Src file="src/rukh/eval/nightly.py" tag="p6" lines="1-15" />

La última frase es la tesis. Una tabla es reproducible porque existe el fichero que dice qué fichero
exacto produjo cada fila, con qué hash, cuánto tardó y qué salió mal. El comando dice cómo se haría;
`nightly.json` dice cómo se hizo, y las dos cosas dejan de coincidir en cuanto una etapa falla y se
relanza a mano. Es el cuaderno de bitácora de M0 aplicado a la evaluación, y vale igual para la
batería de pruebas que se lanza con cada versión de un LLM.

La otra decisión es un _upsert_ por nombre de etapa: el nightly escribe las filas que midió y no toca
las demás. Así se puede lanzar con `--only` sobre una etapa sin perder las otras once, y así se
relanzó el baseline de Karvonen después de que fallara sin volver a jugar 1 760 partidas.

`Artefact` es el tipo del catálogo de la lección 5: un modelo publicado con su repositorio, su ruta en
disco, su nombre de etapa y la suite que lo mide.

El baseline de Karvonen no está en el catálogo; se declara aquí, el único sitio que necesita
conocerlo. El catálogo es la lista de lo que `rukh pull` descarga como nuestro, `rukh publish cards`
documenta y `rukh publish collection` mete en la colección del Hub. Un repositorio ajeno ahí dentro
acabaría, tres funciones más allá, con una card nuestra encima del modelo de otro.

<Callout kind="teoria" title="Una lista por propósito, no una lista por tipo">
  La tentación es tener «la lista de todos los modelos» y filtrarla en cada consumidor. Funciona
  hasta que un consumidor nuevo se olvida del filtro y publica lo que no debía. Aquí la lista se
  define por lo que se hace con ella (lo que el proyecto publica), y lo demás vive fuera aunque sea
  del mismo tipo. Cuesta una concatenación explícita en `plan()`, y ningún consumidor futuro puede
  equivocarse por omisión.
</Callout>

## El registro de lo que pasó

```python title="src/rukh/eval/nightly.py"
class NightlyRecord(BaseModel):
    """One stage of the run: what was measured, from what, and how it went."""

    model_config = ConfigDict(extra="forbid")

    name: str
    stage: str
    measure: str
    checkpoint: str | None = None
    model_sha: str | None = None
    weights_sha: str | None = None
    seconds: float = 0.0
    status: str = "planned"
    """``planned`` (dry run), ``measured``, ``skipped`` or ``failed``."""
    detail: str | None = None


class NightlyReport(BaseModel):
    """What one nightly did; serialised as ``artifacts/eval/nightly.json``."""

    model_config = ConfigDict(extra="forbid")

    date: str
    config: str
    encoder_config: str | None
    records: list[NightlyRecord]
    results: str
    benchmarks: str | None
    seconds: float
```

<Src file="src/rukh/eval/nightly.py" tag="p6" lines="53-81" />

`name` es como se llama el artefacto en el catálogo (`tiny`, `lora-e4`), lo que se escribe en
`rukh pull`; `stage` es el nombre de la fila (`tiny-greedy`), con el sufijo del muestreo porque un Elo
es del par modelo y muestreo. Los dos hashes van juntos: `model_sha` identifica el fichero que se
abrió en esta máquina y `weights_sha` los pesos, que es lo que la card afirma.

`status` es una cadena con cuatro valores documentados y no un `Enum`, porque el JSON se lee desde un
notebook y desde la web, y un `Enum` obligaría a sincronizar el vocabulario en dos sitios.

## El plan

```python title="src/rukh/eval/nightly.py"
def plan(only: set[str] | None = None) -> list[Artefact]:
    """The catalogue entries a nightly measures, in course order."""
    wanted = [artefact for artefact in (*catalogue(), KARVONEN) if artefact.measure != "none"]
    if only:
        wanted = [a for a in wanted if a.name in only or (a.stage or "") in only]
    return wanted
```

<Src file="src/rukh/eval/nightly.py" tag="p6" lines="84-89" />

Tres decisiones:

- `measure != "none"` deja fuera lo que esta suite no mide: los datasets, el tokenizador, el reward
  model y el encoder de preentrenamiento. Como esa propiedad vive en el catálogo, añadir un artefacto
  obliga a decir cómo se mide o que no se mide.
- `--only` acepta el nombre del artefacto o el de la etapa, porque en la terminal escribes lo que
  acabas de leer, y en la tabla pone `tiny-greedy` y en `rukh pull`, `tiny`.
- El orden es el del catálogo, que es el del curso.

```python title="src/rukh/eval/nightly.py"
    cfg = load_suite("full", config).model_copy(update={"stage": stage})

    return run_qwen_suite(adapter_dir, cfg, stage=stage, use_cache=use_cache, device=device)

    from rukh.eval.suite import load_suite

    cfg = load_suite("full", config)
    return run_karvonen_suite(
```

Cuatro funciones con la misma firma y cuerpos distintos: la capa de adaptación que permite que el
bucle no sepa nada de suites. Cada una importa lo suyo dentro de la función, así que
`rukh eval nightly --dry-run` no importa `torch` ni `transformers` e imprime el plan en un segundo.

El decoder y el encoder toman el nombre de la etapa de la configuración
(`model_copy(update={"stage": stage})`), como desde M2; Qwen y Karvonen lo reciben como parámetro.
Igualarlo exigiría cambiar una convención en cuatro ficheros, y la capa de adaptación está para
absorber esta clase de diferencia. El retorno va sin anotar porque cada suite devuelve su tipo y el
bucle tira el valor.

## Fundir un adaptador antes de medirlo

Dos filas de la tabla son adaptadores <Term id="lora">LoRA</Term> de M4: 1,6 MB de factores que no
miden nada por sí solos.

```python title="src/rukh/eval/nightly.py"
def merged_checkpoint(base: Path, adapter_dir: Path, out: Path) -> Path:
    """The base with the adapter folded in, as an ordinary checkpoint the suite can open.

    A style adapter is 1.6 MB of factors and measures nothing on its own; the row of the table
    is the base *with* it. ``load_adapter`` wraps the adapted matrices and reads the factors,
    ``merge_lora`` folds them back into plain ``nn.Linear`` weights, and what is saved has the
    state dict of a normal decoder -- the same thing the LoRA training run wrote as ``best.pt``.
    """
    from rukh.models.lora import ADAPTER_FILE, load_adapter, merge_lora
    from rukh.train.checkpoint import load_model, save_checkpoint

    model, payload = load_model(base)
    load_adapter(model, adapter_dir / ADAPTER_FILE)
    merge_lora(model)
    out.parent.mkdir(parents=True, exist_ok=True)
    return save_checkpoint(
        out,
        step=int(payload.get("step") or 0),
        model=model,
        optimizer=None,
        cfg={"merged_from": base.as_posix(), "adapter": adapter_dir.as_posix()},
        model_cfg=payload["model_cfg"],
        vocab_hash=payload.get("vocab_hash"),
        data_manifest_sha=payload.get("data_manifest_sha"),
        git_sha=payload.get("git_sha"),
    )
```

<Src file="src/rukh/eval/nightly.py" tag="p6" lines="124-149" />

Se funde y se guarda en vez de enseñar a la suite a cargar un adaptador, por dos motivos. El camino
con adaptador calcula `Wx + BAx` en dos multiplicaciones, que no da los mismos bits que la matriz
fundida: la fila mediría una ruta de código que nadie usa en producción. Y el checkpoint fundido es un
fichero que se puede abrir después para investigar una fila rara.

`cfg={"merged_from": ..., "adapter": ...}` deja escrito dentro del fichero de dónde salió, y
`vocab_hash`, `data_manifest_sha` y `git_sha` se copian de la base: sin esa cadena,
`artifacts/eval/merged/lora-e4.pt` sería un checkpoint anónimo de 150 MB.

## Dónde está cada cosa

```python title="src/rukh/eval/nightly.py"
def _checkpoint_of(artefact: Artefact, pull_missing: bool) -> Path:
    """Where the artefact is on disk, pulling it from the Hub when it is not and allowed."""
    if artefact.measure == "karvonen":
        from rukh.eval.karvonen import ensure_karvonen

        return ensure_karvonen(download=pull_missing)
    target = resolve_run(paths.resolve(artefact.target))
    if not target.exists() and pull_missing:
        target = pull(artefact)
    if not target.exists():
        raise FileNotFoundError(
            f"{artefact.name}: {target} is not on disk (rukh pull {artefact.name})"
        )
    if artefact.base is not None:
        base = resolve_run(paths.resolve(artefact.base))
        if not base.exists() and pull_missing:
            from rukh.hub import lookup

            base = pull(lookup("medium-v4"))
        if not base.exists():
            raise FileNotFoundError(f"{artefact.name}: base {base} is not on disk")
        return merged_checkpoint(base, target, paths.resolve(MERGED_DIR) / f"{artefact.name}.pt")
    return target
```

<Src file="src/rukh/eval/nightly.py" tag="p6" lines="152-174" />

Tres caminos, y el orden importa:

- El baseline sale primero porque no se descarga como los nuestros: `ensure_karvonen` sabe de qué
  repositorio ajeno viene.
- `resolve_run` (lección 6) convierte `checkpoints/medium-v4/best.pt` en el
  `medium-v4-20260919-174623/best.pt` de quien entrenó el modelo, y se aplica antes de decidir si hay
  que descargar: quien entrenó `tiny` no vuelve a bajarlo del Hub.
- El `FileNotFoundError` lleva dentro la orden que lo arregla, `rukh pull {name}`. Un error que
  alguien leerá al día siguiente en un JSON tiene que decir qué hacer.

La rama de `artefact.base` es la del adaptador, y tiene un atajo que hay que ver escrito: si la base
no está, descarga `medium-v4` por su nombre literal. Los dos adaptadores del catálogo van sobre
`medium-v4`, pero el día que haya uno sobre `small-v3` esta línea traerá el modelo equivocado y la
fila medirá otra cosa sin fallar.

## El bucle

```python title="src/rukh/eval/nightly.py"
def run_nightly(
    config: Path | None = None,
    encoder_config: Path | None = None,
    only: set[str] | None = None,
    dry_run: bool = False,
    pull_missing: bool = True,
    use_cache: bool = True,
    device: str | None = None,
    results: Path | None = None,
    benchmarks: Path | None = None,
    out: Path | None = None,
) -> NightlyReport:
    """Measure every catalogued stage under one config and rewrite the table around them."""
    from rukh.eval.cache import file_sha, weights_sha
    from rukh.eval.report import write_benchmarks

    started = time.perf_counter()
    records: list[NightlyRecord] = []
    for artefact in plan(only):
        record = NightlyRecord(
            name=artefact.name, stage=artefact.stage or artefact.name, measure=artefact.measure
        )
        records.append(record)
        if dry_run:
            record.checkpoint = paths.resolve(artefact.target).as_posix()
            continue
        tick = time.perf_counter()
        try:
            checkpoint = _checkpoint_of(artefact, pull_missing)
            record.checkpoint = checkpoint.as_posix()
            if checkpoint.is_file():
                record.model_sha = file_sha(checkpoint)
                record.weights_sha = weights_sha(checkpoint)
            log.info("nightly: %s as %s from %s", artefact.name, record.stage, checkpoint)
            if artefact.measure == "decoder":
                _run_decoder(checkpoint, config, record.stage, use_cache, device)
            elif artefact.measure == "encoder":
                _run_encoder(checkpoint, encoder_config, record.stage, use_cache, device)
            elif artefact.measure == "qwen":
                _run_qwen(checkpoint, config, record.stage, use_cache, device)
            elif artefact.measure == "karvonen":
                _run_karvonen(checkpoint, config, record.stage, use_cache, device)
            record.status = "measured"
        except Exception as exc:  # noqa: BLE001 - one stage failing must not lose the others
            log.exception("nightly: %s failed", artefact.name)
            record.status = "failed"
            record.detail = f"{type(exc).__name__}: {exc}"
        record.seconds = round(time.perf_counter() - tick, 1)
```

<Src file="src/rukh/eval/nightly.py" tag="p6" lines="177-224" />

`records.append(record)` va antes del `try`: el registro entra en la lista con estado `planned` y las
ramas de abajo lo mutan, así que ni una excepción ni el `continue` de `--dry-run` pueden producir un
informe al que le falte una etapa.

El `except Exception` con su `noqa` es el correcto aquí. Una tirada de tres horas no puede morir
porque la novena etapa tenga un problema: apunta el fallo en su fila y sigue. No se traga nada:
`log.exception` deja la traza entera y `detail` guarda tipo y mensaje en el JSON. Esa rama se
ejecutó en el hito: el baseline de Karvonen falló con `ValueError: … holds no model_state to hash`
(su checkpoint guarda los tensores bajo `model`), y las once etapas ya medidas, dos horas y media de
motor, se salvaron.

El hash solo se calcula si el objetivo es un fichero, porque el Qwen3 afinado es un directorio. Y los
segundos por etapa convierten `nightly.json` en un presupuesto: el encoder tarda siete segundos y
cada decoder catorce minutos, y de ahí sale qué se puede relanzar.

```python title="src/rukh/eval/nightly.py"
def render_plan(report: NightlyReport) -> str:
    """One line per stage, for the terminal."""
    lines = [f"{'stage':<32}{'measure':<9}{'status':<10}{'seconds':>8}  checkpoint"]
    for record in report.records:
        lines.append(
            f"{record.stage:<32}{record.measure:<9}{record.status:<10}{record.seconds:>8.1f}  "
            f"{record.checkpoint or '-'}" + (f"  ({record.detail})" if record.detail else "")
        )
    return "\n".join(lines)
```

## La orden

```python title="src/rukh/cli.py"
@eval_app.command("nightly")
def eval_nightly_cmd(
    config: Annotated[
        Path | None,
        typer.Option(
            "--config",
            exists=True,
            dir_okay=False,
            help="Suite YAML every decoder is measured with (default: configs/eval/greedy.yaml).",
        ),
    ] = None,
    encoder_config: Annotated[
        Path | None,
        typer.Option("--encoder-config", exists=True, dir_okay=False, help="Encoder suite YAML."),
    ] = None,
    only: Annotated[
        str | None, typer.Option("--only", help="Comma-separated names or stages to measure.")
    ] = None,
    dry_run: Annotated[
        bool, typer.Option("--dry-run", help="List what would be measured and exit.")
    ] = False,
    no_pull: Annotated[
        bool, typer.Option("--no-pull", help="Never download; a missing checkpoint fails.")
    ] = False,
    no_cache: Annotated[bool, typer.Option("--no-cache", help="Replay every game.")] = False,
    device: Annotated[str | None, typer.Option("--device", help="Where to run.")] = None,
) -> None:
    """Measure every published stage under one config and rewrite the whole table.

    The catalogue of `rukh pull` says which stage each model is and how it is measured; what the
    caches hold is not replayed, so a nightly after a nightly costs minutes. `artifacts/eval/
    nightly.json` records what came from where, with which sha, and how long it took.
    """
    from rukh.eval.nightly import render_plan, run_nightly
    from rukh.paths import resolve

    logging.basicConfig(level=logging.INFO, format="%(asctime)s  %(message)s")
    wanted = {part.strip() for part in (only or "").split(",") if part.strip()} or None
    report = run_nightly(
        config=config or resolve("configs/eval/greedy.yaml"),
        encoder_config=encoder_config,
        only=wanted,
        dry_run=dry_run,
        pull_missing=not no_pull,
        use_cache=not no_cache,
        device=device,
    )
    typer.echo(render_plan(report))
    if not dry_run:
        typer.echo(f"results:    {report.results}")
        typer.echo(f"benchmarks: {report.benchmarks or 'not rewritten'}")
        typer.echo(f"seconds:    {report.seconds:.0f}")
```

```python title="tests/unit/test_nightly.py"
def test_an_adapter_is_merged_onto_its_base_before_it_is_measured(
    rukh_home: Path, monkeypatch: pytest.MonkeyPatch
) -> None:
    from rukh.models.lora import LoraConfig, apply_lora, save_adapter

    base = _toy(rukh_home / "checkpoints" / "medium-v4" / "best.pt")
    torch.manual_seed(1)
    model = MoveDecoder(TOY)
    model.load_state_dict(load_model(base)[0].state_dict())
    apply_lora(model, LoraConfig(r=2, alpha=4, targets=["q", "v"]))
    with torch.no_grad():
        for name, parameter in model.named_parameters():
            if ".b." in name:
                parameter.add_(0.5)
    adapter_dir = rukh_home / "checkpoints" / "lora-e4"
    adapter_dir.mkdir(parents=True)
    save_adapter(
        model, adapter_dir / "adapter.safetensors", LoraConfig(r=2, alpha=4, targets=["q", "v"])
    )

    seen: dict[str, Path] = {}
    monkeypatch.setattr(
        nightly, "_run_decoder", lambda ckpt, *a, **k: seen.__setitem__("ckpt", Path(ckpt))
    )
    report = nightly.run_nightly(only={"lora-e4"}, pull_missing=False)
    assert report.records[0].status == "measured"
    merged, payload = load_model(seen["ckpt"])
    assert payload["cfg"]["adapter"].endswith("lora-e4")
    plain, _ = load_model(base)
    # The merged weights differ from the base exactly where the adapter pushed.
    assert not torch.equal(merged.blocks[0].attn.qkv.weight, plain.blocks[0].attn.qkv.weight)
    assert not any(".lora" in k or ".a." in k for k in merged.state_dict())
```

## Qué has aprendido

Un orquestador de evaluación es casi todo decisiones sobre qué hacer cuando algo va mal: dónde vive
la lista, cómo se resuelve una ruta que puede estar en dos sitios, qué se hace con un adaptador que no
es un modelo, qué se escribe cuando una etapa falla y qué se deja intacto.

Eso sirve igual en cualquier pipeline de evaluación, de un clasificador o de un agente: la lista se
define por su propósito para que nadie se equivoque por omisión, el fallo de un elemento se apunta
sin parar el lote, y el fichero que dice cómo se hizo vale tanto como la tabla.

La lección siguiente construye la lista de la que este comando tira, y convierte cada fila en una card
publicada.
